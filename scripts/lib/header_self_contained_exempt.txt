# ─────────────────────────────────────────────────────────────────────────────
# 头文件「自包含性」豁免名单（护栏 scripts/verify_header_self_contained.sh）
#
# ⚠️ **本文件是纯数据** ⇒ ⇒ 护栏的 R2 会做**双向**核对：
#    ① 名单里的每个头 MUST **确实**不能自包含（否则豁免已过时 ⇒ 红）；
#    ② 名单 MUST 与「实际不能自包含的集合」**完全一致**（否则漏登记 ⇒ 红）。
#    ⇒ ⇒ **豁免不得成为万能借口**（本仓「护栏自身有盲区」病症的防线）。
#
# ⚠️ **两种豁免**（kind 不同 ⇒ 判据不同）：
#    `fragment` —— **分片头**：被某个聚合头 include 后才有意义（设计意图）
#                  ⇒ ⇒ **无条件豁免**（与编译器无关）。
#    `stdlib:<能力>` —— **标准库可用性**问题：该头需要 `<能力>`，而**当前编译器
#                  的标准库不提供它** ⇒ ⇒ 豁免**仅在「能力探测失败」时生效**
#                  ⇒ ⇒ 换到提供该能力的编译器（libstdc++）⇒ ⇒ **豁免自动失效**
#                  ⇒ ⇒ 该头若此时能编译 ⇒ ⇒ R2a 报「豁免已过时」⇒ ⇒ 红。
#                  ⇒ ⇒ 这样「能力」而不是「编译器名字」成为判据 ⇒ ⇒ 可移植。
#
# ⚠️ **本名单只收「设计使然」的头** ⇒ ⇒ **公共入口头**（用户会直接
#    `#include` 的）MUST NOT 在本名单里。
#
# 格式：<相对 include/ 的路径>\t<kind>\t<理由>
#       （kind = `fragment` 时第三列是理由；
#         kind = `stdlib:<能力>` 时第三列是理由，能力写在第二列里）
# ─────────────────────────────────────────────────────────────────────────────
