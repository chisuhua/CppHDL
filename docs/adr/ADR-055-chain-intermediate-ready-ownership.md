## 1. 背景（**只陈述决策所需的事实**）

### 1.1 实测事实（2026-11-01，全部可复算）

| # | 事实 | 证据 |
|---|---|---|
| ① | `stream_fifo` **不驱动**入参 `ready`（写使能只用 `input_stream.valid`，内部 `sync_fifo` 自保护） | `include/chlib/stream.h` 的 `stream_fifo` 实现 |
| ② | ⇒ ⇒ builder 链里 `source.ready` **恒 0** ⇒ ⇒ ⇒ **上游遵守 ready 协议 ⇒ ⇒ 永远推不动 = 死路** | 探针 E10（正确接线：16 拍全 0） |
| ③ | 修法 A（中间级 `pop_stream.ready` ← 下一级 `push_stream.ready`）**技术可行** | 手写 2 级 + 显式回接 ⇒ **零丢字**（10 word 全齐） |
| ④ | 多驱动守卫**不误炸**：对**下游**调 `connect_ready` **不抛**；已覆盖的中间级再调**抛**（= 正确检测） | 探针 E5/E6 |
| ⑤ | 修法 B（改 `chlib/fifo.h` 加写口 ready）**不需要** | `stream_fifo` 的 result **已有** `push_stream.ready`（`stream.h:469`） |
| ⑥ | `stream_pipeline.h` 的 3 个 pipe 同样**不驱动**上游 ready ⇒ ⇒ 且**只在「`ready = true` 常量接线」下活着**（正确接线下**零数据通过**） | A4 判决性对比（46/14 vs 23/14 test cases） |
| ⑦ | `stream_pipeline.h` / `stream_width_adapter.h` **不在**护栏 R8 的扫描面 ⇒ ⇒ ⇒ **不在任何 ready 契约的覆盖范围内** | R8 只扫 `stream.h` + `stream_arbiter.h` |

### 1.2 问题（**精确表述**）

`StreamBuilder` 链内的**中间级** FIFO（非链首、非链尾）：

1. 它的**读使能**（`pop_stream.ready` 的驱动源）**应当是什么**？
2. 它**是否属于** ADR-054 §3.2 第 1 条所说的「fifo 类」？
3. 若不属于 ⇒ ⇒ 该条款**如何**表述才不留下「例外先例」？
4. （配套）`StreamBuilder` **如何表示「链」**？

---

## 2. Decision（**裁决**）

### 2.1 核心裁决

> **链内每一级的读使能 MUST 由「下一级的容量信号」驱动；链尾由消费端 ready 驱动。**
> **链内中间级不是对外暴露的组合子 ⇒ ⇒ ⇒ ADR-054 §3.2 第 1 条【不适用】于它。**

⇒ ⇒ **这不是「对 §3.2 第 1 条的例外」** ⇒ ⇒ ⇒ 而是**该条款适用面**的界定
⇒ ⇒ ⇒ ⇒ **⇒ 「适用面」与「例外」的区别是承重的** ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒
**⇒ ⇒ ⇒ ⇒ ⇒ ⇒ 例外会变成先例**（下一个人会问「那我的组件能不能也例外」）
⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ **适用面不会**（它陈述的是「哪些对象在条款范围内」）。

### 2.2 为什么**不**立「第三类」（**分类轴**）—— **关键裁决**

⚠️ 分类是**开放式**的 ⇒ ⇒ 下一个人会把「ready 来自容量信号」套到
**任何对外暴露**的组合子上 ⇒ ⇒ ⇒ ⇒ ⇒ **⇒ 必须用【作用域】而不是【taxonomy】**
⇒ ⇒ ⇒ ⇒ ⇒ **⇒ 例外应当落在 scope clause，不落在 taxonomy**。

⇒ ⇒⇒ **裁决**：**不**引入新分类轴；**改为**一条**链内闭包不变式** + 「不对外暴露」
⇒ ⇒⇒ **⇒ 【可机械核验】**：判据 = 「链内每一级的 `pop_stream.ready`
⇒ ⇒ ⇒ **有驱动源** ⇒ ⇒ 且该源 = **下一级的 `push_stream.ready`」。

### 2.3 配套裁决：链的**表示形式**

⚠️ `StreamBuilder` **当前不保存**链上各 FIFO 的 result 对象 ⇒ ⇒ ⇒ **修复必须把
「链」显式建模** ⇒ ⇒ ⇒ ⇒ **⇒ 裁决**：**不引入「显式链结构」**（那会改变 builder
的公开形态）⇒ ⇒ ⇒ **⇒ 公开 API 零变更**。

⚠️ **实施期订正（2026-11-01 · 实现形态，决策未变）**：初稿写的「用私有成员保存
链上各级的 result 对象」在实现时改为 **只保存「下一级要驱动的那一个节点」**
（`pending_ready_`）。⇒ ⇒ **语义等价**：第 k 级的 output ready 在建立第 k+1 级
时**立刻**被驱动掉 ⇒ ⇒ 之后再也用不到 ⇒ ⇒ 保存历史**没有用处**。
⇒ ⇒ 且**不随链长线性增长**（⇒ §4「负面」第 1 条因此**不成立**）。
⇒ ⇒ 决策（链内闭包不变式 · 不引入显式链结构 · 公开 API 零变更）**一字未改**。

### 2.4 配套裁决：`stream_pipeline.h` 的 pipe 族

⚠️ pipe 族与 builder 中间级**同型**（不驱动上游 ready + 只在常量接线下活着）
⇒ ⇒ ⇒ **裁决**：**纳入同一 capability 的覆盖范围**（MODIFIED）⇒ ⇒ ⇒
⇒ ⇒ **按同一形态修**（链内/组合子内部的上游 ready 由「下游容量/消费端」驱动）
⇒ ⇒ ⇒ ⇒ ⇒ ⇒ **⇒ 且 `stream_pipeline.h` MUST 进护栏 R8 的扫描面**
⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ **⇒（否则它们永远在护栏之外）**。

| # | 选项 | 结论 | 理由 |
|---|---|---|---|

## 4. 后果 / 代价

### 正面
- builder 链从**死路**（`source.ready` 恒 0 ⇒ 上游永远推不动）变为
  **可反压** ⇒ ⇒ ⇒ 「FIFO 满 ⇒ 上游暂停」**可演示**；
- pipe 族（`m2s` / `s2m` / `half`）从**只在常量接线下活着**变为**真实可用**；
- **公开 API 零变更**（builder 的公开形态不动；pipe 的端口不动）；
- 护栏覆盖面扩大（`stream_pipeline.h` 进 R8 扫描面）⇒ ⇒ 「未被守护的面」减少。

### 负面
- ~~builder 的**内部**实现要保存链上各级的 result 对象（私有成员）⇒ ⇒ **链长时内存线性增长**~~
  ⇒ ⚠️ **实施期已消除**（见 §2.3 订正）：只需保存**一个** `pending_ready_`
  ⇒ ⇒ **不随链长增长**；
- 中间级的 `pop_stream.ready` 被覆盖 ⇒ ⇒ ⇒ **调用方不能再对中间级调
  `connect_ready`**（守卫会抛）⇒ ⇒ ⇒ **这是【正确】的多驱动检测** ⇒ ⇒ ⇒
  ⇒ ⇒ **但 MUST 写进契约**（否则调用方撞上「响亮异常」而不知为何）。

### 风险
| # | 风险 | 对策 |
|---|---|---|
| 1 | 「链内闭包不变式」被误用到**对外暴露**的组合子 | 契约 MUST 明写「**仅**适用于链内中间级」+ 「对外暴露的组合子 MUST NOT 适用本不变式」 |
| 2 | 回接引入**组合环** | 已实测**不成环**（源是**下一级**的 `push_stream.ready` = 寄存器 `full` 的组合输出 ⇒ ⇒ 本级读使能是**寄存器输入**）⇒ ⇒ ⇒ **实现时 MUST 复核** |
| 3 | pipe 族改动**暴露既有断言**依赖旧行为 | 既有 `_behavior` 文件已存在（8 个）⇒ ⇒ ⇒ **逐个复核**（⇒ ⇒ 已有 4 个 AXI `_behavior` ⇒ ⇒ **必查**） |
| 4 | 「不适用」被读成「§3.2 对 fifo 类不再是承重的」 | ADR-055 MUST 引述 §3.2 原文并明写「**§3.2 第 1 条对 fifo 类仍然完全有效**」 |

## 5. Verification（**前瞻**验收判据，MUST 可勾选 —— 裁决落地后适用）

      **MUST 有驱动**（`num_srcs() > 0`）⇒ ⇒ 且其**值 MUST 随占用变化**
      （占用满 ⇒ ⇒ 落 0）⇒ ⇒ ⇒ ⚠️ **MUST NOT 锁字面量**（消费速率影响占用）

      `pop_stream.payload` 序列里（**顺序一致**）
- [ ] **效果判据**：pipe 族（`m2s` / `s2m` / `half`）在**正确接线**下 ⇒ ⇒
      **数据能通过**（⇒ ⇒ 当前实测**零通过** ⇒ ⇒ 修复前必红）
- [ ] **结构判据**：链内每一级的 `pop_stream.ready` **MUST 有驱动源** ⇒ ⇒ 且该源
      **MUST 是下一级的 `push_stream.ready`** ⇒ ⇒ ⇒ **⇒ 这条 MUST 进护栏**
