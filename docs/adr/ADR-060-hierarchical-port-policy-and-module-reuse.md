## 1. 背景（**只陈述决策所需的事实**）

### 1.1 实测事实（2026-11-02）

| # | 事实 | 证据 |
|---|---|---|
| ① | 跨模块的合法连法**不止端口**：① bundle 成员跨层（`child.instance().s.payload <<= …`）② 父层直接改子层 `ch_reg` 的 `next` ③ **父层 `ch_out` 由子模块的成员 `reg` 驱动**（`io().y <<= c.instance().acc`）④ **子模块 `ch_out` 由父层表达式驱动**（`child.io().out <<= parent.io().a + 1` ⇒ 子端口的 `src(0)` 是**父层**节点） | `docs/usage_guide/05-component-design.md` §4.1 / §4.2 · `include/core/io.h:465` |
| ② | bundle 成员跨层是 **ADR-042 明确支持**的用法 ⇒ ⇒ ⇒ 直接报错会砍掉合法设计 | `docs/adr/ADR-042-bundle-field-first-class-nodes.md` |
| ③ | `ch_module` 会**转发构造参数**给子组件 ⇒ ⇒ **同类型同端口可含不同体内逻辑**（`ch_reg` 初值进 `always_ff` 的 reset 分支 · `ch_mem` 初值进 mem 初始化） | `include/module.h:60` |
| ④ | 端口节点名恒为 `unnamed_input` / `unnamed_output` ⇒ ⇒ 扁平侧靠**全局** `_N` 后缀消歧 | `include/core/io.h:141-158` · `src/codegen_verilog.cpp:70-78` |
| ⑤ | 扁平产物对「无 driver 的 `ch_in`」的处理是：**它成为顶层 input 端口** | `src/codegen_verilog.cpp:333-360` |

### 1.2 问题（**精确表述**）

1. 跨模块的边若**不落在端口上**，层次化 emitter MUST 为它**造端口** ⇒ ⇒ ⇒
   **造在子侧还是父侧？方向是 input 还是 output？** ⇒ 四种边方向的答案**各不相同**
   （事实① 的 4 种形态）⇒ ⇒ ⇒ 规则 MUST **按方向分列**，不能只写一句「合成隐式端口」。
2. 悬空的子输入在扁平产物里会**冒泡成顶层 input**（事实⑤）⇒ ⇒ ⇒ 层次化 MUST
   **复刻**该行为，否则两份 RTL 语义分叉。
3. 同类型多实例能否复用同一个 module？事实③ ⇒ ⇒ ⇒ **端口签名一致还不够** ⇒ ⇒ ⇒
   复用判据若只看端口 ⇒ ⇒ ⇒ **会把一个实例的初值安到另一个实例头上**（静默错 RTL）。

## 2. Decision（**裁决**）

### 2.1 决策 ① —— 隐式端口：**按边方向分列的规则表**

⚠️ **作用面（ADR-061）**：本章的隐式端口 / 冒泡规则 **只对「被声明为成层的组件」生效**
⇒ ⇒ ⇒ **被 inline 的组件不产生 module ⇒ ⇒ 不需要任何隐式端口**
⇒ ⇒ ⇒ ⇒ **用户的 inline 选择顺带免掉了隐式端口的麻烦**。

⚠️ **本章覆盖不到的第六格**（critic SF 指出，由 ADR-061 决策② 的**两作用域表**处理）：
**inline 组件位于非顶层成层 module 内** ⇒ ⇒ 它的 `ch_out` 是**该 module 体内的普通信号**
（**不**上 RTL 顶、也不是隐式端口）⇒ ⇒ 与本章的方向矩阵**无关**
⇒ ⇒ ⇒ 本章的矩阵只处理「**成层 module 之间**的跨模块边」。

⚠️ **矩阵缺的第三轴：driver 的 `owner` 落在哪个 module**（v1.4，oracle R4）：
下游真实形态是 driver 在 `setup()` 里建 ⇒ `owner == nullptr` ⇒ 按 ADR-058 §2.1 归**顶层**；
而被驱动的 `ch_in` 属于某个**更深的成层 module** ⇒ ⇒ 父 module **无法引用顶层网**
⇒ ⇒ MUST 沿祖先链合成**上行 input 端口**（逐级 pass-through），或按 `Reject` 策略拒绝。

| driver 的 `owner` | 处理 |
|---|---|
| **同一 module** | **inline** ⇒ 体内 `assign`（扁平规则）；**成层** ⇒ ⚠️ **无解** ⇒ MUST `CHFATAL_EXCEPTION`（⇒ 子 module 内对 `input` 赋值 = 非法 Verilog；父层又引用不到体内 driver ⇒ ADR-062 决策① 已裁「响亮拒绝」） |
| **父 module** | 实例端口连接（不合成端口 —— ADR-062 决策①） |
| **更上层（含 `owner == nullptr` ⇒ 顶层）** | 沿祖先链**逐级合成 pass-through input 端口**（每级一个同名端口）⇒ 或 `Reject` |

| 边方向 | 子侧端点 | 合成 | 说明 |
|---|---|---|---|
| **父 → 子** | 子侧端点**不是**子端口 ⇒ ⇒ **节点形态仅限** ① 子成员 `reg` 的 `next` · ② **proxy**（bundle 字段） | 子侧 **input** 隐式端口 | 父侧 wire → 例化映射 ⇒ ⇒ ⚠️ **op 操作数**（`ch_uint <<=`）**不在本行** ⇒ 见「第七格」**拒绝**；`operator=` 是本地重绑定 ⇒ **不产生边** |
| **子 → 父** | 子侧端点**不是**子端口（父层读子成员的 `reg` / bundle 字段） | 子侧 **output** 隐式端口 | 父侧 `assign` 取实例输出 |
| **子 → 父**（★ **v1.16 补格** · 2026-11-08） | 子侧端点**是**子端口（`ch_out`）且**父侧带运算**（消费点不是父 `output` 端口） | **不合成**子侧端口（**复用**该 `ch_out`） | **父侧合成一根 `logic` 网**（网名 = **驱动端点的 ctx 全局名**）⇒ 子 output 以 `.port(net)` 连它 ⇒ 父侧运算读该网 ⇒ ⇒ **ADR-066 决策 ①**（⚠️ 本行与上一行**并列存在**，MUST NOT 合并：上一行的前提是「子侧端点**不是**端口」，本行的前提是「**是**端口」）⇒ ⇒ 直通形态（消费点 = 父 `output` 端口）**不造网** ⇒ ⇒ **ADR-066 决策 ③**；⚠️ 消费点是父 **`input`** 端口时 MUST **拒绝**（物理不可行）⇒ ⇒ **ADR-066 决策 ① 排除项** |
| **父 → 子** | 子侧端点**是**子端口，但**驱动节点在父模块** | ⚠️ **不合成任何端口** —— **复用**该 `ch_in` 作为子 module 的 input 端口；父层的驱动表达式成为**实例端口连接** | ⚠️ 定语**不是**「合成隐式端口」（v1.3 订正，ADR-062 决策①）：子端口**本来就要成为端口** —— 见下 |
| **任意** | **mem 本体**跨 module（父层调 `child.mem.aread()`） | ✅ **已裁决（2026-11-02 · 用户拍板）**：**响亮拒绝**（`CHFATAL_EXCEPTION`）—— **MUST NOT** 合成隐式端口 | ⚠️ 理由：mem 是**数组**，其读端口是「地址 → 数据」的**关系**，不是单根信号 ⇒ ⇒ 合成端口**无法用一根 wire 表达** ⇒ ⇒ 且跨模块读别人的存储器 = **隐藏共享状态** ⇒ ⇒ ⇒ 属于设计味道 ⇒ ⇒ ⇒ 故**拒绝**并给出替代路径（见下）· ⚠️ **v1.17 收窄**：本行的适用面 = **mem 本体**跨 module ⇒ ⇒ 与下一行**并列存在**（MUST NOT 合并）· ⚠️ **现状实现缺口（v1.17）**：闸门段 `src/hierarchy_analysis.cpp:542-553`（闸门点 `:543`）对字面「mem 本体跨 module」**预期不可达**（mem 本体节点零 `add_src` ⇒ 端口与其 src 的 owner 同 module ⇒ 不产生跨 module 边）⇒ ⇒ 现状处置**可能**为发射期**静默丢端口** ⇒ ⇒ ★ 本行是**契约要求**（不是现状断言）⇒ ⇒ **登记义务** = ADR-066 §2.7 (i) 机制订正 + §5 **V20**（运行期探针）· phase-6 **P5** |
| **子 → 父**（★ **v1.17 补格** · 2026-11-09） | 子侧端点 = **`ch_mem` 的读 / 写端口**（mem 端口）· **实参视线跨层**（`addr` / `en` / `wdata` 取自成层子组件的 `ch_out`）· ⚠️ **前提：mem 本体与使用者同 module** | **不合成**（mem 端口**不是**一根信号 ⇒ ⇒ 合成端口无法用一根 wire 表达） | **边界句（逐字 · 唯一权威）**：「mem 持有 module == 使用 module、仅`实参视线`跨层」 ⇒ ⇒ 该形态 **不属**上一行的「**mem 本体**跨 module」⇒ ⇒ 处置 = **归下游独立立项**（分析层 `:542-553` 的**粒度拆分** + **归因订正**）⇒ ⇒ **ADR-066 决策 ⑦**（v1.2 修订）⇒ ⇒ ⚠️ 「正确支持」那一支 = **条件化**于该边界句（用户 2026-11-09 裁决）· ⚠️ **mem 本体**跨 module ⇒ ⇒ **仍按上一行响亮拒绝**（不变） |

⚠️ **跨层边的两端宽度 MUST 一致；不一致 ⇒ 响亮拒绝**（v1.10 · B2b-3 实施期实测）：
合成端口的宽度取**子侧**端点的宽度（`ModuleView` 侧无宽度概念 ⇒ 只能取一侧）
⇒ ⇒ 父侧若给出不同宽度的驱动节点 ⇒ ⇒ 实例端口映射会触发 Verilog 的**自动扩展/截断**
⇒ ⇒ **而产物头部把 `WIDTHEXPAND`（扩展静默 · `:311`）与 `WIDTHTRUNC`（截断 · `:312`）
两半都关掉了**（`src/codegen_verilog.cpp:311-312`）
⇒ ⇒ ⇒ 宽度不匹配在产物里**完全静默**（连 lint 都看不见）。
⇒ ⇒ **裁决**：MUST 在**合成前**比对两端宽度；不一致 ⇒ ⇒ **响亮拒绝**
（点名前后端 + 两个宽度）⇒ ⇒ **MUST NOT** 静默扩展/截断。
⚠️ **理由**：跨层接口宽度不匹配是**设计错误**（写错了位宽）⇒ ⇒ 而 Verilog 的自动扩展
是**合法**行为 ⇒ ⇒ 不报 ⇒ ⇒ 用户看不出 ⇒ ⇒ 属 ADR-062 决策①「响亮拒绝」同族。
⚠️ **与「冒泡」的区别**：冒泡的端口宽度取**该 `ch_in` 自身的宽度**（两端同源 ⇒ 天然一致）
⇒ ⇒ 本条只针对**跨层合成端口**。
⚠️ **与 ADR-058 §5「实例化端口宽度 MUST 一致」的接缝**（v1.10 · critic SF）：
那一处是**验收期判据**（覆盖**全部**实例端口映射）⇒ ⇒ 本条是**发射期 fail-closed**
（只覆盖**合成**端口这个子集）⇒ ⇒ **两处互补，不是重复实现** ⇒ ⇒ 实施者 MUST NOT
二选一，也 MUST NOT 在两处写同一套逻辑。

⚠️ **虚拟重定向的两条不变式**（v1.10 · B2b-3 实施期实测）：

| # | 不变式 | 为什么 |
|---|---|---|
| **R1** | 被重定向的节点是**本 module 内的本地 wire**（由合成端口驱动：`assign <node> = __if_<n>;`） | ⇒ ⇒ **任何**读该节点的表达式读**本地 wire 名** = 正确 ⇒ ⇒ 而**不是**读它的 `src(0)` |
| **R2** | **所有 `src(0)` 解析 / 节点穿透路径 MUST 先查重定向表**（等价表述：被重定向节点按**本地 wire 名**取值） | 被重定向节点的 `src(0)` 可能已被**父层**驱动覆盖 ⇒ ⇒ 继续穿透 ⇒ ⇒ 引用**父层信号** ⇒ ⇒ 该信号在本 module 内**未声明** ⇒ ⇒ 非法 Verilog（且**零告警**） |

⇒ ⇒ ⇒ **R2 是 B2b-3 实测踩到的真缺陷**（`print_output` 的 proxy-chain walk）⇒ ⇒
⇒ ⇒ 它**不**是「实现细节」而是**机制的正确性前提** ⇒ ⇒ MUST 留在契约里。

ⓘ **R2 的适用范围**（v1.10 · critic SF：契约字面 MUST 约束**未来新增**的路径）：
「读 `src(0)` 或穿透节点」的路径**不止一条** ⇒ ⇒ 契约按「**所有**这类路径」表述，
而不是点名某一条 ⇒ ⇒ **今天**的四条路径与各自的守卫形态：

| 路径 | 守卫形态 |
|---|---|
| `print_output` 的 proxy-chain walk | 显式查重定向表（B2b-3 修的就是它 ⇒ 变异 M3） |
| `print_input` 的 driver walk | **只穿透未命名 proxy** ⇒ ⇒ 被重定向的 proxy **有名字** ⇒ ⇒ 天然停下 |
| `print_proxy` 的 `src(0)` | 重定向 **early-return**（B2b-3 修） |
| `print_reg` 的 `get_next()` | 重定向**优先**（B2b-2 修） |

⚠️ **MUST NOT** 把 R2 泛化成「**停在任何有名字的节点上**」—— `print_output` 在**扁平**
路径下今天**穿透所有 proxy（含命名的）** ⇒ ⇒ 泛化会改变**扁平产物**
⇒ ⇒ 违反 ADR-058 §2.3 的「扁平产物逐字节不变」零回归判据 ⇒ ⇒ R2 的窄措辞
（只停**被重定向**的节点）是**唯一**正确选择。

⚠️ **矩阵未覆盖的第七格**（v1.8 · 2026-11-05 实测）：**父层用 `<<=` 改写子模块
内部「运算节点」的操作数**（`child.instance().sum <<= parent.io().a`，`sum` 是 `ch_uint`
成员、绑定在 `+` 之类的 `type_op` 节点上）。
⇒ ⇒ **实测可达**：`ch_uint::operator<<=` 对该节点走 `set_src(0, …)` ⇒ ⇒ 分析层确实把它
识别为 `父 → 子 · child side is not an input port`（探针：`sum <<= io().din` ⇒
`ok=0` + 点名该边）。

⇒ ⇒ **裁决：拒绝（`CHFATAL_EXCEPTION`）· MUST NOT 合成**。**承重理由**（稳定判据）：
① **破坏模块边界** —— 父层改写子模块内部运算的输入 = 子模块的逻辑由父层决定
   ⇒ ⇒ 与 ADR-058 §2.1「模块边界 = 所有权边界」冲突。ADR-042 支持的是 **bundle 字段**
   （有独立 driver 槽位、语义是「一次赋值」），**不是**「改别人的运算」；
② **没有合法的端口形态可以表达**：父层只经**实例端口映射**接子模块 ⇒ ⇒ 而 op 节点是
   子 module 的**体内**逻辑（不是端口）⇒ ⇒ 不存在「把父层的值合法接进去而不改子模块
   语义」的接法（对比：reg next / proxy 有**独立的 driver 槽位**，合成 input 端口后
   只需把该槽位指向端口 ⇒ 语义不变）；
③ **替代路径清晰且语义等价**：改为驱动子模块的**输入端口**（`child.io().din <<= …`），
   由子模块自己的运算消费。

ⓘ **注释性陈述（不是承重理由 —— 实现成本会随重构漂移）**：`ch_reg` / proxy 的重定向是
**单打印点**的驱动替换（`print_reg` 一处 · `print_proxy` 一处）；而 op 操作数要替换
`src(k)`，需要在**全部操作数打印路径**按槽位做 module 作用域的名字替换（面广、漏一处
即静默错 RTL）。⇒ ⇒ **即使将来 emitter 重构使该成本下降，本格仍拒绝** ——
承重的是理由 ① / ②。

⚠️ **矩阵的第八格（v1.9 · oracle 实测）**：**父层驱动子模块的 `ch_out` 端口**
（`child.io().dout <<= parent.io().a`）⇒ ⇒ **拒绝**（同型：父层重写子的数据通路）。
⇒ ⇒ ⚠️ **它今天恰好被白名单挡住**（发射层行 1 只收 `type_reg`）⇒ ⇒ 但那是
**偶然的 fail-closed**：B2b-3 给白名单加 `type_proxy` 时，若有人顺手加 `type_output`
（「反正也是合成 input + assign」）⇒ ⇒ 就打开了**唯一无法用合法 Verilog 实现**的形态
（实例的 output 只能由**实例内部**驱动）⇒ ⇒ ⇒ MUST 显式列入拒绝清单，
**MUST NOT** 依赖白名单的偶然形状。
⇒ ⇒ **替代路径**（二者择一）：① 子模块加 input 端口 + 子内
`assign dout = select(use_ext, ext_in, <内部信号>)`（⇒ 显式表达「父层接管」而不是让
新端口悬空）；② 把 `dout` 的驱动源改为**经端口的输入**（⇒ 子内不再有本地驱动）。
⚠️ **MUST NOT** 写成「加 input 端口」却不消费它 —— 那不是替代路径，只是多一个悬空端口。

ⓘ **行 2 的一个已验证推论（v1.9）**：**父层读子模块的 `ch_in` 端口**
（`parent.io().y <<= child.io().din`）⇒ ⇒ 分析层已正确归类为行 2（子侧端点不是 output 端口）
⇒ ⇒ 合成子侧 `output __x_<n>` + 子内 `assign __x_<n> = <din 的全局名>;`
⇒ ⇒ **合法 Verilog**（读自己的 input 端口）⇒ ⇒ 该形态**不需要**额外机制，
写在此处以免后人当成空格再探。

⚠️ **对照：`operator=` 不产生跨 module 边**（同一探针）—— `child.instance().sum = x`
是**本地句柄重绑定**（ADR-042 已定性「不是连接手段」）⇒ ⇒ 实测 `ok=1` ⇒ 无需任何处理。
⚠️ **bundle 字段（proxy）在矩阵内**（行 1「子侧端点不是子端口」）⇒ ⇒ 实测可达且产生跨
module 边 ⇒ ⇒ **必须合成**（复用寄存器形态的节点级重定向 ⇒ proxy 有独立 driver 槽位）。

⚠️ **「跨模块」的判定口径 MUST 用「**inline 折叠后**的 module 归属**」（v1.2，oracle R16）：
若 mem 与访问者被同一个 **inline** 组件/父层包住（⇒ 折叠后同属一个 module）⇒ ⇒
**不是**跨模块，MUST NOT 拒绝。⇒ ⇒ 若按**原始 owner** 判 ⇒ ⇒ `chlib::memory` / `riscv2i_tcm`
被 inline wrapper 包住、父层读其 mem 的**合法**写法会被**误拒**。

**跨模块 `ch_mem` 的两条替代路径（拒绝时 MUST 一并给出）**：

1. **父层持有 mem**：父层 `ch_mem` + 把**地址/写数据**经**端口**下发给子模块，
   把**读数据**经**端口**取回 ⇒ ⇒ mem 与它的使用者**同层**；
2. **子模块持有 mem**：子模块把「读结果」做成自己的 `ch_out`（或经一个**显式读端口**）
   ⇒ ⇒ 父层只经**端口**取数 ⇒ ⇒ mem 与它的使用者**同层**。

⇒ ⇒ ⇒ **两条路径的共同点**：**mem MUST 与使用者同层** ⇒ ⇒ ⇒ 这是本裁决的实质。

⚠️ **第三行是最容易写错的一格**：子模块的 `ch_out` **不能**由父模块的节点驱动
（`ch_out` 的 `src(0)` 在子模块内）⇒ ⇒ ⇒ 必须把驱动**搬进**子模块（隐式 input + 内部 assign）。

⚠️⚠️ **但「子侧端点是子端口」那一半的规则由粒度决定**（v1.3，ADR-062 决策①）：

| 组件粒度 | 其 `ch_in`（**有** driver） | 其 `ch_out` |
|---|---|---|
| **inline** | 父 module 内 **wire**（扁平规则，`src/codegen_verilog.cpp:333-360`） | 祖先 module 的 output 端口 |
| **成层** | **本 module 的 input 端口**（父层用实例端口映射连接）⇒ ⇒ emitter MUST **忽略** `driver()` | 本 module 的 output 端口 |

⇒ ⇒ ⚠️ **把「有 driver 的 `ch_in` ⇒ 内部 wire」照搬到成层组件 ⇒ 它的输入端口会全部消失
⇒ 父层驱动落在别的 module 体内 ⇒ 跨 module `assign` ⇒ 非法 Verilog。**

⚠️⚠️ **「图重写」MUST NOT 真的改 IR**（v1.2，oracle R12）：自然实现是 `set_src`，但
`regimpl::set_next` 本身就是 `set_src(0, next)` 并维护 `users_`
（`include/ast/ast_nodes.h:46-54` · `include/core/lnodeimpl.h:118,142`）⇒ ⇒ 一旦真改图：
(a) **之后**调 `toVerilog()` 产物也变 ⇒ `ADR-058 §2.3` 的「既有路径逐字节不变」**破产**；
(b) **解释器行为变**（同一 ctx 被重新求值）；(c) **两次生成不确定**。
⇒ ⇒ 裁决：该行只允许**发射期的虚拟重定向**（emitter 内部保存「本模块内这个端口的驱动者是谁」
的覆盖表），**MUST NOT 写回 `lnodeimpl`**。

⚠️ **策略默认「合成 + 告警」**，且 MUST：
① 打 `CHWARN` 点名路径；② 在生成文件里写 `// implicit port (bundle/member crossing)`；
③ 提供 `strict` 策略（`CHFATAL_EXCEPTION`）把「非法跨层访问」整体关掉。

### 2.2 决策 ② —— 悬空子输入：**向上冒泡**（复刻扁平行为）

> 无 driver 的子 `ch_in` ⇒ ⇒ **逐级向上冒泡** ⇒ ⇒ 最终成为**顶层 input**
> ⇒ ⇒ **名字 = 该输入节点在 ctx 级全局命名表里的名字（sanitize 后）**
> ⇒ ⇒ ⇒ 因此**与扁平产物里的那个顶层 input 逐字相同** ⇒ ⇒ 顶层可驱动。

⚠️ **为什么 MUST 复用扁平名，而不是发明 `__undriven_<path>` 前缀**（v1.1 订正，
critic BLOCKER B1）：`__undriven_` 与 ADR-061 决策④「MUST NOT 引入任何新的改名」
**互斥**；且会让 `hier.top_ports ⊆ flat.top_ports` **必然不成立**（名字不同 ⇒ 不是子集），
又会让下游按 ctx 级节点名解析（`resolve_node_id(ctx,name)`）**失效**
（`__undriven_` 名**没有**对应节点）。
⇒ ⇒ **来源信息用注释承载，不用名字**：在端口声明旁写
`// implicit: undriven input of <组件路径>` ⇒ ⇒ 信息不丢，名字不变。

⚠️ **作用域限定**：`__if_<n>` / `__x_<n>` 这类**合成端口名**只允许出现在
**非顶层** module 的端口上（那些端口在扁平产物里**不存在** ⇒ ⇒ 无「逐字一致」义务）。
⇒ ⇒ **顶层端口名 MUST NOT 带任何框架前缀**（`__if_` / `__x_` / `__undriven_`）。

⚠️ **合成名与用户节点名的去重（v1.9）**：`__if_<n>` / `__x_<n>` **不经过** `node_names_`
的去重表（`synthesized_ports` 直接进 `print_header`）⇒ ⇒ 若用户节点恰好叫 `__if_0`
⇒ ⇒ **重复声明**（lint 会响 = 响亮失败，但属**可预防**缺陷）⇒ ⇒ 发射前 MUST 断言合成名
不在 `names` 表内；冲突时顺延 `_N`。

⚠️ **命名订正（v1.8）**：v1.7 及以前写 `__if_<field>` ⇒ ⇒ **不准确** —— 隐式端点**不是**
bundle 字段（没有 `field` 名，它是子模块内部的寄存器/proxy 节点）⇒ ⇒ 实现取 `__if_<n>`，
`n` = 该 module 内的出现序（与 `__x_<n>` **对称**）⇒ ⇒ 确定性由「按路径 + 出现序派生」
保证（§4 否定项 3 的同一条规则）。

⚠️ **冒泡的注册层位与端口顺序（v1.13 · G3 · B3 实施前定死）**：

| # | 规定 | 理由（承重） |
|---|---|---|
| **G3-1** | 冒泡端口 MUST 在**分析层**端口表登记（`HierarchyPortOrigin::Bubbled`，逐级同名）⇒ ⇒ **MUST NOT** 由发射器在顶层「就地合成」 | 顶层端口表 MUST 与扁平产物**逐字逐序**一致（ADR-058 §5：clock → reset → 无 driver 的 input → 全部 `ch_out`）⇒ ⇒ 而发射期合成端口**恒追加在节点端口之后** ⇒ ⇒ bubbled input 会排到 `ch_out` 之后 ⇒ ⇒ **两序发散** |
| **G3-2** | **分析层** MUST 用 **G0 的 chain builder**（v1.12 §2.3）同时产出**逐级同名端口**与**每跳的 pass-through 连接**（`HierarchyConnection{同名, 同名, into_child=true}` ⇒ 进中间祖先 module 的对应实例 `connections`）⇒ ⇒ 发射器 **MUST NOT** 自行推导冒泡连接 | 现状连接表**只从有 driver 的边生成**（`src/hierarchy_analysis.cpp` 遍历 `src(i)`）⇒ ⇒ 无 driver 的 `ch_in` **没有 src ⇒ 不产生任何连接条目** ⇒ ⇒ 若发射器不自行补，中间祖先的端口会**空连接** ⇒ 叶 module 的 `ch_in` 读到 0 ⇒ ⇒ **值传到中途断线且零报错**（lint 只查语法） |
| **G3-3** | 链路遇到**已存在的分析层端口**（同名 + 方向 + 宽度一致）⇒ **幂等复用**；方向或宽度不一致 ⇒ fail-closed | G3-1 让端口先存在于分析层 ⇒ 若「已存在」一律按撞名拒绝 ⇒ **合法形态被误拒** |
| **G3-4** | 冒泡**不引入**新端口名（名字恒为 ctx 级全局名，§2.2）⇒ 顶层端口名 MUST NOT 带任何框架前缀 | 与扁平逐字相同 ⇒ 外部 TB 在同一处驱动；下游按名解析不失效 |
| **G3-5** | **顶层 module 的 `ModuleView::synthesized_ports` MUST 恒空**；任何「顶层需要新端口」的需求 MUST 走**分析层端口表**（新增 origin 类型），MUST NOT 走 `synthesized_ports` | G3-1 的禁令需要一个**可判定**的判据：`print_header` 对 `synthesized_ports` **无条件追加在节点端口之后**（`src/codegen_verilog.cpp:344-351`）⇒ ⇒ 顶层多出的合成端口会**静默排到 `ch_out` 之后** ⇒ 顺序错是**语义级**缺陷，lint 看不见 |
| **G3-6** | ⚠️ **G3 只约束冒泡路径**：**第三轴 / 兄弟边**的合成端口仍在**发射期**（它们只落在**非顶层** module ⇒ 不参与顶层端口序）⇒ ⇒ 但两处的**链条机制 MUST 是同一份实现**（抽成同一内部 helper，各一处调用）⇒ ⇒ MUST NOT 各自维护一份链 | G0 的目的就是消除「两条链必然漂移」；若为满足 G3-1 而在分析层复制一份 chain builder ⇒ ⇒ 反而制造两条链 ⇒ **G0 落空** |

⇒ ⇒ 另提供 `Reject` 策略 ⇒ 供「不允许隐式悬空端口」的设计使用
（**确切语义见 §2.4.2** ⇒ ⇒ 错误载体 = 错误结果，不是异常 ⇒ ADR-058 §2.3 ⑤）。

⚠️ **为什么必须冒泡**：事实⑤ ⇒ 扁平产物把这类端口暴露在顶层 ⇒ 若层次化产物
**不**暴露 ⇒ ⇒ 外部 TB **无法驱动**它 ⇒ ⇒ ⇒ 两份 RTL **行为分叉** ⇒ ⇒ ⇒ 等价性判据失效。

### 2.3 决策 ③ —— module 复用：**当前不触发**（条件条款）

⚠️ **作用面（ADR-061）**：复用只在**成层组件**之间发生 ⇒ ⇒ ⇒
**被 inline 的组件**根本不产生 module ⇒ ⇒ ⇒ 无复用可言。

⚠️ **复用在当前命名规则下不触发**（v1.4，ADR-062 §2.6）：端口名 MUST 含**实例路径前缀**
⇒ ⇒ 同类型两实例的**端口签名（名字序列）必然不同** ⇒ ⇒ 「三要素全等」中的第 ② 条**恒不成立**
⇒ ⇒ ⇒ **每实例一份 module**（⇒ 复用是**优化**，命名一致性是**契约**；二者不可兼得，
本仓取契约）。⇒ ⇒ 本节的复用条款保留为「**将来若改相对端口名**才生效」的条件条款。

> ⚠️ **当前生效的裁决是「MUST NOT 复用」**（§5）；以下是**将来若改相对端口名**才生效的
> **条件条款**（⇒ 三要素全等**才**允许复用）：
> ① `module_type_name()` 相同；
> ② **端口签名**相同（名字 / 方向 / 宽度序列）；
> ③ **体内等价性签名**相同（= 体内的**可观测**对象逐项相等：节点类型序列 +
>   常量字面值集合 + `ch_reg` 初值集合 + `ch_mem` 深度/初值 + 是否含 `sread`）。

⚠️ **MUST NOT 把「模板 / 构造实参」写进签名**（v1.1 订正，critic SF）：`ch_module`
只把实参**转发**给子组件构造函数（`include/module.h:60`），**不记录**任何东西
⇒ ⇒ ⇒ 该维度**没有数据来源、无法机械比对**。⇒ ⇒ 改为比较**可观测的体内对象**
（⇒ 构造实参若真的影响行为，必然体现在初值 / 深度 / 节点形态上）。

⇒ ⇒ **任一不等 ⇒ 按实例各发一份 module**（MUST NOT 合并）⇒ ⇒
⇒ 事实③ ⇒ ⇒ 「同类型 + 同端口」**不足以**复用。

⚠️ **模块名冲突**：`module_type_name()` 相同但**组件类型不同** ⇒ ⇒ MUST
`CHFATAL_EXCEPTION`（**MUST NOT** 静默合并）。

⚠️ **同类型多实例的 module 命名**（critic NIT）：不复用 ⇒ 每实例一份 ⇒
module 名 MUST 是 `<module_type_name>_<序号>`（序号 = 组内实例按**路径排序**）
⇒ ⇒ 保证**确定性**且无重名（⇒ 否则 Verilator 报 duplicate module）。

### 2.4 决策 ④ —— 旋钮形态：**单一线性枚举**（避免布尔组合产生未定义态）

```cpp
// 本 ADR 只定义**它拥有的**两个枚举；选项结构的**唯一权威定义**在 ADR-061 §2.5
// （⚠️ 不要在这里再写一份 `VerilogHierOptions` —— 三份副本必然漂移，critic NIT）
enum class PortPolicy     { SynthesizeWarn, SynthesizeFatal, Reject };
enum class UndrivenPolicy { Bubble, Reject };
```

⚠️ **为什么不用布尔开关**：`implicit_ports` / `strict` / `emit_undriven_bubble` 三个布尔
两两组合会产生**语义重叠**的组合（如 `strict=true` + `implicit_ports=true` 谁赢？）⇒ ⇒ ⇒
**MUST NOT** 留给实现者自行发明 ⇒ ⇒ ⇒ 改为**两个线性枚举**。

⚠️ **默认值（2026-11-02 · 用户拍板）**：
`port_policy = SynthesizeWarn`（合成 + 告警）· `undriven_policy = Bubble`（冒泡）
⇒ ⇒ 理由：二者都**与扁平输出行为最接近** ⇒ ⇒ ⇒ 等价性判据最简 ⇒ ⇒ ⇒
`SynthesizeFatal` / `Reject` 作为**可选**的严格模式保留。

### 2.4.1 三个 `PortPolicy` 取值的**确切语义**（v1.7 裁决 —— 此前只定义枚举、**未定义语义**）

| 取值 | 是否合成 | 是否产出文件 | 失败/告警时 MUST 提供的诊断 |
|---|---|---|---|
| `SynthesizeWarn`（**默认**） | ✅ 合成 | ✅ 产出 | `CHWARN` 点名**每一条**被合成的边 + 合成端口名；**发生合成时**产物内写注释 |
| `SynthesizeFatal` | ✅ 合成（**先合成完**） | ❌ **不产出** | **错误结果**里 MUST 列出**全部**被合成的边 + 合成端口名（⚠️ v1.13 按 ADR-058 §2.3 ⑤ 收窄：**删除原「/ 异常」** —— 发射器路径 MUST NOT 依赖异常 ⇒ 异常会落进 `print()` 的 `catch(...)` ⇒ 静默失败） |
| `Reject` | ❌ 不合成 | ❌ 不产出 | 只报**第一条需合成的跨 module 边**（= **可合成集**的第一条；**本档**不合成 ⇒ 无从列出合成端口名）· ⚠️ **v1.18 消歧**：「越界边」曾指代不明 ⇒ ⇒ 现明确 = **可合成集**（矩阵内 · 能被合成的边） |

⚠️ **为什么 `SynthesizeFatal` ≠ `Reject`**：二者**都失败**，但 `SynthesizeFatal` **先完成合成**
⇒ ⇒ 诊断信息**完整**（哪几条边、合成出哪些端口、各叫什么名字）⇒ ⇒ 用户可照着改设计；
而 `Reject` 连合成都不做 ⇒ ⇒ 只能给出第一条越界边 ⇒ ⇒ 用户得**反复试错**才能收敛。
⇒ ⇒ ⇒ **`SynthesizeFatal` 的价值 = 「失败的诊断质量」**，不是「更严格的门」。

⚠️ **执行时机（承重）**：`SynthesizeFatal` 的失败 MUST 在**合成完成之后**才发生
⇒ ⇒ 否则「先合成再报错」退化成「先报错再合成」（诊断为空）⇒ ⇒ 该取值**失去存在意义**。

⚠️ **`UndrivenPolicy` 只有两格**（`Bubble` / `Reject`）⇒ ⇒ 无「Fatal」格 ⇒ ⇒ 因为「悬空输入」
的诊断（哪条输入悬空、冒泡到哪几层）**不依赖合成动作** ⇒ ⇒ 两格够用。

⚠️ **与 ADR-058 §2.3 错误模型的接缝（承重 · MUST 声明）**：「合成」MUST 是**纯内存 phase**，
**先于任何文件 I/O** ⇒ ⇒ ⇒ 「先合成完再失败」⇒ ⇒ **无临时文件、不触碰既有文件**
⇒ ⇒ ⇒ 与 §2.3 ①「所有校验 MUST 在第一次 I/O 之前完成」· ②「临时文件 → rename」**兼容**。
⚠️ ⇒ 若将来 emitter 重构把合成挪到**流式写出之后** ⇒ ⇒ 本裁决与 §2.3 ① 将**静默互斥**
⇒ ⇒ ⇒ **该次序 MUST 留在契约里**（不得只靠实现事实维持）。
⚠️ **「是否产出文件」在单文件模式下的确切含义** = 「**不产出那唯一一个产物文件**」
（产物形态 = 单文件多 module ⇒ 见 ADR-058 v2.9 §2.3）⇒ ⇒ 「合成已完成」与「无文件产出」
**并存不悖**（合成结果只存在于内存，随失败一起丢弃）。

⚠️ **「合成不适用」与「合成尚未实现」MUST 区分**（v1.8）：

| 情形 | 处置 | 与 `PortPolicy` 的关系 |
|---|---|---|
| **合成不适用**（矩阵外的形态：`ch_uint <<=` 改写操作数 · **跨模块 `ch_mem`（= mem **本体**跨 module · ADR-066 §2.7 (i)）** · 成层组件自驱动 `ch_in`） | **始终拒绝**（`CHFATAL_EXCEPTION` / 错误结果） | **无关** —— 策略管的是「**可合成**的边要不要合成 / 要不要出声」，**不是**「把非法形态放行」 |
| **合成尚未实现**（实施中间态） | **MUST fail-closed**（不产出文件） | **无关** —— 取值叫 `SynthesizeWarn` **不**授权静默产出**错误产物** |

⇒ ⇒ ⇒ **T3-④ 归档的前置判据**：默认策略 `SynthesizeWarn` 在**全部可达形态**上 MUST 符合
上表（「可达形态」= 本 ADR §2.1 矩阵内的行 + 第三轴 + 兄弟边；矩阵外形态由「拒绝」覆盖）。
⇒ ⇒ 「部分合成 + 错误产物」**不**是合法中间态。

⚠️ **与「全 inline ⇒ 与扁平逐字节一致」判据的张力（已消解）**：默认策略是 `SynthesizeWarn`
且产物内写注释 ⇒ ⇒ 但注释**只在确实发生合成时**出现 ⇒ ⇒ 而「全 inline」形态**没有跨 module 边**
⇒ ⇒ ⇒ **无合成 ⇒ 无注释** ⇒ ⇒ ⇒ 「逐字节一致」判据**不受影响**。

### 2.4.1.1 `SynthesizeWarn` 的**产物注释**（v1.18 —— 此前只写「产物内写注释」、**未定义文本与位置**）

⚠️ **为什么现在写死**：§2.4.1 的 `SynthesizeWarn` 行只说「**发生合成时**产物内写注释」⇒ ⇒
**没有文本、没有位置、没有触发定义、没有数量口径** ⇒ ⇒ 实现者必然即兴 ⇒ ⇒ 而注释是
**产物内容** ⇒ ⇒ 一旦各实现各写 ⇒ ⇒ 产物的**可 grep 判据**与**逐字节可比性**都失效
⇒ ⇒ 本节把四件事写死。

**① 「发生合成」的**确切定义**（**结构化** · 不按机制枚举）**：

> **注释义务的对象 = `ModuleView::synthesized_ports` ∪ `ModuleView::synthesized_wires`
> 的**全体成员***（发射器的**两个**「合成物」载体）⇒ ⇒ 落在任一载体里 ⇒ ⇒ **必须**有注释。
> ⚠️ **「唯二载体」的精确说法**（v1.18 · critic SHOULD_FIX 修正）：发射器**还有**第三个把
> **注入端口**（clock / reset）写进产物的通道（发射期 `view.ports`）⇒ ⇒ 但它**不是**「合成物」
> ⇒ ⇒ ⇒ 故本节的对象仍 = 上述**两个**向量；**MUST NOT** 把该句读成「发射器只有两个产物通道」。

| 机制（**例证**，非穷举） | 载体 | 算「发生合成」？ |
|---|---|---|
| 隐式端口合成（`__if_<n>` / `__x_<n>`） | `synthesized_ports` | ✅ |
| 第三轴链的 `__up_` 端口 | `synthesized_ports` | ✅ |
| 父侧落点网（ADR-066 决策 ①） | `synthesized_wires` | ✅ |
| 向上 pass-through 的体内重定向网 / 兄弟边中转网 | `synthesized_wires` | ✅ |
| **冒泡端口**（`UndrivenPolicy::Bubble`） | **不在**上述两载体 | ❌ **不算**（**独立**义务 ⇒ 见下方边界句） |
| **注入 clock/reset**（非 root module · 发射期 `view.ports`） | **不在**上述两载体 | ❌ **不算**（时钟 / 复位 = **基础设施端口** · 命名约定已可识别 ⇒ ⇒ 非「合成物」） |
| **扁平路径**（全 inline） | 两载体**恒空** | ❌ **不适用**（⇒ **零**注释 ⇒ ⇒ 「逐字节一致」不变量保持） |

⚠️ **闭合句（承重 · 防第三载体）**：未来发射器**新增产物载体**时，MUST 落进上述**两个向量之一**
⇒ ⇒ 自动获得本节的注释义务 ⇒ ⇒ **MUST NOT** 开第三个载体（否则 ⇒ 义务**静默失效**）
⇒ ⇒ 对齐 §2.2 G3-5 的句式。

**② 精确文本（逐字 · 唯一权威）**：

| 对象 | 注释行（**逐字**） |
|---|---|
| 合成端口 | `    // CppHDL-synth: implicit port <name> (ADR-060 2.4.1)` |
| 合成网（落点网 / 中转网 / 体内网 **统一**） | `    // CppHDL-synth: net <name> (ADR-060 2.4.1)` |

⚠️ **缩进 = 4 空格**（与 `port_notes` 的既有形态**逐字对齐** ⇒ ⇒ 产物内两套标注缩进一致）。

⚠️ **为什么网用**统一**文本 `net`**：合成网载体里同时装着**父侧落点网**、**兄弟边中转网**、
**向上 pass-through 体内网** ⇒ ⇒ 若按机制分文本 ⇒ ⇒ 每加一种网就要加一种文本
⇒ ⇒ **机制误标**风险 ⇒ ⇒ 故按**载体**分两类文本（`implicit port` / `net`）⇒ ⇒ 文本**可穷举**。

⚠️ **文本纪律**：标记前缀 = `// CppHDL-synth:`（**行注释** · Verilog 语法）⇒ ⇒
① `<name>` = 该合成物在产物里的**名字**（与声明行**逐字**相同）⇒ ⇒
② 文本 MUST **只含名字** ⇒ ⇒ **MUST NOT** 含时间戳 / 绝对路径 / 计数器 / 档位名
⇒ ⇒ **确定性**（两次发射**逐字节相同** ⇒ ADR-058 §2.3 的确定性不变量保持）⇒ ⇒
③ 注释 MUST **不含**「这条边是哪两端」等**易漂移**信息 ⇒ ⇒ 边的定位由 **`CHWARN`** 承担。

**③ 位置**：
- **合成端口** → **端口表内、该端口条目**正上方**单独成行**（与 §2.2 `port_notes` 的既有形态**逐字同类**
  ⇒ ⇒ 形态先例 = `src/codegen_verilog.cpp` 的 `port_notes` 发射段 ⇒ ⇒ R1 lint 门对该形态**恒绿**
  ⇒ ⇒ ⚠️ **插入点 = 合成端口的发射循环内**（端口文本**之前**、逗号**之后**）⇒ ⇒
  **MUST NOT** 复用 `port_notes` 的**查表**机制（合成端口**不是 IR 节点** ⇒ ⇒ 查表键不存在））
  ⇒ ⇒ ⚠️ 合成端口**只在端口表里声明一次**（`print_decl` **不**声明它们）⇒ ⇒ 「声明正上方」在此**只能**指端口表内；
  ⇒ ⇒ ⚠️ 被禁的是**行尾注释**（会吞掉端口表的逗号 ⇒ 语法破坏）⇒ ⇒ **MUST NOT** 用行尾注释；
- **合成网** → `print_decl` 里该网 `logic` **声明行的正上方**一行（同 module、同缩进）。

**④ 数量**：**每个合成物恰好一处**注释 ⇒ ⇒ MUST NOT 每 module 汇总成一条
⇒ ⇒ 否则「哪条边被合成」不可定位 ⇒ ⇒ 与 §2.4.1 的 `CHWARN` 义务**互补**
（`CHWARN` = 运行期可见 + 点名**边与端口名**；注释 = 产物内可追溯 + 名字一致）。

⚠️ **v1.18 登记：`CHWARN` 义务在**成功路径**上是**新增**的**：§2.4.1 表要求
`SynthesizeWarn` 的 `CHWARN` 点名**每一条**被合成的边 + 合成端口名
⇒ ⇒ 但**现状**：成功合成路径**零** `CHWARN`（现有 CHWARN 只在**失败集**非空时触发）
⇒ ⇒ ⇒ **P7 MUST 新增**：每一条被合成的边 MUST 产出一条 `CHWARN`（进 `HierarchyEmitResult::warnings`
⇒ ⇒ 测试通道 = `r.warnings` ⇒ ⇒ 既有先例见 `tests/test_hierarchy_verilog.cpp` 的 warnings 断言）
⇒ ⇒ 与本节的产物注释**同源触发**（同一「被合成的边」集合）⇒ ⇒ ⚠️ ★ **两条计数**必须**分别**判
（v1.18 · critic BLOCKER 修正）：
⇒ ⇒ ① `CHWARN` 数 MUST == 被合成的**边**数；
⇒ ⇒ ② 注释数 MUST == 两载体**成员**数；
⇒ ⇒ ⇒ ⚠️ **二者无「MUST 相等」关系** —— **一条边可合成多个产物**（第三轴链：每 hop 一个
`__up_<n>` 端口 + 目标为 reg/proxy 时另加一根体内网 ⇒ ⇒ 1 条边 ⇒ k 个端口 + 1 根网）
⇒ ⇒ ⇒ ⇒ **MUST NOT** 写「二者计数一致」（不可满足 ⇒ ⇒ 实施方无从判断通过）⇒ ⇒ 判据**分别**核。

⚠️ **合成名的跨重构稳定性（v1.18 已知并接受）**：`__if_<n>` / `__x_<n>` 的序号依赖**模块内出现序**
⇒ ⇒ **跨重构会变** ⇒ ⇒ 但本节的判据是「**同一代码状态下**两次发射逐字节相同」
⇒ ⇒ 序号名满足该判据 ⇒ ⇒ 且「注释里的名字与声明行**逐字**相同」比「名字跨重构稳定」**更重要**
⇒ ⇒ ⇒ 故维持「**只含名字**」，**不**改用驱动端点的 ctx 全局名（它同样跨重构漂移 ⇒ ⇒ 稳定性收益是假的）。

⚠️ **与 §2.4.2（`UndrivenPolicy`）的边界**：冒泡端口**不属**本节义务 ⇒ ⇒ 它的注释 = §2.2
既有的 `port_notes`（文本 `// implicit: undriven input of <组件路径>` · **逐字不变**）
⇒ ⇒ ★ 本节 **MUST NOT** 引入第二个标记去改写 §2.2 的文本（那是**另一次**契约变更）
⇒ ⇒ 两类注释因此**天然可区分**（文本前缀不同：`CppHDL-synth:` vs `implicit:`）。

⚠️ **「与 `PortPolicy` 无关」的**确切含义**（v1.18 澄清 —— **不是**「诊断也不变」）**：
⇒ ⇒ **无关**指的是**判定与处置**（矩阵外形态**一律拒绝** ⇒ ⇒ 不因档位而放行），
⇒ ⇒ **不**排除**诊断广度**随档变化 ⇒ ⇒ v1.7 表 `Reject` 行的「只报第一条越界边」
⇒ ⇒ 与 §2.4.1.1 上表的「与策略无关」**并存且不矛盾**⇒ ⇒ ★ **MUST NOT** 把「无关」
读成「诊断广度也不许随档变化」⇒ ⇒ 现状实现 `all = (policy != Reject)`（广度随档）
⇒ ⇒ **合规** ⇒ ⇒ 但 MUST 在契约里**写死**（否则下一个人会按字面把它当 bug 改掉）。
⇒ ⇒ ⚠️ **失败集 = 本发射**无法合成**的形态（v1.18 补写 · 承重 · critic SHOULD_FIX 修正）**：
⇒ ⇒ 失败集 ⊇ **矩阵外形态**（`ch_uint <<=` 改写操作数 · 跨模块 `ch_mem` · 自驱动 `ch_in`），
⇒ ⇒ **且**含**矩阵内但合成失败**的形态（**表亲边**（矩阵邻域但本批不合成）· **宽度不一致**
（矩阵内 1/2 行 · v1.10 响亮拒绝））⇒ ⇒ ⇒ ★ 即「**发射器合成诊断的全体成员**」
⇒ ⇒ ⇒ ⚠️ **MUST NOT** 把失败集**窄化**成「矩阵外形态」（否则 ⇒ ⇒ 拿宽度不一致边对照本段
⇒ ⇒ 仍会得出「实现违反契约」）⇒ ⇒ 失败集**同样**受
**这一个**旋钮控制 ⇒ ⇒ `Reject` = 只报**第一条**、其余档 = 报**全部** ⇒ ⇒ 现状实现
`all = (policy != Reject)`（**一个**旋钮覆盖两集）⇒ ⇒ **合规** ⇒ ⇒ ★ 这句话的作用 =
把 `:956` 从「看着像 bug」变成「**契约写死**」⇒ ⇒ **MUST NOT** 只改失败集那一半。
⇒ ⇒ ⚠️ 三档对**可合成**边的差异 = **合成与否** + **产物注释** + **诊断广度**三面
（`SynthesizeWarn` = 合成 + 注释 + 全部诊断；`SynthesizeFatal` = 合成 + **不产出** + 全部诊断；
`Reject` = **不合成** + 无注释 + **第一条**诊断）⇒ ⇒ 对**矩阵外**形态三档**同样失败**
⇒ ⇒ 差异**只在**上面那三面。

### 2.4.2 `UndrivenPolicy` 两格的确切语义（v1.13 —— 此前只定义枚举、未定义语义）

> ⚠️ **为什么要写死**：`undriven_policy` 在 v1.12 之前**没有任何实现读取**
> （选项字段存在但零行为 ⇒ Zero-Debt 违规）⇒ ⇒ 不定义语义 ⇒ 实现者必然即兴
> ⇒ ⇒ 而「哪一类悬空输入算『隐式悬空端口』」直接决定**会不会误拒合法设计**。

| 取值 | 行为 | 是否产出 | 诊断义务 |
|---|---|---|---|
| `Bubble`（**默认**） | 逐级冒泡（§2.2 的 G3） | ✅ 产出 | 每条悬空输入一条 `CHWARN`（点名**端口名 + 所属 module + 冒泡层级**）+ 端口声明旁注释 |
| `Reject` | **不冒泡** | ❌ **不产出** | 错误结果 MUST 列出**全部**悬空输入（端口名 + 所属 module + **该输入将要冒泡的层级链**） |

⚠️ **`Reject` 的适用范围（承重 · v1.13）**：只对「**inline 折叠后的 module 归属**是
**非根成层 module**」的悬空 `ch_in` 生效（口径与 ADR-062 v1.2 的「inline 折叠后的 module
归属」同词 ⇒ ⇒ 用 module 归属，不用原始 Component owner）。
⇒ ⇒ 下列两类**不属**「隐式悬空端口」，**两格都 MUST NOT 触发 `Reject`**：
① **根 module 自己的 `ch_in`**（扁平产物里它就是顶层 input ⇒ 是 TB 的**正常驱动点**）；
② **inline 折叠进根 module** 的悬空 `ch_in`（扁平产物里**同样**是顶层 input）。
⚠️ **理由**：`Reject` 的承重对象是「**跨 module 边界的隐式传递**」；把它扩到上述两类
⇒ ⇒ 等于**拒绝合法设计** ⇒ ⇒ 与 §2.2「复刻扁平行为」**直接冲突**（⇒ 也违反 §2.4 的
「默认与扁平行为最接近」的选型理由）。
⚠️ **诊断广度 = 全部**（不是首条）：悬空诊断**不依赖合成动作**（同 §2.4.1 的
`SynthesizeFatal` 理由）⇒ ⇒ 一次列全 ⇒ 用户一次改完。
⚠️ 失败载体 = **错误结果**（`ok=false` + 点名），MUST NOT 依赖异常（ADR-058 §2.3 ⑤）。

### 2.5 lint 门的**可执行定义**（v1.9 · 据 oracle 实测）

⚠️ **为什么必须写死**：ADR-058 §5 与本文多处写「MUST 通过 `verilator --lint-only`
**零 Error / 零 Warning**」⇒ ⇒ 该口径此前**没有可执行定义** ⇒ ⇒ 实测三个反例：
① 仓内 lint 辅助（`tests/external_tool_helpers.h:99`）用 **`-Wno-fatal`** ⇒ ⇒ warning
**不影响退出码** ⇒ ⇒ `PINMISSING` 不会让 exit ≠ 0；② `tests/test_hierarchy_verilog.cpp`
全文**没有** lint 调用 ⇒ ⇒ 现有「exit 0」只来自**手工探针**；③ **`-Wall` 下 `.port()`
空连接触发 `PINCONNECTEMPTY`** ⇒ ⇒ 若把门写成 `-Wall`，ADR-061 v1.6.4 的空连接方案
**直接变成失败源**（⇒ 而「故意悬空的子输出」是本设计契约的**合法产物**
⇒ ⇒ 升 `-Wall` 会让门的信噪比下降，正确动作是**钉死集合**，不是升墙）。

⇒ ⇒ **裁决（门的确切形态）**：

| 项 | 规定 |
|---|---|
| 命令 | `<verilator> --lint-only --top-module <top> <file>` ⇒ ⇒ **不加 `-Wall`** |
| 退出码 | MUST 捕获：`0` = 通过；非 `0` = 失败 |
| stderr | MUST 额外断言**不含 `%Error`**（防 `-Wno-fatal` 式的「有错误但 exit 0」） |
| `lint_off` | 产物内每条 `/* verilator lint_off ... */` MUST 进白名单（当前仅 `WIDTHEXPAND` / `WIDTHTRUNC`，来自既有扁平基线）⇒ ⇒ 新增任何 `lint_off` MUST 在 change 里登记理由 |
| 验收调用 | **MUST NOT** 用 `-Wno-fatal` |
| 前提 | Verilator 的**默认** warning 集**仍**是 warning-fatal（⇒ 不加 `-Wno-fatal` 时 warning 会使 exit≠0）⇒ ⇒ 这就是「零 Warning」在**不加 `-Wall`** 时仍有意义的原因；`-Wall` 只是把**额外的、本设计合法形态会触发的** warning 加进来（`PINCONNECTEMPTY` / `UNUSED`） |

⇒ ⇒ **编码位置**：`scripts/verify_hierarchical_rtl.sh`（B4 的 R1）+ T3-⑤ 的等价性套件。
⇒ ⇒ 「零 Error / 零 Warning」在本文档中的**唯一**解释 = 上表。

⭐ **实测（2026-11-05 · critic 要求）**：对同一个**合法**三层产物（含一个未消费的子
`ch_out`）分别跑两种门：

| 门 | exit | warning |
|---|---|---|
| `--lint-only --top-module top <file>` | **0** | **0** |
| 同上 + `-Wall` | **1** | **4 类**：`DECLFILENAME`（**单文件多 module ⇒ 文件名只可能匹配其中一个**）· `PINCONNECTEMPTY`（空连接 · ADR-061 决策② 的合法形态）· `UNUSEDSIGNAL` ×2（inline 折叠产生的合法体内信号） |

⇒ ⇒ **四类全部是本设计的合法产物** ⇒ ⇒ 这**不是**「warning 被忽略」，而是 `-Wall`
与本设计的产物形态**结构性不相容** ⇒ ⇒ 更确认「钉死集合、不升墙」的裁决。

## 3. 选项对比（**逐条含理由**）

| # | 选项 | 结论 | 理由 |
|---|---|---|---|
| 1 | **隐式端口：合成 + 告警**（含方向分列规则表） | ✅ **采纳** | ① bundle 成员跨层是 ADR-042 明确支持的**合法**用法（事实②）⇒ ⇒ 直接报错会砍掉合法设计；② 但 MUST **响亮**（`CHWARN` + 文件内注释）⇒ ⇒ 「非法跨层访问」不被合法化得无声；③ 方向分列表消除了「子侧 input」这种**单方向**描述在事实① 四种形态上的歧义 |
| 2 | **隐式端口：直接拒绝**（`CHFATAL_EXCEPTION`） | 🟡 **作为 `strict` 策略采纳** | ① 它把「非法跨层访问」变成**硬错误**⇒ ⇒ 对「接口必须显式」的团队有价值；② 但作为**默认**会砍掉事实② 的合法用法 ⇒ ⇒ ⇒ 只作可选策略 |
| 3 | **隐式端口：降级为内联**（把跨层节点直接拉进使用方模块） | ❌ 否决 | ① 同一节点被两个模块引用 ⇒ ⇒ 必须**复制**⇒ ⇒ 复制后两份逻辑**各自求值**⇒ ⇒ 若该节点有状态（`ch_reg`）⇒ ⇒ ⇒ **两份状态发散** ⇒ ⇒ 静默错 RTL；② 与「模块边界 = 所有权边界」（ADR-058 §2.1）**直接冲突** |
| 4 | **悬空输入：冒泡** | ✅ **采纳** | ① 复刻扁平行为（事实⑤）⇒ ⇒ ⇒ 外部 TB 仍能驱动 ⇒ ⇒ 等价性判据成立；② 顶层多出「子模块的悬空输入」端口是**可见代价**（比「行为分叉」好）⇒ ⇒ 且名字**复用扁平名**（⇒ 不引入新前缀） |
| 5 | **悬空输入：接 0 / 报错** | 🟡 **报错**作可选策略；**接 0** 否决 | ① 接 0 ⇒ 静默改变行为（扁平里它是**可驱动输入**，不是常量）⇒ ⇒ ⇒ 语义分叉 ⇒ ❌；② 报错 ⇒ 合法设计（「故意留空」）被拒 ⇒ ⇒ 只作可选策略 |
| 6 | **module 复用：仅端口签名相同即复用** | ❌ 否决 | ① 事实③ ⇒ 同类型同端口可含不同初值 ⇒ ⇒ ⇒ 复用会把一个实例的初值安到另一个头上 ⇒ ⇒ **静默错 RTL** |
| 7 | **module 复用：三要素全等才复用** | 🟡 **降级为条件条款**（当前**不触发** ⇒ 每实例一份；见 §2.3 / §5） | ① 消除初值串味；② 「各发一份」是**安全退化**（只多几个文件，不出错）；③ 代价 = 同类型多实例时文件变多 ⇒ ⇒ 可接受 |
| 8 | **旋钮：三个布尔开关** | ❌ 否决 | ① 组合语义重叠（`strict` vs `implicit_ports` 谁赢？）⇒ ⇒ ⇒ 未定义态留给实现者 ⇒ ⇒ ⇒ 改为线性枚举 |
| 9 | **冒泡端口在发射期「就地合成」**（`ModuleView::synthesized_ports`） | ❌ 否决（v1.13 · G3-1） | ① `print_header` 对 `synthesized_ports` **无条件追加在节点端口之后** ⇒ ⇒ bubbled input 会排到全部 `ch_out` 之后 ⇒ ⇒ 顶层端口表与扁平**逐字逐序**判据（ADR-058 §5）必然失败；② 若改为「让 `print_header` 按方向插入」⇒ ⇒ 排序逻辑出现**两个点**（发射循环的 `stable_sort` + `print_header`）⇒ ⇒ 必然漂移；③ 合成端口结构**没有 `node` 指针** ⇒ 无法参与既有排序 |
| 10 | **`UndrivenPolicy::Reject` 覆盖全部悬空 `ch_in`** | ❌ 否决（v1.13 · §2.4.2） | ① 根自己的 `ch_in` 与 inline 折叠进根的悬空 `ch_in` 在**扁平产物里本来就是顶层 input**（TB 正常驱动点）⇒ ⇒ 拒绝它们 = 拒绝所有「顶层有输入」的合法设计；② 与 §2.2「复刻扁平行为」及 §3 选项 5「报错只作可选策略」**直接冲突** |
| 11 | **为冒泡在分析层复制一份 chain builder**（不动发射期的第三轴那份） | ❌ 否决（v1.13 · G3-6） | ① 两套链必然漂移 —— 这正是 v1.12 G0 要治的病；② 第三轴与冒泡**方向相反但机制同构**（每级一个同名 input 端口 + 逐跳实例映射）⇒ ⇒ MUST 是**同一份实现**的两个调用点 |

## 4. 后果 / 代价

### 正面
- 跨层的**全部**合法形态（含 ADR-042 支持的 bundle 成员跨层）都有确定规则 ⇒ ⇒ ⇒
  不会出现「文档没写 ⇒ 实现者猜」；
- 悬空端口**不产生行为分叉** ⇒ ⇒ ⇒ 等价性判据成立；
- module 复用**不会串初值** ⇒ ⇒ ⇒ 消除一整类静默错 RTL；
- 旋钮**无未定义组合** ⇒ ⇒ ⇒ 用户可预期。

### 负面
- 隐式端口把「不该跨层的访问」**合法化**（默认策略）⇒ ⇒ ⇒ 必须靠 `CHWARN` 与 `strict` 兜住；
- 顶层会出现「子模块的悬空输入」端口（名字是 ctx 级名 ⇒ 可读性尚可，但**来源**要靠注释）；
- **非顶层** module 会出现 `__if_*` / `__x_*` 这类**框架内部术语**的端口
  ⇒ ⇒ ⇒ 外部评审**不可解读** ⇒ ⇒ ⇒ MUST 随产物产出**端口清单**（见 ADR-058 §4 风险 4）；
- 「各发一份 module」让同类型多实例时文件数增加；
- 决策 ① 第三行（子端口由父层驱动）需要**图重写** ⇒ ⇒ ⇒ 比「加端口」复杂一个量级；
- **跨层宽度不一致从「Verilog 自动扩展/截断」变为响亮拒绝**（v1.10 · W1）⇒ ⇒ ⇒
  少数依赖隐式扩展的跨层写法 MUST 改为**显式** `zext` / 截断（或改驱动子模块的**显式端口**）
  ⇒ ⇒ ⇒ 替代路径 = 驱动显式端口。

### 风险

| # | 风险 | 对策 |
|---|---|---|
| **v1.10** | **新增 `src(0)` 解析路径时漏加重定向守卫** ⇒ ⇒ 引用**父层信号** ⇒ ⇒ 非法 Verilog 且**零告警**（`WIDTHEXPAND` / `WIDTHTRUNC` 均被关）⇒ ⇒ 极难发现 | 不变式 **R1 / R2** 留在**契约**里（不是实现注释）⇒ ⇒ 「重构禁令」记在台账 §11.8 ⇒ ⇒ 且 emitter 的每条解析路径**各自**有守卫 ⇒ ⇒ 变异逐条验证 |
|---|---|---|
| 1 | 隐式端口**方向搞反** ⇒ 产出错 RTL | 方向规则表逐行有判据（§5）+ 四个方向的用例各一 |
| 2 | 子端口由父层驱动（第三行）**被漏做** ⇒ 子模块输出恒 0 | MUST 有该形态的用例（§5 效果判据第 3 条） |
| 3 | `__x_<n>` 的 `n` **不确定** ⇒ 产物不可复算 | 命名 MUST 按「路径 + 序号」确定性派生（序号 = 该 module 内出现序） |
| 4 | 悬空端口名**含路径** ⇒ 同类型两实例的签名不同 ⇒ 复用失效 | 复用判据（决策③）已含「端口签名」⇒ ⇒ 自然退化到「各发一份」⇒ ⇒ 无需额外处理 |
| 5 | 跨模块 `ch_mem` | ✅ **已裁决**（决策①第四行 + §2.1）：**响亮拒绝** ⇒ ⇒ 判据见 §5 |
