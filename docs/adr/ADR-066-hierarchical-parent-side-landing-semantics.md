## 1. 背景（**只陈述决策所需的事实**）

### 1.1 问题的形状：父层「消费」子 `ch_out` 的四种形态

父层消费成层子组件的 `ch_out` 时，**父侧消费点的性质**决定发射器行为（实测 · 2026-11-08）：

| 形态 | 父侧消费点 | C++ 侧 | 发射结果 | 产物 |
|---|---|---|---|---|
| **S1 直通** | 父 `output` 端口 | 合法 | ✅ `ok=1` | **不造网**（子 output 直接接父 output 端口）⇒ ⇒ **逐拍等价实测全等** |
| **族 ①/③** | 父内运算 / 父内 reg / 子 input 的表达式 | 合法 | ❌ **拒绝** | —— |
| **路径 B** | 父内运算 · 消费子**非端口端点**（`ch_reg` / bundle 字段 / op 节点） | 合法 | ✅ `ok=1` | ⚠️ **引用子 module 内部信号名 ⇒ 产物不可编译** |
| —— | 父读子 `ch_out`（**无**运算） | 合法 | ✅ `ok=1` | 父侧读**合成端口名** ⇒ ⇒ 产物干净 |

⇒ ⇒ **只有「父侧消费点不是父 `output` 端口」时**，形态才出问题 —— 而它**分两种结局**：
**被拒**（族 ①/③，子侧端点是**端口**）或**放行但产物坏**（路径 B，子侧端点是**非端口端点**）。

### 1.3 问题（**精确表述**）

**父层消费成层子组件的 `ch_out` 时，父侧消费点的三种合法形态 —— 直通 / 运算 / 内部寄存器 —— 在契约层
只规定了「产物长什么样」（造网 + `.port(net)`），却没有规定「父侧运算的操作数读什么」；
而实现把「父侧带运算」当成了**越界形态**（族 ①/③ 拒绝）或**放任形态**（路径 B 产出坏产物）。**

⇒ ⇒ 本 ADR 回答：**父侧运算的操作数 MUST 读哪个名字**、**哪些形态合法**、**失败时怎么诊断**。

## 2. Decision（**裁决**）

### 2.1 决策 ① —— 父侧消费点**不是**父 `output` 端口时：**支持**（补 ADR-060 §2.1 矩阵一格）

> 父层消费成层子组件的 `ch_out` 时，按**消费点的性质**分成两个子情形，二者的义务**不同**：
>
> **(a) 消费点 = 父 module 的 `output` 端口**（直通 · **无**父侧运算）
> ⇒ ⇒ **无需造网**：子 output MAY 直接作为该 `.port(...)` 的实参
> ⇒ ⇒ 此情形**由决策 ③ 管辖**（造网要求**不适用**）⇒ ⇒ **不是**决策 ① 的授权对象。
>
> **(b) 消费点 = 父 module 体内的节点**（op / reg / proxy 链 ⇒ ⇒ **带**父侧运算，族 ①/③）
> ⇒ ⇒ **MUST 被支持**：父 module MUST 为该子 `ch_out` 合成**一根 `logic` 网**，
> 子 output MUST 以 `.port(net)` 连接该网，**父侧运算的操作数 MUST 读该网**
> （不得读子实例输出）。
>
> ⚠️ **消费者的排除项**：消费点是**父 module 的 `input` 端口**时（子从 module 内部驱动父 `input`）
> = **物理不可行形态** ⇒ ⇒ **MUST 拒绝**并进 fail-closed 诊断。
>
> ⚠️ **落点网的命名 MUST 钉死**：网名 = **驱动端点（子 `ch_out`）的 ctx 全局名**
> ⇒ ⇒ 复用**兄弟边**的既有约定（`src/hierarchy_verilog.cpp:618` 用 `names.at(e.from_ptr)`）
> ⇒ ⇒ **MUST NOT** 用**被驱动节点自体名**（`src/hierarchy_verilog.cpp:697-698` 的
> `names.at(e.to_ptr)`）—— 消费点是表达式时那会产出 **自指**（`assign top_or_or = top_or_or | 1`）
> 与**双驱动**；⚠️ 该陷阱今天**看不见**，只因产物本来就坏（未声明标识符先炸）。

⇒ ⇒ 这**补上** ADR-060 §2.1 矩阵缺的一格（新增拓扑行「**子 → 父 · 父侧带运算**」，
子侧端点 = `ch_out` ⇒ 合成**父侧**网 + **父侧**操作数重定向）。
⇒ ⇒ **实现 MUST 落在 ADR-060 R1/R2 的虚拟重定向表上**（事实 ⑥）。
⇒ ⇒ ⚠️ **但 R2 的四条 `src(0)` 路径枚举是 `input` 方向的面**：本决策的真实失效点在
**表达式操作数的命名**（`src/codegen_verilog.cpp:868-897` 的 `print_unary_op`、
`:1144-1154` 的 `print_mux` 直接用 `node_names_[src]` ⇒ ⇒ **从不查重定向表**）
⇒ ⇒ 故验收 MUST 覆盖**两个面**：「操作数名解析守卫」+「R2 的四条路径回归」（§5 V8）。

### 2.2 决策 ② —— **路径 B MUST 一并覆盖**：父侧运算消费子**非端口端点** ⇒ 读**合成端口名**

> 父层运算消费子组件的**非端口端点**（`ch_reg` / bundle 字段 / op 节点）时，
> 父侧表达式 MUST 读**该端点的父侧落点网名**（= 决策 ① 的命名规则），
> **MUST NOT** 读**仅在子 module 内声明**的名字（判据 = 该标识符在**父 module 作用域内
> 不可解析**），也 **MUST NOT** 直接读子 module 的**端口名**（父作用域同样不可见）。
>
> ⚠️ **措辞订正（v1.1 · Q6）**：旧措辞「读子 module 的**内部信号名**」与决策 ① 的命名规则
> （网名 = **驱动端点的 ctx 全局名**）**自相矛盾** —— 两者是**同一串** ⇒ ⇒ 逐字执行会把
> **正确实现**判成违规 ⇒ ⇒ 判据 MUST 用「**仅在**子 module 内声明」（= 父作用域可解析）。
>
> ⓘ **链条**（消除跨文档查找）：非端口端点 ⇒ 沿 ADR-060 §2.1「子 → 父」行合成**子侧 output 隐式端口**
> ⇒ 该端口名 = `__x_<n>`（**ADR-060 §2.2 v1.8 命名订正** · `n` = 该 module 内出现序
> ⇒ ⇒ **不是**端点的全局名）⇒ 端点的 **ctx 全局名**出现在**两处**：
> ① **子 module 内** `assign __x_<n> = <端点全局名>` 的 **RHS**；
> ② **父侧落点网名**（决策 ① 的命名规则）。
> ⇒ ⇒ ⚠️ **端口名 ≠ 网名**（`__x_<n>` vs `<端点全局名>`）—— **MUST NOT** 把合成端口命名为端点全局名
> （那会违反 ADR-060 §2.2 的确定性命名契约）。

⇒ ⇒ 理由：R2（事实 ⑥）要求所有穿透路径先查重定向表 ⇒ ⇒ 现路径**未查** ⇒ ⇒ **契约违反**（事实 ⑧）。
⇒ ⇒ ⚠️ **本决策与决策 ① 同批落地**（**交付层**）：只修 ① 而不修 ② ⇒ ⇒ 坏产物**仍在**
⇒ ⇒ ⇒ 二者 MUST 在**同一 change 内**完成 ⇒ ⇒ 且 MUST 在**同一归档**前落地。
⇒ ⇒ ⚠️ **实施层 MAY 拆两条通路**（**v1.1 · Q2 修订**）：实施期实测发现「决策 ① 的实现面覆盖两条
路径」这句话**不成立** —— 分析层把跨 module 边分成两桶（`pending_implicit_edges` = 子侧端点
**不是**端口 ⇒ 决策 ② 的形态；`analysis.edges` = 子侧端点**就绪** ⇒ 决策 ① 的形态）⇒ ⇒ 两者的
**合成代码通路不同** ⇒ ⇒ 故拆批**不产生**「坏产物窗口」⇒ ⇒ **顺序 MUST 为 α（决策 ② · 路径 B）
→ β（决策 ① · 族 ①/③）**（反序 ⇒ 路径 B 的格从 `Broken` 变 `Ok` 而产物仍坏 ⇒ 矩阵说谎）。

### 2.3 决策 ③ —— **造网要求收窄**（修订 ADR-062 §5 最后一条 + spec `:241-246`）

> 「父 module MUST 为子 `ch_out` 声明连接网」**仅在「父侧消费点不是父 `output` 端口」时**成立；
> 消费点**就是**父 `output` 端口时（直通），MUST NOT 强制造网 —— 允许子 output 直接接父 output 端口
> （Verilog 的隐式连续赋值 ⇒ **合法**，且逐拍等价实测全等 ⇒ 事实 ⑦）。

⇒ ⇒ ⇒ **修订** ADR-062 §5 最后一条与 spec `:241-246` 的 Scenario 措辞（**取代流程**，见元数据）。
⇒ ⇒ 理由：造网的**必要性**来自「Verilog 不允许把实例输出放进**表达式**」（ADR-062 `:78` 的理由句）
⇒ ⇒ 该理由**只在消费点含表达式时 bite** ⇒ ⇒ 对「直接接端口」形态**无约束力**。

### 2.4 决策 ④ —— **诊断 MUST 可行动**（删已过时的归因）

> 被拒形态的诊断 MUST ① 点名**真正的父侧消费节点**（不是派生节点）· ② 给出**可执行的改法**
> · ③ **MUST NOT** 复述「隐式端口合成不支持 / 发射器无法合成」这类归因（该能力 **2026-11-05 已全部落地**
> ⇒ ⇒ 该归因**现在就是假的**，事实 ③）。

⇒ ⇒ 归因被读成「能力不存在」⇒ ⇒ 用户误判 ⇒ ⇒ 这是**无条件义务**（无论决策 ① 的实现细节如何）。

### 2.5 决策 ⑤ —— **单连接不变式**

> 同一子 `ch_out` 端口在**实例语句**中 MUST **至多连接一次**；
> 父侧若需多处消费该输出，MUST 全部**扇出同一根父侧网**。

⇒ ⇒ 理由：Verilog 报 `Duplicate pin connection` ⇒ ⇒ 而**同一输出既直通父 output 又参与运算**
（形如 ①×④ 重叠）⇒ ⇒ 会产生两次连接 ⇒ ⇒ 故 MUST 扇出同一网
⇒ ⇒ 由决策 ① 的**网扇出**满足 ⇒ ⇒ **可判定**（§5 V7 含该重叠形态）。

### 2.6 决策 ⑥ —— **范围边界**（本 ADR **不**授权的部分）

| 边界 | 处置 |
|---|---|
| **跨多层**（孙组件 output 进祖父表达式） | **不在授权范围** ⇒ ⇒ 沿既有向上冒泡 / 拒绝路径 ⇒ ⇒ **属另立裁定** |
| **跨模块 `ch_mem`** | 仍按 ADR-060 `:70` 矩阵第五行**响亮拒绝** ⇒ ⇒ 本 ADR MUST NOT 顺带放宽 |
| **粒度** | 仅成层下触发（`ForceLayer` 或类级 `CH_HIERARCHY_LAYER`）⇒ ⇒ 默认粒度下形态**不出现**（事实 ⑬） |
| **父 = 根 module** | 网**在根内部** ⇒ ⇒ 根的端口表**不受影响**（ADR-062 的「根 MUST 单列」不变） |
| **宽度不一致** | 沿用 ADR-060 v1.10 的 W1（响亮拒绝 + 点名两个宽度值）⇒ ⇒ 本 ADR 不新增宽度语义 |

### 2.7 决策 ⑦ —— **`ch_mem` 端口实参跨层** **不**属本 ADR 的消费点范围（v1.1 · Q4 / Q5）

> 父层 `ch_mem` 的读/写端口，其 `addr` / `en` / `wdata` **实参**取自成层子组件的
> `ch_out` 时 ⇒ ⇒ 该形态 **MUST NOT** 按本 ADR 的「父侧落点网」处理；
> ⇒ ⇒ 分析层 `:543` 的**跨 module `ch_mem` 闸门** MUST **维持**响亮拒绝
> （`CHFATAL_EXCEPTION("cross-module ch_mem access …")`）。

⇒ ⇒ **理由**（**运行期实测** 2026-11-08 · 最小复现 = 父持 `ch_mem` + 成层子 `ch_out` 驱动地址）：
`is_mem_node()` **含** mem 读/写**端口**类型（`hierarchy_analysis.cpp:43-47`）且 `addr`/`en`/`wdata`
是端口的**直接 `src`**（`include/ast/mem_port_impl.h:39-49,141`）⇒ ⇒ 「子 `ch_out` → mem 端口」是一条
跨 module 边 ⇒ ⇒ 在**父子关系判定之前**被 `:542-553` 的闸门**响亮拒绝**⇒ ⇒
`print_mem_read_port` 的 early-return（`codegen_verilog.cpp:1266-1270`）**不可达**
⇒ ⇒ 现状 = **响亮拒绝 + 归因错误**（诊断让用户「把 mem 与使用者放同层」，而 mem **本来**就在同层）
⇒ ⇒ **不是**「静默不发射」（⇒ ⇒ 台账行 20 的原描述据此订正）。

⇒ ⇒ **选项对比**：

| 选项 | 结论 | 理由 |
|---|---|---|
| **A. 不纳入本 ADR** | ✅ **选中** | ① 「mem 与使用者同层」这条**已成立**（mem 就在父层）⇒ ⇒ 该形态**不是**「跨模块访问存储体」⇒ ⇒ 归类问题属**分析层闸门的粒度**问题，不是「父侧落点」问题；② 纳入本 ADR 会把「mem 端口实参」与「子 `ch_out` 消费」两类**语义不同**的形态混进同一张网 ⇒ ⇒ 决策 ① 的落点网规则**不适用**于 mem 端口（mem 端口不是一根信号） |
| **B. 纳入并支持** | ❌ 未选 | 需放行 `:543` 的粒度拆分 + 给 mem 端口单独一套落点语义 ⇒ ⇒ **独立的架构问题**，且与决策 ⑥「跨模块 `ch_mem` 仍拒」的边界句相邻 ⇒ ⇒ MUST 另立裁定 |
| **C. 纳入但只改诊断文案** | ❌ 未选 | 该形态**已经**是 fail-close ⇒ ⇒ C ≈ B + 一次文案修正 ⇒ ⇒ 无独立价值（文案修正是 B 的子集） |

⇒ ⇒ **处置**：台账 **行 20** 改记「**已裁决（不纳入本 ADR）**」⇒ ⇒ **归下游独立立项**
（分析层 `:543` 的粒度拆分 + 归因订正 + 可选的正确支持）⇒ ⇒ 本 ADR **MUST NOT** 顺带放宽
决策 ⑥ 的「跨模块 `ch_mem` 仍拒」。

## 3. 选项对比（**逐条含理由**）

| 选项 | 结论 | 理由 |
|---|---|---|
| **A. 保持拒绝 + 契约修订** | ❌ 未选 | ① 仓内公共库**自己**在用该形态（7 处，事实 ⑫）⇒ ⇒ 「不支持」= 库自己的写法不被自己的特性支持；② 契约层**早已规定**该形态的产物规范（事实 ⑨）⇒ ⇒ 拒绝使该规范**永不可达** ⇒ ⇒ 且矩阵外形态由「拒绝」覆盖只是**缺省**（事实 ⑪）⇒ ⇒ 补格为「拒绝」= 把缺省升格为 affirmative 裁决 ⇒ ⇒ 但那是**在契约层拒绝一个已被规范过的形态** ⇒ ⇒ 代价 = 用户侧改写 7 处（含公共库 5 处）+ 契约修订债 |
| **B. 支持（补矩阵格）** | ✅ **选中** | ① 唯一同时满足「契约可用 + 用户零改写」的选项；② 产物形态**已有先例**（族 ④ 的兄弟边路径，事实 ④）⇒ ⇒ 不是新机制 ⇒ ⇒ 实现面 = 复用既有「网登记 + `.port(net)` + 声明 + 撞名检查」+ 落在 R1/R2 表上的**操作数重定向**（事实 ⑤⑥）；③ 与族 ①/③ 的**既有拒绝**方向一致（两者都因「父侧带运算」而起 ⇒ ⇒ 修 ② 后「父侧带运算」整体变成**合法且正确**） |
| **B′. 路径 B 改为 fail-close**（子**非端口**端点 ⇒ `ok 1→0`） | ❌ 未选 | ① 严格更小的修复（仓内零实例）⇒ ⇒ **但**与决策 ① 的「父侧带运算」原则**不自洽**：同一维度上「子侧端点是端口」支持、「非端口端点」拒绝 ⇒ ⇒ 矩阵同轴两格结论互斥；② 42 格矩阵已把 `Broken→Ok` 预登记为预期可见变更；⚠️ 本选项**已评估并显式驳回**（非遗漏） |
| **C. 分层（默认拒绝 + 显式 opt-in）** | ❌ 未选 | ① **不解 motivating case**：默认档下库内 7 处**仍失败**⇒ ⇒ 库不能要求用户 opt-in；② 契约层已有一个策略维度 `PortPolicy`（ADR-060 §2.4.1）⇒ ⇒ 再加一档 = **零行为字段前科** + 语义定义债（而 `port_policy` 今天的唯一读取点只在 fail-closed 分支 ⇒ ⇒ 该维度本身也**尚未分化** ⇒ ⇒ ⇒ 在其分化前再加一档 = 在**未分化的维度**上叠加语义）；③ **即便**实现为 per-component opt-in 而非 `PortPolicy` 档，**也是同一性质的新语义维度** ⇒ ⇒ 结论不变 |

## 4. 后果 / 代价

### 正面

- 父层「读子状态 + 运算」这一**最常见**的组合逻辑在层次化输出下**可用** ⇒ ⇒ **该形态**用户零改写
  （⚠️ 更窄：全 riscv-mini SoC 的成层发射仍被 ADR-060 `:70` 的跨模块 `ch_mem` 先拒 ⇒ ⇒ 本 ADR **不**收口那一条）；
- 「父侧带运算」从「两种坏结局」（被拒 / 坏产物）变成**一种正确结局** ⇒ ⇒ 语义自洽；
- 契约闭环：矩阵不再有缺格 ⇒ ⇒ ADR-062 §2.6 的落点表与 spec `:241-246` 的 Scenario **变得可满足**；
- 判别力底座已就位（42 格矩阵）⇒ ⇒ 决策 ①/② 的验收**直接复用**它
  ⇒ ⇒ ⚠️ **第四态 `Broken` 已随本 change 移除** ⇒ ⇒ 由 **R9**（lint 集合）替代。

### 负面

- 发射器改动**触及产品代码**（`src/hierarchy_verilog.cpp` 的父侧检查 + 重定向表）⇒ ⇒ 需全量重建 + 全量回归；
- ADR-062 §5 最后一条与 spec `:241-246` **必须同步修订**（取代流程）⇒ ⇒ capability 变更走 change 流程；
- 决策 ① 与决策 ② **共用一张重定向表** ⇒ ⇒ 实现面比「只修族 ①/③」**更大**（一条路径漏改 ⇒ 坏产物仍在）。

### 风险

| 风险 | 缓解 |
|---|---|
| **漏改一条操作数/穿透解析路径** ⇒ ⇒ **lint 响亮失败**（父作用域未声明 ⇒ Verilator `%Error`）**或值错** ⇒ ⇒ ⚠️ **不是**「零告警」（父引用子内部名会被 R1 lint 门抓到） | §5 V8（操作数名解析守卫 + R2 四路径回归，两**面**各逐条变异 MUST 转红）· V4 逐拍等价抓「值错」 |
| **宽口 / 宽度不一致** ⇒ ⇒ 隐式扩展或截断（产物已关 `WIDTHEXPAND`/`WIDTHTRUNC`） | 沿用 W1（响亮拒绝 + 点名两个宽度值）⇒ V6 |
| **同端口两次连接** ⇒ ⇒ Verilog `Duplicate pin connection` | 决策 ⑤（单连接不变式）⇒ V7 |
| **默认粒度下形态不出现** ⇒ ⇒ 用例「恒绿」⇒ 零判别力 | V10（默认粒度负向对照）已在矩阵用例中 |
| **决策 ① 落地后矩阵的 `row2_expr × ch_out` 格从 `Reject` 变 `Ok`** ⇒ ⇒ 矩阵转红 | 预期**可见变更** ⇒ ⇒ 届时 MUST 同步更新该格与三态计数（决策 ① 的验收项） |
