## 1. 背景与问题

### 1.1 诉求来源

用户裁决（2026-11-21）：把 `examples/spinalhdl-ported/` 的 8 个已登记产品面 target 迁到
`examples/stream` / `examples/axi4` 的形态（**三角色分离 + 具名端口 + `.verif` 单一真相源 +
生成式 TB**）⇒ ⇒ 其中 6 个 target 的手写 TB 含**聚合类 metamorphic 判据** ⇒ ⇒ 用户在
「判据面处置」上明确选择「**先扩展 `.verif` 原语集**」⇒ ⇒ 本 ADR 裁**那一半**。

### 1.3 问题

「在不动 ADR-074 D1/D2 的核心不变量的前提下，`.verif` 能不能表达这 3 条判据？若能，加哪几条原语？

## 2. 决策

### 2.1 **D1** = 原语集增补 **4 条**（**每条都有实际消费者**）

`RECORD <port>` · `EXPECT_SEQ_SELF <port> <n> <lag>` · `EXPECT_SEQ_STEP <portV> <portE> <n>` ·
`EXPECT_SEQ_COUNT <port> <value> <n> <count>`。

⚠️ **不引入表达式**：全部参数（`n` / `lag` / `value` / `count`）在**扫描期**求值成字面量
⇒ ⇒ ADR-074 D2 的「生成期求值 ⇒ IR 里没有表达式 ⇒ 两后端不需要各自解释表达式」**逐字保持**。
⚠️ **不加无消费者的原语**（Zero-Debt）⇒ ⇒ **不含** `EXPECT_SEQ_EQ` ⇒ ⇒ 其否决的举证义务
由迁移 change 以「现有判据逐条映射表」承担（映射中出现 port-vs-port 历史恒等型消费者 ⇒ **STOP**）。

### 2.2 **D2** = 历史的语义（**TB 侧状态**，非 DUT 状态）

按**端口标识符字符串**分桶 · `RECORD` 追加**当前采样点**（沿后结算后 · 与 `EXPECT` 同窗）的值 ·
**跨 scenario 累积不清空**（与 DUT 状态持续性同构）· 深度上限 **1024** · 值按 **64 位无符号**存取
⇒ ⇒ 差值按 **mod 2^64** 回绕。

### 2.3 **D3** = 静态计数器**一份** · **跨 scenario 不清空** · 按**展开后**程序顺序累计 · key = 标识符字符串

⚠️ **这是 D2 的「运行期不可能超限 / 不可能不足」这一承诺的成立前提** ⇒ ⇒
**运行期历史长度恒等于静态计数** ⇒ ⇒ 「深度超限」「历史不足」**都不可达**。
⚠️ **实施期反模式**：把计数器声明在 per-scenario 循环内（深度计数重置 ⇒ 跨 scenario 越界；
充足性 per-scenario 判定 ⇒ 误拒合法用法）。

### 2.4 **D4** = 静态良构性在**扫描期**判定 ⇒ ⇒ **运行期无分叉**

参数个数 · 取值域（`n ≥ 1` · `lag ≥ 1` · `count ≤ n`）· **32 位上溢** · 历史深度上限 ·
**历史充足性**（`EXPECT_SEQ_STEP` **两个端口各判**）· **端口 width > 64 ⇒ fail-closed**（两端同源于 manifest）。

### 2.5 **D5** = `EXPECT_SEQ_STEP` 的「同位」= **两端口历史「各自尾部的第 (n+1-i) 项」**

⚠️ ⇒ ⇒ **LV ≠ LE 时它不是「同拍关系」** ⇒ ⇒ **使用前提（规范义务）**：两端口 MUST 在
**同一采样点集合**上 `RECORD`（交错记录且次数相等）⇒ ⇒ 写法范式 = 每拍 `RECORD v` → `RECORD en`。
⚠️ **公式（实施期修正 · 差一错位）**：`(hV[LV-n+i] - hV[LV-n-1+i]) mod 2^64 == hE[LE-n-1+i]`
⇒ ⇒ **不是** `hV[LV-n+i+1]`（那会**越界**读 `hV[LV]`）⇒ ⇒ **不是** `hE[LE-n+i]`
（那是**晚一拍**的 E 值 ⇒ ⇒ 「造成这次跃迁的 E」应是**较早端**的那个）。
⚠️ ⇒ ⇒ 前置 = **两个端口各需 ≥ n+1** 条历史。

### 2.6 **D6** = 已知差异**登记而不修**：X 态（`!==` ⇒ FAIL vs 解释器无 X · `COUNT` 的 X 项不计数 ⇒ 计数偏少）· **复位尾缝**（场景首条 `RECORD` 继承 wait-level 已登记的 1 拍接缝 ⇒ ⇒ 夹具 MUST 沿用 `SET` + `TICK` 前缀范式）

### 2.7 **D7** = D8 举证义务**升级**为逐**对** `(check_id, PASS/FAIL)` 比对（严于 D8 原文的「集合相等」）

⇒ ⇒ **本升级 MUST 在本 ADR 明记** ⇒ ⇒ 免得日后被读成「D8 原文被悄悄替换」。

### 2.8 **D8** = 「一个物理端口只用一个标识符 `RECORD`」（否则两条独立历史）+ **sanitize MUST 单射**（撞名 ⇒ fail-closed，**扫描期**判定 ⇒ 两端同源）

### 2.9 **D9** = 既有原语的语义与**渲染文本 MUST NOT 改** ⇒ ⇒ 既有 checked-in `.sv` 产物**逐字节不变**

## 3. 选项对比表

| # | 选项 | 结论 | 理由 |
|---|---|---|---|
| **①** | **扩 4 条原语 + 扫描期静态良构性**（本 ADR） | ✅ **采用** | 判据面零损失；新增分叉面被 D3/D4 在**扫描期**消灭；每条原语都有实际消费者；不触动 ADR-074 的核心不变量 |
| ② | **把 3 条 metamorphic 降级为绝对判据** | ❌ 拒 | 判据面实质收窄 ⇒ 与「判据零损失」的交付口径直接冲突（事实 ④）⇒ ⇒ 降级是**用户已否决**的选项 |
| ③ | **加一条「万能原语」（表达式化的序列判据）** | ❌ 拒 | 等于在 IR 里**重开表达式** ⇒ ⇒ 复活 D8 要消灭的「两端各自解释」漂移面；且违反 D2 的「生成期求值」不变量 ⇒ ⇒ ADR-074 §7.4 已否决同族方向 |
| ④ | **在运行期做充足性检查**（两端各自拦） | ❌ 拒 | 回到「两个执行后端各自判定 ⇒ 可分叉」的旧病；且反馈环后移（生成物已生成才发现）⇒ ⇒ 与 D4 的中心主张相反 |
| ⑤ | **加 `EXPECT_SEQ_EQ`（两端口历史逐项恒等）** | ❌ 拒 | **无消费者**（事实 ③）⇒ ⇒ Zero-Debt 禁死代码；⇒ ⇒ 否决的举证义务由迁移 change 以逐条映射表承担（出现 port-vs-port 型消费者 ⇒ STOP ⇒ 走本 ADR 的增补条款） |
| ⑥ | **宽端口（>64 位）登记差异而不拒绝** | ❌ 拒 | 解释器只拿得到**低 64 位** ⇒ ⇒ 两端「大概都截断」⇒ ⇒ 「大概同构」正是 D8 要消灭的 ⇒ ⇒ 不如**直接拒**（事实 ⑧ ⇒ 两端同源可判） |
| ⑦ | **把决策追加进 ADR-074 §7** | ❌ 拒 | ADR-074 §7 头部**自禁**继续追加（事实 ⑦）⇒ ⇒ MUST 拆**独立新 ADR** |
| ⑧ | **改 `.verif` 的表达式文法**（变量 / 条件 / 外部引用） | ❌ 拒 | ADR-074 §7.4 已否决（不动「生成期求值」不变量）⇒ ⇒ 若实施期发现不动该不变量就表达不了 ⇒ ⇒ **STOP** ⇒ 另立 ADR |

## 4. 后果 / 代价

### 4.1 正面

| # | 后果 |
|---|---|
| P1 | 3 条 metamorphic 判据**可忠实表达** ⇒ ⇒ 8 个 target 的迁移**不降级** |
| P2 | 「历史不足 / 深度超限 / 宽端口截断」三类**执行后端分叉**在**扫描期**被消灭（D3 + D4）⇒ ⇒ 运行期只剩「值不同」这一类真分叉 |
| P3 | 不触动 ADR-074 的核心不变量（IR 无表达式）⇒ ⇒ 既有产物**逐字节不变**（D9）⇒ ⇒ 无回归面 |
| P4 | 每条新原语都有**实际消费者** ⇒ ⇒ 无死代码 |

### 4.2 负面 / 代价

| # | 代价 | 量级 |
|---|---|---|
| N1 | 原语集从 9 条 → 13 条 ⇒ ⇒ `.verif` 的作者负担上升 | 中（由 D4 的 fail-closed 静态检查兜底 ⇒ ⇒ 错在**扫描期**而非**运行期**） |
| N2 | 解释器侧新增按端口分桶的历史缓冲 ⇒ ⇒ 运行期内存随端口数 × 1024 × 8B 增长 | 极小（8KB/端口） |
| N3 | 渲染侧每个被 `RECORD` 的端口需要 1024 × 64bit 数组（64KB） | 可忽略（TB 一次性分配） |
| N4 | `EXPECT_SEQ_STEP` 的「同位」语义**易被误读** ⇒ ⇒ 靠 D5 的规范前提 + 文档警告兜住 | 中（作者侧风险，非实现侧） |
| N5 | 「记录与比较 MUST 分到不同拍次」是**限制**（`REPEAT` 自举形态被过拒）⇒ ⇒ 方向安全但需登记 | 小 |

### 4.3 风险

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 新原语自身有缺陷 ⇒ ⇒ 两端**同构地错**（同源失明） | ① D4 的扫描期静态检查；② D7 的逐对运行期比对；③ 变异自证（点名清单 + 无效变异如实登记） |
| R2 | 静态计数器作用域写错 ⇒ ⇒ 「运行期不可能超限」的承诺失效 | D3 明文 + 跨 scenario 超限构例（AC14）⇒ ⇒ 该承诺**有判别力** |
| R3 | 迁移 change 的作者把聚合判据误降级 | 迁移 change MUST 附「现有判据逐条映射表」⇒ ⇒ 映射不到 ⇒ STOP |
| R4 | 公开面变更（`include/rtl_emit/verif.h` 加 4 kind + 5 字段）漏登记 | 公开面登记义务写进 change 的 C4（不得悬空） |
