## 1. 意图（为什么有这份文档）

台账行 16 登记的是**现象**（「父层运算消费子 `ch_out` 被拒，且诊断不可行动」）。但**现象不等于问题**：登记那一刻尚未确定「被拒」是**缺陷**还是**有意约束** ⇒ ⇒ 若不先裁定，后续任何修复都可能是在**实现一个从未被要求的语义**（违反「契约是单一权威」）。
⇒ ⇒ 本文档的产出 = **一个可被单点回答的裁定问题** + **候选的代价对比** + **可行性的先验判据**。

## 2. 背景与问题

### 2.1 缺口一句话

父层**消费**成层子组件的 `ch_out` 时：*消费点 = 父 output 端口*（直通）⇒ 能发射且**行为已实测正确**，但**产物形态与 spec 字面不符**（未造网）；*消费点 = 父内运算 / 父内寄存器 / 子 input 的表达式*（含子 output）⇒ **被发射器 fail-closed 拒绝**，诊断不可行动 ⇒ ⇒ 该形态族在契约层**没有可用形态**。

### 2.2 形态分类（2026-11-08 实测 · `ForceLayer` · 仓外探针 `/tmp/opencode/probe_{shapes2,row3,row3b}.cpp`）

| 族 | 方向 | 消费点 / 父表达式 | 典型 C++ 写法 | 实测 | 仓内站点 |
|---|---|---|---|---|---|
| **①** | **子 → 父** | 父内 reg / 父内 op 节点（⚠️ **不含**父 output 直通） | `exmem_valid <<= select(exmem_en, id_stage.io().valid_out, …)` | ❌ 拒 | `include/cpu/pipeline/rv32i_pipeline.h:398`、`:401`、`:402`（**3 处**） |
| **②** | **父 → 子** | 子 `ch_in` · 父表达式**只含父内信号** | `hazard.io().mem_reg_write <<= exmem_is_alu \| exmem_is_load \| exmem_is_jump;` | ✅ `ok=1` | `rv32i_pipeline.h:505`、`:508` 等 |
| **③** | **父 → 子** | 子 `ch_in` · 父表达式含子 `ch_out` **且含运算** | `itcm.io().addr <<= bits<kTcmAddrWidth+1,2>(pipeline.io().instr_addr);` | ❌ 拒 | `rv32i_pipeline.h:506`、`:524` · `examples/riscv-mini/src/rv32i_pipeline_top.h:112`、`:121`（**4 处**） |
| **④** | **父 → 子（兄弟边）** | 子 `ch_in` · 父表达式 = **单个**子 `ch_out`（**无运算**） | `hazard.io().ex_is_load <<= id_stage.io().is_load;` | ✅ `ok=1` | `rv32i_pipeline.h:520` 等 |

⚠️ **族 ① 的 ❌ 仅适用于「父内 reg / 父内 op」消费点** ⇒ ⇒ 「消费点 = 父 output 端口」（S1 直通）⇒ ✅ `ok=1`（**基线**，§2.4）⇒ ⇒ **族 ① 内部是二分的** ⇒ ⇒ Q1 的选项边界以「消费点**是不是**父 output 端口」为界。

⚠️ **族 ③ 与族 ④ 的分界 = 「父表达式里除子 `ch_out` 外还有没有运算」** ⇒ ⇒ **族 ④ 是兄弟边**（矩阵内 · T3-④ 已落地 ⇒ **不在本裁定范围**）⇒ ⇒ **族 ③ 才是缺口**（族 ③ 的父侧端点是父内 op 节点 ⇒ 落进族 ① 的父侧检查 ⇒ 被拒 ⇒ ⇒ **族 ① 与族 ③ 同根因**）。

⚠️ **族 ④ 的产物形态 = 候选 B 的目标形态，且已跑通**（★ 本裁定**最强的可行性证据**）：父 module 内声明一根 `logic` 网 ⇒ 子 output 用 `.port(net)` 连接 ⇒ 父侧表达式读该网（`logic [7:0] top_l1_unnamed_output;` · `.top_l1_unnamed_output(top_l1_unnamed_output)` · `.top_l2_unnamed_input(top_l1_unnamed_output)`）⇒ ⇒ **C1/C2 的字面在此形态上已被遵守**。
⚠️ **族 ③ 曾被怀疑会产出「引用未声明标识符」的坏产物** ⇒ ⇒ **实测证伪**：族 ③ **被拒**（`ok=0`）⇒ ⇒ 坏产物**不会**产生；但 ⇒ ⇒ **行 2 遮蔽**（§8）⇒ ⇒ 真实 riscv-mini 顶层**先**被跨模块 `ch_mem` 拒绝 ⇒ ⇒ 这两条检查**当前从未被真设计触发过** ⇒ ⇒ 其正确性**缺乏实证**（不是「潜伏坏产物」，是「从未跑过」）。

### 2.3 诊断的三个具体缺陷

| 缺陷 | 证据 | 后果 |
|---|---|---|
| **不可行动** | 诊断原文：`child module 'top.l1' drives 'top_bits' in module 'top', which is not an output port of that module` ⇒ ⇒ 不点名「父侧带运算」· 不给改法 | 用户无法自行定位到「父侧消费点不是父 output 端口」 |
| **归因过时** | 错误串前缀：`… require implicit-port synthesis (ADR-060 §2.1), which this emitter cannot synthesize:` ⇒ ⇒ 隐式端口合成 **B2b 五批已于 2026-11-05 全部落地** ⇒ ⇒ 该归因**现在就是假的** | 用户误判为「能力不存在」 |
| **点名不精确** | 族 ① 的 `select` 消费点报**两条**：`top_gt_gt`（比较结果）+ `top_mux_select`（mux 选择信号）⇒ ⇒ **真正消费子输出的那个节点未被点名** | 用户要自己反推哪条是根因 |

⇒ ⇒ **无论 Q1 怎么裁**，这三条诊断义务都成立（§6 Q3）⇒ ⇒ 措辞的**最终形态**依赖 Q1（若裁 B ⇒ 该检查整体消失）。

### 2.4 ★ 「S1 未造网」的逐拍等价实测（v0.2 新增 · 决定 Q2 的性质）

| 项 | 实测 |
|---|---|
| 形态 | S1 直通：`io().out <<= l1.io().val;`（父 output ← 子 output · **未造网**） |
| 产物 | `.top_l1_unnamed_output(top_unnamed_output)` ⇒ 子 output **直接**接父 output 端口（Verilog 的**隐式连续赋值**） |
| lint | `verilator --lint-only` ⇒ **exit 0** |
| **逐拍等价** | `ch::hier_eq::compare` ⇒ **`equal=1` · `mismatch_count=0`** · 激励 {`0x00`,`0x5A`,`0xA5`,`0xFF`} ⇒ 扁平侧逐拍 = {0, 90, 165, 255} ⇒ ⇒ **与手推预期逐拍吻合**（直通 ⇒ `out == din`） |

⇒ ⇒ **「未造网」不产生行为缺陷** ⇒ ⇒ 它是**契约措辞过宽**（spec :241-246 要求**一律**造网）
⇒ ⇒ **契约层应把造网要求收窄**到「消费点**不是**父 output 端口」的族 ①/③（§5.3）。

## 4. 位置判定：**ADR-060 §2.1 矩阵的缺格**

矩阵「**子 → 父**」行（ADR-060 `:68`）的前提是「子侧端点**不是**子端口」⇒ 合成子侧 output 隐式端口 ⇒ 「父侧 `assign` 取实例输出」。⚠️ **当子侧端点就是子 `ch_out` 时**：矩阵说**不合成**任何端口（与 S1 实测一致）⇒ ⇒ 「父侧 `assign` 取实例输出」成为**唯一**可用形态 ⇒ ⇒ **父侧一旦含运算，该形态即失效**（Verilog 不允许把实例输出放进表达式 ⇒ 必须有一根父侧网）⇒ ⇒ **矩阵未覆盖这一格**。

⚠️ **它不是矩阵外的第七 / 第八格**（两者**方向相反**）：

| 格 | 方向 | 内容 |
|---|---|---|
| 第七格（ADR-060 `:114-136`） | **父 → 子** | 父层 `<<=` 改写**子模块体内**运算节点的操作数 ⇒ 拒绝（破坏模块边界） |
| 第八格（ADR-060 `:138-148`） | **父 → 子** | 父层驱动**子模块的 `ch_out`** ⇒ 拒绝（父驱动子输出） |
| **本缺口** | **子 → 父**（族 ①）· **父 → 子但表达式含子 output**（族 ③） | 父层**消费**子 `ch_out` 且父侧带运算 ⇒ **缺格** |

⇒ ⇒ **裁定动作 = 给 §2.1 矩阵补一格**（补「拒绝」还是「支持」两可）⇒ ⇒ 这是**架构决策**，不是实现细节。
⇒ ⇒ ⚠️ 族 ②（父表达式纯父内）**已在矩阵内**（「父 → 子 · 子侧端点是子端口 · 驱动节点在父模块」行）⇒ ⇒ **不在本裁定范围**；
⇒ ⇒ ⚠️ 族 ④（兄弟边）**也在矩阵内**（T3-④ 已落地）⇒ ⇒ **不在本裁定范围**，但 ⇒ ⇒ **它的产物形态正是 B 的目标形态**（§2.2）⇒ ⇒ B 有先例。

## 5. 契约层**已经**回答 / **需要收窄**的部分

### 5.1 产物形态的规范已存在

C2 已把**父侧落点**定死：成层非根 module 的 `ch_out` ⇒ 父侧一根 `logic` 网 + `.port(net)`。
⇒ ⇒ 「产物长什么样」**不是**待裁定项。

### 5.2 E5 的正确答法（v0.2 修订 ⇒ 删去原「条款永不可达」论证）

原论证「若裁 A ⇒ C1/C2 永不可达」**不成立**（被文档自身的 Q2 处方反例击穿：裁 A + 修 S1 ⇒ C1 字面即被满足）。
⇒ ⇒ 换成三条**成立**的承重理由：

1. **矩阵外 ⇒ 缺省拒绝，不是对该形态的 affirmative 裁决** ⇒ ⇒ C6 明文「矩阵外形态由『拒绝』覆盖」
   ⇒ ⇒ 现行拒绝**只说明矩阵没写**，**不说明该形态该被拒绝** ⇒ ⇒ **必须补格**才是契约闭环（这正是本裁定的契约依据）。
2. **立法理由只在「表达式消费」时 bite** ⇒ ⇒ ADR-062 `:78` 的理由句是「Verilog 不允许把实例输出直接接**表达式**」
   ⇒ ⇒ 该理由**预设了表达式消费形态的存在** ⇒ ⇒ 起草者**认为**这种形态该被支持 ⇒ ⇒ 拒绝与**起草意图**相悖。
3. **惯用法证据**：族 ①/③ 在**公共库内**共 7 处（`include/cpu/pipeline/rv32i_pipeline.h` 5 处 + examples 2 处）
   ⇒ ⇒ 该形态是**库自身在用**的写法 ⇒ ⇒ 「不支持」= 库自己的 API 用不了自己的特性。

### 5.3 ★ spec :241-246 的造网要求**过宽**（v0.2 实测结论 ⇒ Q2 升为无条件义务）

实测：族 ①/③ 族之外的「S1 直通」**未造网**（子 output 直接接父 output 端口）⇒ ⇒ `verilator --lint-only` **exit 0**
⇒ ⇒ 且**逐拍等价实测全等**（§2.4）⇒ ⇒ 「未造网」**不产生行为缺陷**。

⇒ ⇒ 故 C1 的字面（「父 module 消费一个成层子组件的 `ch_out` ⇒ MUST 造网」）**比实现**与**实际需要**都宽：
真正需要造网的只有**消费点不是父 output 端口**的族 ①/③（因为 Verilog 不允许把实例输出放进表达式）。
⇒ ⇒ **无论 Q1 怎么裁，C1 都应被收窄** ⇒ ⇒ 收窄不是「选边」的附属品，而是**独立的契约修正义务**。
⚠️ **但收益不对称**：B 档下收窄**咬 7 个站点**（族 ①/③ 全部）；A 档下收窄后的 C1 **近乎 vacuous**
（非父 output 端口的消费点**全被拒** ⇒ ⇒ 无合法落点可援引）⇒ ⇒ ⇒ 故 **Q2 的独立权重在 A 档下显著低于 B 档**。

| 决策陈述 | 族 ①/③ = 矩阵外形态 ⇒ **始终拒绝**（C6）⇒ 补格写「拒绝」+ 诊断可行动化 + 用户侧改写为「子侧多导出一个 `ch_out`」 | 族 ①/③ = 合法形态 ⇒ 父侧合成一根网（复用 I3/I4）+ 把父侧运算的操作数重定向到该网（落在 I5 的 R1/R2 表上） | 新增策略维度（如 `AllowParentOp`）；默认沿 A，显式开启走 B |
| 契约冲突面 | 需**改**：C1 收窄（§5.3 · 无条件）+ C2 措辞对齐 + ADR-060 §2.1 补格（写「拒绝」） | 需**改**：C1 收窄（同左）+ ADR-060 §2.1 补格（写「支持」）+ 追加 capability Requirement（Q4 单连接） | 需**改**：C1 收窄 + §2.1 补格 + §2.4.1 枚举扩张 + 新策略语义定义 ⇒ ⇒ 改动面最大 |
| 实现面 | **小**（诊断文本 + 契约文字；无产品代码改动） | **中**：父侧网机制已有（I3/I4）⇒ 主要工作在「按 I5 的四条路径重定向父侧操作数」⇒ ⚠️ 漏一条路径 ⇒ **零告警静默错 RTL** | **大**（B 的全部 + 策略分发 + 枚举语义定义债） |
| 用户侧代价 | **大**：公共库内 **7 处**（`rv32i_pipeline.h` 5 处 + examples 2 处）需改写 ⇒ ⇒ 改的是**库自己的 API 用法** | **小**（现状写法即可用） | **中**（默认路径仍要改写；opt-in 才免） |
| 回滚路径 | 易（删诊断改动 + 回滚契约文字） | 中（回滚 = 恢复拒绝 + 契约文字回滚；已发产物不受影响） | 难（策略维度一旦进枚举，回滚需改所有分发点） |
| 风险 / 驳回理由 | ① 用户无法在层次化下表达常见组合逻辑；② 库自己的写法不被自己的特性支持 | ① 重定向漏路径 ⇒ 静默错 RTL（I5 已给出四条路径清单可逐条钉）；② **跨多层边界**（见下） | ⛔ **不解 motivating case**：默认档下库内 7 处仍失败 ⇒ 库不能要求用户 opt-in；⚠️ 风险定性 = **策略字段在成功路径零读取前科**（I6）+ 与 `PortPolicy` 的**交互语义定义债**，而非「枚举组合爆炸」 |

⇒ ⇒ **倾向 B**（唯一同时满足「契约可用 + 用户零改写」的选项），但**B 的可行性 MUST 先经 E1 spike 证实**。

⚠️ **B 的「跨多层」默认立场**（★ 拍板 B 的**前置条件**，非实施期事项）：**Q1 只裁「直接子组件」单层**；
「孙组件 output 进入祖父表达式」**不**在本裁定的授权范围 ⇒ ⇒ 沿既有冒泡 / 拒绝路径处理 ⇒ ⇒ **属另立裁定**。
同理 **跨模块 `ch_mem`** 仍按 ADR-060 `:69` 的矩阵第四行**响亮拒绝** ⇒ ⇒ B MUST NOT 顺带放宽。

## 8. 关键可行性问题（E1–E5）与建议 spike

| # | 问题 | 承重理由 | 现状预判 |
|---|---|---|---|
| **E1** | 族 ①/③ 的父侧运算操作数能否重定向到「父侧合成网」？ | B 的全部成本在此 ⇒ ⇒ 答「否」⇒ B 退化为 A/C | **正面（已被既有路径证明）**：族 ④（兄弟边）的产物形态**就是** B 的目标形态（父侧网 + `.port(net)` + 父侧表达式读网）⇒ ⇒ 机制已在发射器里跑通 ⇒ ⇒ B = **把该机制用到族 ①/③**；⚠️ 仍 MUST 落在 I5 的 R1/R2 表 + **四条**路径守卫上（漏一条 ⇒ **零告警静默错 RTL**）；⚠️ 与第七格（跨作用域改**子**内 op 操作数）相比，B **不跨 module 作用域** ⇒ 面更窄 |
| **E2** | 产物是否与扁平等价（逐拍）？ | B 若产生行为差异 ⇒ ⇒ B 不可选 | 可预期等价（改写的是**命名**不是**语义**）⇒ ⇒ 仍 MUST 用既有 `ch::hier_eq` 实测（★ 期望值**手推** ⇒ 禁抄仿真输出） |
| **E3** | 用户侧零改写的可行性 | 决定 A 的代价有多痛 | 已实测：族 ①/③ 共 **7 处**在**公共库内** ⇒ ⇒ A 的代价 = 改公共库 API 使用形态 |
| **E4** | 宽度 / 驱动语义 | 跨层边两端宽度 MUST 一致（ADR-060 v1.10）⇒ 不一致 ⇒ 响亮拒绝 | 沿用既有 `width_check` 语义 ⇒ ⇒ 无新决策 ⇒ 只 MUST 在契约里写明（双向宽度 + 诊断点名两个宽度值） |
| **E5** | 现行拒绝是**实现选择**还是**契约要求**？ | 决定 A 是否需要改契约 | 见 §5.2 三条：**矩阵外缺省拒绝**（C6）· **起草意图预设表达式消费**（ADR-062 `:78` 理由句）· **库内惯用法**（7 处）⇒ ⇒ 倾向「实现选择」 |

⇒ ⇒ **建议 spike（判别力优先 · 仓内最小改动）**：① 发射器里实现「父侧运算操作数 → 父侧合成网」的重定向（**仅探针级**，不入产品）；② 用既有 `ch::hier_eq` 对族 ①/③ 做「层次化 ≡ 扁平」逐拍对比（**期望值手推**）；③ 记录产物 diff（应只有**命名**差异）；④ ⚠️ **逐条变异** I5 的四条重定向守卫 ⇒ ⇒ 每条 MUST 转红（对齐 ADR-060 §5 W2 的机械形态）。

## 10. 判别力边界（**不可**当作正确性证据的项）

- ⚠️ **两后端 parity 对本族缺陷结构性失明** ⇒ ⇒ 「interpreter 与 Verilator 一致」**不是**「支持正确」；
  ⇒ ⇒ 期望值 MUST **手推**（§2.4 的手推已吻合 ⇒ 该口径有效）。
- ⚠️ **「能发射」≠「产物正确」**：S1 即为反例（能发射 · 形态不符契约 —— 虽实测行为正确，但**契约面**仍不符）。
- ⚠️ **诊断文本断言 = 脆弱断言**（行 17 的过时刻固化即此类）⇒ ⇒ 新诊断 MUST 以「**形态/落点**」而非「能力不存在」措辞，
  且测试 SHOULD 断言**语义要点**而非整串。
- ⚠️ **形态矩阵探针目前在仓外** ⇒ ⇒ MUST 随对应 change 进仓，否则 CI 守不住。
- ⚠️ **探针自身的纪律**：同一端口 MUST 单一驱动（C++ 侧 last-wins ⇒ 产物侧变 `Duplicate pin connection` ⇒ Verilator 报 `%Error`）⇒ ⇒ 形态探针 MUST 逐形态**独立**构造。
- ⚠️ **范围外观察项（本次不裁定）**：族 ④（兄弟边）的连接（`.port(父侧网)`）在「同一子端口被驱动两次」时会产出
  `Duplicate pin connection` ⇒ ⇒ C++ 侧是 last-wins（静默）· 产物侧是 lint 错误 ⇒ ⇒ **族 ④ 现状已覆盖**
  ⇒ ⇒ 该现象**不属于**本裁定范围 ⇒ ⇒ **建议单独登记**（候选：台账行 18），**不在此顺手扩大 scope**。

## 11. Verification 判据草案（供未来 ADR 的「Verification 章」取用）

- [ ] **V1** 形态矩阵进仓：族 ①（父 output / 父内 reg / 父内 op）× 族 ②（父内表达式）× 族 ③（表达式含子 output **且含运算**）× 族 ④（表达式 = 单个子 output，兄弟边 · **回归基线**）各有独立用例，且**每端口单一驱动**；
- [ ] **V2** 若裁 B：族 ①/③ MUST `ok=1` 且产物含**父 module 作用域内**的 `logic` 网 + `.port(net)`（★ 作用域锚定 ⇒ 防「子串误配」判绿）+ **单连接断言**（每个子 output 端口至多出现一次）；

- [ ] **V4** 诊断可行动性：被拒形态的诊断 MUST 含「父侧消费点不是父 output 端口」+「可执行改法」；MUST NOT 含「隐式端口合成不支持」类**已过时**归因；MUST 点名**真正的消费节点**（不是派生节点）；
- [ ] **V5** 宽度不一致 MUST 响亮拒绝（沿用既有 `width_check`）+ 诊断 MUST 点名**两个**宽度值；
- [ ] **V6** 回归锚：「默认（全 inline）产物与扁平产物**逐字节一致**」MUST 仍然成立（对齐 ADR-058 §2.3）；
- [ ] **V7** 产物 MUST 过 **ADR-060 §2.5 lint 门**（抓未声明标识符 / `Duplicate pin connection` 一类）；
- [ ] **V8** 护栏可判别性：新增产物级护栏 MUST 有 `--self-test` 投毒（否则恒绿无意义）；
- [ ] **V9**（若裁 B）I5 的**四条**重定向路径 MUST 各有一条变异用例 ⇒ ⇒ 每条变异 MUST 转红。
