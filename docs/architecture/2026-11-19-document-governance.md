### D1 · 文档分级（**全域**）—— 治理的第一道分流

`docs/` 全域按「**可变性**」分四级，**每一篇文档 MUST 落在且只落一级**：

| 级别 | 判据 | 读者义务 | 治理义务 |
|---|---|---|---|
| **L1 活文档** | 是**导航入口**或**当前态权威** | **可直接作为实现依据** | 死链 MUST 归零；行号引用 MUST 准；示例 MUST 可编译 |
| **L2 历史快照** | 记录**当时**的判断 / 计划 / 评审 | **只作历史参考**，不得作实现依据 | **不改写正文**；过期用 dated addendum 追落；死链 / 行号漂移 **不追**（登记为接受项即可） |
| **L3 过程记录** | 计划 / 报告 / 迁移计划 | 同 L2 | 同 L2 |
| **L4 外部** | 第三方文档（`external/**`） | 同上游 | **不归本仓管** |

⚠️ **分级是引用判定的前置**：未分级的引用失效无法判定是缺陷还是史料（§2.2 的 357 处里有 330 处属此）。

#### D1′ · 分级来源（**两级** —— 目录前缀默认 + 混合目录逐文件登记）

⚠️ **分级 MUST 为派生式登记表**（`.rddf/checks/docs-link-scope.md`）：由护栏 `--render` 生成、**禁手改**（形态对齐 `.rddf/checks/guard-reachability.md`）⇒ ⇒ 分级不是「编辑者当时的心情」，而是**可审计的派生结果**。

| 来源 | 规则 |
|---|---|
| **① 目录前缀默认**（零维护） | **L1** = `docs/usage_guide/**` · `docs/developer_guide/**` · `docs/skills/**` · `docs/simulation/**`<br>**L2/L3** = `docs/adr/**` · `docs/archive/**` · `docs/plans/**` · `docs/reports/**` · `docs/freertos/**` · `.rddf/**` · `openspec/changes/archive/**` |
| **② 混合目录逐文件登记** | `docs/architecture/**`（**L1/L2 混居**：主题权威文档 = L1，`phases/**` 与 `2026-*-review*` = L2）· `docs/` 根的散落 `*.md` · **仓根**散落 `*.md` |

**仓根散落 `*.md` 的逐条裁决**（2026-11-19）：`improvement-suggestions.md` · `improvement-approved.md` = **L1**（是 `.rddf/improvements/` 的**活索引**，不是 legacy 镜像）· `README.md` · `READING-GUIDE.md` · `QUICK_REFERENCE.md` = **L1**（仓入口导航）· `PHASE1-REVISED-PLAN.md` · `perf_results.md` · `Compare.md` = **L3**（计划 / 结果 / 对比快照）· `docs/simulation/ARCHITECTURE.md` = **L1**（被根 `AGENTS.md` 引为「Memory read port timing」的**权威**）。


#### D1″ · 显式 **out-of-scope**（**不是隐含排除**）

| 范围 | v1 处置 | 理由 |
|---|---|---|
| **`AGENTS.md` 家族**（根 + `include/**` + `examples/**` + `tests/`） | **不扫**，登记为 out-of-scope | 实测根 `AGENTS.md` **0 处 markdown 链接** ⇒ C1 对其零成本；但其 `file:line` 引用密度**全仓最高**（每会话注入）⇒ 纳入 C2 需逐条重定位数百处 ⇒ **另立独立小项**，不塞进本方案 |
| `openspec/changes/**`（**活动态**） | 不扫 | 结构由 openspec CLI 自校验（`validate --strict`）⇒ 重复治理无收益 |
| `.rddf/checks/**` | 不扫 | 是**登记表**（非导航文档）⇒ 其中的路径引用按「登记项」口径判 |

### D2 · 引用有效性口径（行号 pin）

| 文档级别 | `file:line` 引用 | 理由 |
|---|---|---|
| L1 | MUST **准**（被引行内容与描述相符）；修时**逐条重定位 + 核实被引行内容** | L1 是实现依据 ⇒ 行号错 = 读者按行号找不到代码 |
| L2 / L3 | **不追**（行号是**历史锚点**） | 改成今天的行号 = **篡改历史语境**（ADR 尤其危险） |
| L1 内部 | 优先**按符号 / 内容锚定**（`ch::hier_eq` · `create_child`）而非 pin 行号 | 行号漂移是**结构性**脆弱点（实测：`usage_guide/05` 一次漂移 14 处） |

⚠️ **例外（人工裁决 · 护栏不执行）**：L2 中语义上充当**决策依据**的引用允许追落，但 MUST 满足三条：

1. **可判的操作判据**（不是「看着像」）：所在章节标题 ∈ {实现 · 代码位置 · 依据}，**或**引语文本含「见 / 位于 / 体现」类动词；
2. **追落位置 = 文末 Addendum 节**（追加 dated 注记：原引用 · 新引用 · 日期 · 「若上游被否则回滚」）⇒ ⇒ **正文一行不改**（⚠️ 与 `docs/architecture/README.md` §3.2 对**主题文档**的「对应条目行尾」要求**刻意不同** —— ADR 是决策正本，行内插入任何内容都侵蚀正本 ⇒ 故更严）；
3. **人工裁决、护栏不执行**（量低：ADR 的 71 处行号越界里，属「决策依据」的只是子集）。

✅ **正向模式（比追 ADR 更省事，优先用这条）**：**活文档（L1）负责刷新 pin，ADR 保留历史 pin** ⇒ ⇒ L1 文档引用 ADR 决策时 **MUST 重新锚定**（按符号 / 内容，而非照抄 ADR 的行号）⇒ ⇒ ADR 永远不需要因代码漂移而改。

### D3 · 死链处置

| 死链所在 | 处置 | 理由 |
|---|---|---|
| L1 导航 | **MUST 修** ⇒ 改指到**核实过的现存文件**；目标确实不存在 ⇒ **delink**（去链、**保留文本** + 标注「文件尚未创建」）⇒ ⇒ **不删行**（删行会丢掉「计划存在」这条信息）⇒ ⇒ **不得留可点的占位链接** | L1 是读者入口 ⇒ 死链 = 读者被挡住；而「规划中」是**信息**，不是噪声 |
| L2 / L3 | **不追**；在对应文档加一句 dated 注记「本文含历史链接」 | 改写历史 = 伪造 |
| L4 | 不动 | 不归本仓管 |

⚠️ **本机绝对路径**的处置**不按级别分** ⇒ ⇒ 见下方 **P1**（独立条款）—— 否则本表会出现「L2 不追」与「任何链接 MUST 修」的**字面冲突**。

#### D3′ · P1 · 本机路径禁令（**级别无关**）

任何**被跟踪文档** MUST NOT 含本机绝对路径（`/workspace/` · `/home/`）——⚠️ **豁免：`docs/archive/**`**（仓规「历史条目**逐字**保留」区 ⇒ 改它即破坏该约定 ⇒ ⇒ 判据 C3 MUST 排除该目录）。

| 级别 | 处置 | 理由 |
|---|---|---|
| L1 | **改为仓内相对路径** | 链接仍可达 ⇒ 修链即可 |
| L2 / L3 | **delink**（降级为**行内代码** + 文末 dated 注记）⇒ ⇒ **不得 relink 到不存在的目标** | `.sisyphus/plans/…` 这类目标**仓内根本不存在** ⇒ 改成相对路径仍是死链 ⇒ 正确修法是**去掉链接**（实测：`docs/architecture/2026-03-30-cpphdl-architecture-gap-analysis.md:382-383`） |

⚠️ **P1 与死链正交**：死链是「目标不存在」，本机路径是「目标在**作者机器上**存在」⇒ ⇒ 判据 C3 **全仓扫描，与分级无关**（与 C2 只扫 L1 的口径**刻意不同**）。

## 4. 选项对比表

| 选项 | 结论 | 理由 |
|---|---|---|
| **A. 只修 27 处死链** | ❌ **不选** | 治标：规范仍是规划态 ⇒ 下一轮导航重建**必然复发**；且**无任何机制**阻止再次漂移（实测：`usage_guide/05` 一次漂移 14 处就是证据） |
| **B. 全仓「所有失效引用都修」**（357 处） | ❌ **不选** | 其中 **330 处属历史快照** ⇒ 修它们 = **篡改历史语境**（ADR 尤其危险）⇒ 且改完后 ADR 与它记录的代码**对不上**，反而更难读 |
| **C. 分级 + 只治理 L1 + 建自动化门**（**本方案**） | ✅ **选** | ① 分类是引用判定的前置（否则每次扫仓都产几百条伪缺陷）② L1 是读者入口 ⇒ 死链必须归零 ③ **护栏把「不许漂移」变成常驻判据**（与仓内既有治理思路一致）④ 历史快照不被改写 ⇒ 不破坏史料 |
| **D. 把所有文档都当 L1（全部修 + 全部准）** | ❌ **不选** | 违反仓规「存量文档不追溯」（`docs/architecture/README.md` §3.2）⇒ 且 ADR 是**决策正本**，改其引用等于改决策载体 |

## 5. 后果 / 代价

### 正面

- **读者不再被挡住**：L1 的 27 处死链归零 ⇒ 导航可信
- **规范不再是误导源**：从「规划态」校准到「当前态」⇒ 新人按它建导航不会指向不存在的文件
- **漂移被机器拦住**：C1–C5 进 CI ⇒ 下次漂移在 PR 上就红
- **伪缺陷归零**：分级清单 ⇒ 「扫出 357 处失效」不再发生 ⇒ 后续治理不再被噪声淹没

### 负面 / 代价（**如实披露**）

- **分级清单是人工维护的**（仅混合目录）⇒ 新增混合目录下的文档时 MUST 更新它 ⇒ **新增一道手续**（与 `port-naming-exempt.tsv` / `guard-reachability.md` 同型 ⇒ 仓内已有先例）
- **护栏是新增资产** ⇒ 需维护 + 进 CI（增量：实测扫描 314 链接 / 4076 引用 ≈ **数秒** ⇒ 可忽略）
- **规范校准是一次性大改**（§2.1 目录树 + §6.1 统计 + §8.1）⇒ diff 较大 ⇒ ⇒ **只改事实性内容**，不改其分类原则与写作规范（那是它的价值所在）
- **ADR 域的 7 处死链本方案不实施**（architect 域）⇒ **留 1 个「已裁决待执行」项**（§7.4）

### 风险

| 风险 | 缓解 |
|---|---|
| 分级清单**漏登记**新文档 ⇒ 其死链不被守 | **C5**（`docs/**` 下任一 `.md` 无法归级 ⇒ 红） |
| 护栏**误红**（代码块里的 `[..](..)`、L2 历史链接） | 扫描 MUST 跳过代码块 + **只扫 L1 清单内** |
| 规范校准**改过头**（连分类原则也改了） | 校准范围限定为「事实性内容」⇒ 评审逐项对照 |
