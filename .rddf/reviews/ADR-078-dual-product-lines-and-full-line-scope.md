## 1. oracle 第 1 轮（**REJECT**）

**意图陈述**（可判定）：要解决的问题 = RV32I 平台需要第二条产品线（总线化取指 + I-L1 + `AxiDma` boot + 多级缓存），而已冻结的 mini 线必须**逐字不变**（含 268 处不可变历史决策记录 + 15 个单线硬编码护栏）；范围边界 = 本 ADR 只裁「产品线形态 / 共享边界 / 分批与命名」，不裁逐文件实施细节、不裁 S4c-3 内部设计。

**oracle 的判定依据**：事实 ①②③⑤⑥⑦⑨⑪⑫⑯⑰ 成立；但发现**四处事实漂移与四个实质性缺陷**：

| # | finding | 性质 |
|---|---|---|
| **B1** | **AC 章三条判据前提不成立或不可判** —— AC3（「1 行登记 + 0 处代码改动」对**全局整数锚点面**不成立；「1 行」对多字段面不成立；15 个脚本中其余 8 个的处置全文未交代）· AC4（「端口集互不覆盖」**字面恒假** —— 两核必然共享大部分端口名）· **AC6 与 D10 自相矛盾**（D10 下 mini 产物端口表**按构造失败** + mini 源**必须**新增 tie-0 ⇒ P1「零回归面」在源码级为假） | BLOCKER |
| **B2** | **R3 的缓解既无机判据、机制也未决** —— 「共享 IF 级只允许加可选输入」无任何现有护栏能判；「可选」未定义；换 IF 级的机制（模板参数 / 模式开关 / fork）**未选**；与事实 ③ 的张力（`instr_ready` 须成真反压 ⇒ 是**加协议**不是加可选输入） | BLOCKER |
| **B3** | **选项 ⑩ 的否决理由被仓内先例推翻** —— S3 已对 **D 侧**做过一模一样的原地升级（且 D 侧**有**生产消费者）；事实 ④ 的「不足以接 full 互连」被 `tcm_axi_slave.h:40` 证伪（单拍读是合法 full 事务，真实缺口只是 fill 效率）；D7 造成 I-cache 第二份实现 | BLOCKER |
| **B4** | **D10 双方成本都被低估** —— D10 侧不止「12→14 对」（还有 fixture `set7/get7` + `CrossTestMap` 第 7 窗口 + capability `spec.md:304` + mini 源 tie-0）；复制侧不止 791 行（还有 ~1000 行双后端测试 + **M1–M7 共 8 行**变异自证的复制与逐条再验证） | SHOULD_FIX |
| **B5** | **D1/D9 长期代价有实证且漏两类失败模式** —— 散文表漂移**已是现实**（`examples/riscv-soc/AGENTS.md` 的 module 表仍写 12）；漏「治理红线的**线无关**假象」（imem `sread` 红线 / `rv32i-data-forwarding` 停顿矩阵实为 mini 线专属）；漏「S4c-1..3 期间**共享库层的验证不对称**」 | SHOULD_FIX |
| **B6** | 事实层小漂移 —— `AxiDma` 实为 **11** 用例；引用面命令需排除 `build*`；实现实为 **791** 行；变异表实为 **8** 行；**C6（51 核自有）与 53 端口集分属两个脚本** | SHOULD_FIX |

**oracle 的关键提示（已采纳）**：「登记机制三形态」比较 —— 中央登记表（坏于多会话并行改同一文件）· 纯自动发现（坏于忘登记 ⇒ **静默不覆盖新线**，正是本仓最恐惧的失败族）· **per-line marker + 元护栏**（推荐）；以及「登记表自身的护栏」是 ADR 缺的一格。

## 4. 结论

### 4.1 critic 第 2 轮（闭合复审）—— **APPROVE**

`mergeable: yes` · `scope_exceeded: false` · **0 BLOCKER · 0 SHOULD_FIX**。

复审逐条核实（审查者自行对照源码与裁决原文，未采信 ADR 的自述）：

- **上一轮唯一 BLOCKER 已闭合**：代码事实（`i_cache_sync.h:116` 的 `offset` 全文件仅 1 处出现 · `:151` 恒取低 32 位 · `:179,183` fill 只填低 32 位）· S3 先例（`d_cache_sync.h:159` `lane_sel` + `:177` 「修『假 line』」注释 + `:46-48` 头注）· G-7 引用逐字准确（`:47`「不是性能问题，是功能错误」+ 文首 `:11-12` 与 `:107`「读选 lane 无论协议都必须做」）⇒ 事实 ⑤ 与 ⑤‴ **冲突已消解**；D7「两处一起改」+ 爆炸半径三条 + AC8 + R7 + 选项 ⑩ 均一致。
- **上一轮 7 条 SHOULD_FIX 全部闭合**（19 根面 / 第 8 窗口 / wrapper 与测试同批改写 / phantom principle 撤回 / V1-V2 与 C6 编号订正 / AC15 集合相等 / AC11 措辞）。
- **本轮修订未引入新的架构级问题**。
