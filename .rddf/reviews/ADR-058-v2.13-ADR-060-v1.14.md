## 2. oracle 发现与处置

⚠️ **归属说明**：下表只列 **oracle** 的输出。critic 的 SF-1（端口集合必须由 emitter 产物派生）
**不在**本表 —— 它见 §3。

| # | oracle finding（影响） | 处置 |
|---|---|---|
| 1 | **高**：双 backend 共享 `verilator_work_dir_` ⇒ `top.v` / `sim_main.cpp` / `obj_dir` 互踩；任何「重新 initialize」的顺序假设都会错 | **已按原句修** ⇒ E2（物理隔离 + 双 work_dir） |
| 2 | **高**：`initialize_with_verilog` 若沿用 `try_initialize` 的 best-effort（编译/dlopen 失败仅 `CHWARN`）⇒ backend **静默不可用** ⇒ harness 按 dual-backend 惯例把「不可用」当 SKIP ⇒ **整套静默跳过 = 恒绿假绿** | **已按原句修** ⇒ E3（失败 MUST 返回 `VerilatorError`；harness MUST 断言**真初始化成功**） |
| 3 | **高**：端口集合漏 clock/reset ⇒ `pulse_reset()` / `clock_field_ptr_` 空转 ⇒ 寄存器永不更新 ⇒ **逐拍全等恒绿**（最危险的假绿） | **已按原句修** ⇒ E1 的 `⊇ {clock, reset}` |
| 4 | 中（**机制订正**）：Verilator 顶层类名的决定因素**不是**「顶层 module 名」单独决定 | **已按实测改写** ⇒ 「`--top-module` 或输入文件名（`--prefix` 亦可覆盖）」；据此把「顶层名 ≠ `top` ⇒ 编译期失败」写成**入口 fail-early** |
| 5 | 中：`node_id` 是 §2.2 映射表的**承重列**（backend 按 node id 取 `data_map_` 槽位）⇒ 表里只有名字它用不了 | 采纳 ⇒ 新增字段带 `uint32_t node_id`；并补**有效性域** = 同一 ctx（`node_id` 是 ctx 私有自增编号，跨 ctx 无可比性契约） |
| 6 | 中：被移出顶层的那批 `ch_out` 在映射表里**无处落账** | 采纳 ⇒ schema 允许 `hier_top_port_name` 为空；「层次化位置集合」= 含**子 module 端口**与**体内线网** |
| 7 | 中：「映射表由 emitter 产出」是**禁令**不是**判据** | 采纳 ⇒ 载体定为 `HierarchyEmitResult` 的**字段**（同一调用内产出 ⇒ 结构上无法自建）+ §5 补「缺一项 ⇒ 转红」的判别力自证 |
| 8 | 低：本轮**不做**的四项须显式登记，否则会被后续实施者当成待办 | 采纳 ⇒ 台账 §11.11.4（backend 任意顶层名 · **C2** 多份产物拼接 · P6/P8 独立立项 · 端口命名静态护栏） |

## 3. critic 结论（arch 档）

`APPROVE_WITH_CONDITIONS` · `mergeable: yes` · `scope_exceeded: false` · **BLOCKERS: 无**。

| # | 条件 / 建议 | 处置 |
|---|---|---|
| SF-1 | `ADR-058:249`（E1）+ `:159-164`（映射表载体）—— E1 未约束「显式端口集合 MUST 由 emitter 产物（映射表 + `port_provenance`）**派生**、不得独立撰写」 | **已修（v2.14）** ⇒ §2.2 映射表载体段补「同一份产物 = 同一个真相源 ⇒ §2.3 E1 的集合 MUST 同样由它派生」；E1 行补 **MUST NOT 由 harness / backend 独立撰写 / 手工列举** |
| SF-2 | 台账 §11.11.2 的 **D4** 行只有「MUST 任务化」，缺**可执行闭环判据** ⇒ 无法保证 T3-005 归档时 5 处 spec 修订真的做了 | **已修（v2.14）** ⇒ 台账 §11.11.2 末新增 **V1**：两条 `grep` 判据（正面 7 行清零 · 反面 `MUST NOT 依赖抛异常` 仍为 1）⇒ 两条 MUST 进 T3-005 的 tasks verify 块 |
| NIT-1 | `ADR-058:208-211` 仍写 `port_provenance`「尚未落地」（实际已落地） | **已修（v2.14）** ⇒ 改为「已落地 · `include/hierarchy_verilog.h:48-69`」，并明示它**不含 `node_id`** ⇒ 不能顶替映射表（两者并存） |
| NIT-2 | ADR-060 §5 把 `PortPolicy` 与 `UndrivenPolicy` 的 `Reject` 混写 | **已修（v1.15）** ⇒ 改为点名 `PortPolicy::SynthesizeFatal` / `PortPolicy::Reject`（两者**都**属 `PortPolicy`，见 `include/component.h:52,55`），并注明 `UndrivenPolicy::Reject` 见冒泡判据 |

⚠️ **NIT-2 的处置与 critic 建议的差异（如实登记）**：critic 建议「只点名 `SynthesizeFatal`」。
未采纳该简化 —— `PortPolicy` **本身也有 `Reject`** 值（首错即返），删掉它会丢失该策略下
「跨层非端口边 MUST 失败」的覆盖。真正的病根是**裸写导致的枚举歧义** ⇒ 改为**全限定名**
既消除歧义、又不缩面。

## 4. 验证移交（build）

1. **T3-005 的 tasks 里落 D1–D4**（多文件任务删除 / 计数 ×3→×2 / 三处 `-Wall` / 5 个 Requirement
   的 MODIFIED）—— 本报告不代替 tasks 修订。
2. **D4 的闭环判据 V1**（台账 §11.11.2 末）⇒ 进 tasks 的 verify 块，**归档前**必须为
   0 / 1。
3. **E1/E2/E3 落地时的负向对照**：
   - E1：把端口集合改成「手工列举且漏 clock/reset」⇒ 逐拍等价判据 MUST 转红（否则该判据**对这类
     缺陷失明**）。
   - E2：两个 backend 共用 work_dir ⇒ MUST 出现编译失败或产物互踩（不是静默通过）。
   - E3：让 `initialize_with_verilog` 在编译失败时 `CHWARN` 后继续 ⇒ harness MUST 报失败（**不是**
     SKIP）。
4. **顶层名约束**：用 `top_module_name = "myroot"` 调入口 ⇒ MUST `ok=false` + `error` 点名，
   且**不产生**文件（fail-early 先于 I/O）。
