## 1. 缺陷本体（W2）：反压期的旁路档位**没有跟着冻结**

### 1.1 相关信号的**归属**（`include/cpu/pipeline/rv32i_pipeline.h`）

| 信号 | 归属 | 出处 |
|---|---|---|
| `fwd_a_d1` / `fwd_b_d1` | **派生状态**（前推**档位**）· 打**一拍** | `:166-167` · `->next` 在 `:836-839` |
| `hazard.io().forward_a/b` | **组合**输出 · 判据用 **ID 级输入那条指令**的 rs 地址 | `hazard_unit.h:218-228` · 输入接线 `rv32i_pipeline.h:734-735`（`id_stage.rs1_addr_id` = **组合**译码） |
| `fwd_mux` | 消费档位 · 服务 **ID→EX 边界那条指令** | `rv32i_pipeline.h:844-845` |
| `id_stage.io().freeze` | MEM 级反压 ⇒ **ID/EX 全字段保持** | `rv32i_pipeline.h:723` · `id_stage.h:264-268` |
| `exmem_en` | MEM 级反压 ⇒ **EX/MEM 不前进** | `rv32i_pipeline.h:560` |
| `m2_*` / `memwb_*` | MEM 级反压 ⇒ **保持** | `rv32i_pipeline.h:316-323` · `:637-652` |

⇒ ⇒ **三条路径都冻结，唯独档位寄存器不冻结** ⇒ ⇒ 它成了**唯一**在反压期继续变化的
「服务于某条指令」的派生状态 ⇒ ⇒ 它的**服务对象**（EX 级那条被冻结的指令）不变，
**内容**却每拍变 ⇒ ⇒ **失步**。

### 1.2 失步的**逐拍**推导（`E` = 被冻在 EX 的指令 · `S` = IF/ID 那条后继）

| 拍 | `fwd_a_d1` 的内容 | 它服务的指令 | 对齐？ |
|---|---|---|---|
| `N-1` | `hazard.forward_a`（判据用 **E** 的 rs） | `N-1` 时 `E` 在 ID ⇒ `N` 时 `E` 在 EX | ✅ |
| `N`（反压开始） | 同上（仍 = **E** 的档位） | `E` 在 EX | ✅ |
| `N+1` | `hazard.forward_a`（判据用 **S** 的 rs）⚠️ | `E` 仍在 EX（被冻结） | ❌ **失步** |

⇒ ⇒ **「档位的内容」必须与「它服务的指令」一起冻结** ⇒ ⇒ 这正是
SpinalHDL / VexRiscv 的做法（**派生状态随它服务的级一起冻结**）：
- SpinalHDL `RiscvCore.scala:666` 的 `m2sPipe` + `Stream.scala` 的
  `RegNextWhen(payload, self.ready)` ⇒ ⇒ **halt 时 payload 物理冻结**；
- VexRiscv `Pipeline.scala:124` 用 `RegNextWhen(…, !stage.arbitration.isStuck)`。

⇒ ⇒ **修法 = 在 `mem_stall` 期间保持档位寄存器** ⇒ ⇒ **零结构变更**。

### 1.3 两个**被排除**的「看起来更保守」的错法

| 方案 | 为什么**错** | 判据 |
|---|---|---|
| ❌ **反压期间清零档位** | 被冻结指令若**自身**在冻结入口档位就非 0（距离-2 生产者此刻在 M2）⇒ ⇒ 清零把「**错前推**」换成「读 `idex_rs1_data` 的**陈旧**值」⇒ ⇒ 同样是错 | **A2**（M2 形态）⇒ 两种错法都给出 `x6 == 1`（应为 43） |
| ❌ **改用「ID 读拍的 M2/WB 旁路冻结」** | 那条通路服务的是**解冻沿锁存的后继指令**（反压期间 `idex_update_en == 0` ⇒ 其输出**无消费者**）⇒ ⇒ 冻结它反而请回 ADR-069 §7.1.2（D11）处理的**同沿竞态** | 推导（无独立用例） |

### 1.4 **解冻沿无缝隙**

`mem_stall` 解除的那一拍，寄存器装入「该拍按**后继指令**地址算出的档位」，
而后继指令于**下一拍**进 EX 消费它 ⇒ ⇒ **d1 的对齐关系逐拍保持**
（被冻结指令在该拍**仍在 EX** ⇒ 持有档位施加给它**正确**）。

## 2. 缺陷的**数值互证**（`rv32ui-p-lb` 轨迹）

```
c=40..48   冻结期：EX/MEM 持 `lb`（alu = 0x8001_0050）· EX 持 `li t2,-1` · ID 输入持 `bne a4,t2`
c=49       该 `li` 的 alu = 0x8001_004f · rs2 = 0x8001_0050
           ⇒ ⇒ 被冻结指令的 rs1 被换成 **M2 的写回值** 0x8001_0000 的等价值
```

⇒ ⇒ **三处数值互证**（EX/MEM 的 alu · EX 的 alu · ID 输入的 rs）⇒ ⇒ 根因闭合。

**对照实验**：`rv32ui-p-lw` 修复后通过 ⇒ ⇒ 因为它的后继被冻结指令是 `lui`
（**不用 rs1 / rs2**）⇒ ⇒ 污染**不可观测** ⇒ ⇒ 「7 个失败」是**污染可见性**的分布，
不是「7 条独立缺陷」。

## 3. R1：镜像重建的**两个**改造点

### 3.1 `env/riscv_test.h` —— 只换 4 个宏

上游 `env/p/riscv_test.h` 的 `RVTEST_CODE_BEGIN` 无条件做
`csrw mtvec` / `csrwi mstatus` / `csrw mepc` / `mret`；
`RVTEST_PASS` / `RVTEST_FAIL` 走 `ecall`（`a7 = 93`）+ trap 处理程序
⇒ ⇒ 要求**完整特权 / trap 机器** ⇒ ⇒ 本核**不实现 CSR**
（`.rddf/improvements/rv32i-privileged-csr-2026-11.md`）。

⇒ ⇒ 换成「直接写 `tohost`」的 4 个宏 ⇒ ⇒ **测试体一字未改**
⇒ ⇒ 依据 = riscv-tests 上游 **issue #368**（维护者给出的做法）。

### 3.2 `env/link.ld` —— 双 TCM 布局

上游假设**单一平坦内存** ⇒ `.data` 落在 `0x8000_0000` 起 ⇒ ⇒ 本核从 D-TCM 侧读它
⇒ ⇒ 读到 **0** ⇒ ⇒ 7 个测试失败（`lb/lbu/lh/lhu/lw/sb/sh`）。

⇒ ⇒ 布局：`.text.init` / `.text` @ `0x8000_0000`（I-TCM）·
`.tohost` @ `0x8001_0000`（D-TCM 区首）· `.data` / `.bss` 随后。

⇒ ⇒ **固定地址是判据依赖**（`tohost` 的地址被 R2 的运行器当作判定锚点）。

## 4. R2：怎么在核级观察 `tohost`

`tohost` 在 D-TCM 的**首字** ⇒ ⇒ 核**自己**写它 ⇒ ⇒ D-TCM 在核内部、**无读出口**
⇒ ⇒ 运行器改观察**既有根端口**上的 **store 提交事件**：

```
obs_data_write_en   = pipeline.data_write_en & data_ready_calc   （单拍脉冲）
obs_data_addr       = pipeline.data_addr                          （**字节**地址）
obs_data_write_data = pipeline.data_write_data                    （整字）
```

⇒ ⇒ 地址 == `0x8001_0000` 的那次写 ⇒ 就是 env 写 `tohost` ⇒ 值即判定依据
⇒ ⇒ **零新增端口** ⇒ ⇒ 53 端口契约表 + C6 快照**零改动**
⇒ ⇒ 顺带覆盖 **store 路径**（D-L1 写穿 → D-TCM ⇒ 事件在总线侧派生）。

## 5. A3（控制面）的**形态推导** —— 为什么前三版恒绿

判据要求「污染**改变分支的比较结果**」⇒ ⇒ 被冻结分支的 rs1 在**冻结入口**档位就
MUST **非 0**（否则污染把它刷成 0 ⇒ 读回的仍是寄存器堆里的**同一个值**）。

| 版次 | 形态 | 为什么**恒绿** |
|---|---|---|
| ① | `beq x0,x0` | 立即成立 ⇒ 在冻结开始**之前**就 flush ⇒ **根本没经历冻结** |
| ② | `beq x14,x0` | 冻结入口档位 = 2，污染后档位**仍是** 2 ⇒ 值不变 |
| ③ | `beq x14,x14` | `rs1 == rs2` ⇒ 两个操作数被**同样**污染 ⇒ 值不变 |
| ④ **（落地）** | `beq x5, x0`（`x5` 由**距离 2** 的生产者提供） | 冻结入口档位 = **2**（MEM 档）⇒ 正确值 = **42**；后继指令 rs = 0/0 ⇒ 污染把档位刷成 **0** ⇒ **回退**到陈旧值 **0** ⇒ `0 == 0` ⇒ **翻转** ✅ |

⇒ ⇒ **两个可手推的期望值**（42 与 0）⇒ ⇒ 判据**不依赖实现时序**。
⇒ ⇒ **旁证**：`beq x14,x14`（版次 ③）之所以恒绿，是因为 **rs1 与 rs2 同时被污染**
⇒ ⇒ 污染源必须**只命中一侧** ⇒ ⇒ 这也解释了为什么 A1（M1 · 后继别名型）要用
**两个别名**（`rs1` 与 `rs2` 各命中一处）。
