# Capability: chlib-state-machine-semantics

## ADDED Requirements

### Requirement: 状态守卫贡献的优先级 MUST 是「先匹配者胜」

同一 target 的**多条**状态守卫贡献 MUST 被合成为**一条** `select` 链 ⇒ ⇒
该链 MUST 是**先匹配者胜**：贡献的**声明顺序**即优先级 ⇒ ⇒ **靠前者**的贡献
MUST 位于链的**外层**（先被求值并胜出）。

⇒ ⇒ 贡献的**声明顺序** MUST 是**状态序**（状态枚举值由小到大）⇒ ⇒
**低编号**状态的贡献 MUST 优先于**高编号**状态的贡献。

⇒ ⇒ 该方向 MUST 与仓内其它条件构造一致（`_if` / `multi_if` 均为「先匹配者胜」）。

⇒ ⇒ 优先级 MUST 有**结构级**断言钉住（运行期**不可观测** ⇒ 金标**不足以**
钉住它 ⇒ MUST 断言最外层 mux 的守卫 = **第一个**贡献的守卫）。

⚠️ **由来**：ADR-051 D10 的组合器抽取**静默翻转**了该优先级（该 change 的
`design.md` §1）⇒ ⇒ 该翻转**不违反**本 capability 的既有任何条款。

#### Scenario: 同一 target 的多状态贡献按状态序优先

- **WHEN** 同一 target 有两条状态守卫贡献，状态枚举值为 `S0 < S1`
- **THEN** `S0` 的贡献 MUST 优先于 `S1` 的贡献
- **AND** 该优先级 MUST 可由**结构级**断言判定（最外层 mux 的守卫 = `S0` 的守卫）

#### Scenario: 贡献的优先级方向 MUST 与其它条件构造一致

- **WHEN** 状态守卫贡献与 `_if` 的条件贡献由**同一个**组合器合成
- **THEN** 两者的优先级方向 MUST **一致**（均为「先匹配者胜」）
- **AND** MUST NOT 一方是「先匹配者胜」而另一方是「后匹配者胜」

#### Scenario: 优先级 MUST 有结构级断言钉住

- **WHEN** 共享组合器的链构造方向被改动（`rbegin→rend` 改成 `begin→end`）
- **THEN** **结构级**断言 MUST **转红**
- **AND** 运行期用例 MUST **仍绿**（⇒ 证明「运行期不可观测」这条事实成立）
