## Q2 — 是否允许把实施拆成两个批次（α = 路径 B / β = 族 ①/③）

### 问题陈述

`ADR-066 §2.2` 末尾的 operative 义务原文：

> 「**本决策与决策 ① 同批落地**：只修 ① 而不修 ② ⇒ ⇒ 坏产物**仍在** ⇒ ⇒ 且两者共用同一张重定向表
> ⇒ ⇒ **决策 ① 的实现面因此覆盖两条路径**（不是两条独立工作项）。」

拆成两半看：

| 子句 | 今天的实际 | 判定 |
|---|---|---|
| 「只修 ① 不修 ② ⇒ 坏产物仍在」 | 路径 B 的事实依据（`hierarchy_verilog.cpp:695-701` 用 `names.at(e.to_ptr)`） | ✅ **成立** ⇒ 这是一条**顺序**约束（② 不得晚于 ①） |
| 「两者共用同一张重定向表」 | 「重定向表」一词在仓内指三样东西：① ADR-060 R1/R2 的 per-module redirect map；② `view_.names` 命名真源；③ `synth_wires`（纯字符串，**无节点身份**）⇒ 本句只对 ② 成立 | ⚠️ **换所指才成立** |
| 「决策 ① 的实现面覆盖两条路径」 | 两桶结构（F1）⇒ ① 的实现**不会**自动覆盖 ② | ❌ **不成立** |

⇒ ⇒ 结论：**operative 义务保留**（② 不晚于 ①），**rationale 的后两句要改**（它们给了「不是两条独立工作项」这个操作层推论，而该推论已被 F1 推翻）。

1. **中间态不得比现状更危险** —— 且「危险」的判据不是感觉，见下方 `L1/L2`。
2. 拆批不得改变决策 ①② 的**内容**（支持范围 / 命名规则 / 诊断义务）。
3. 契约（spec / ADR-060 / ADR-062）在 change 归档前 MUST 全部同步。
4. 保留取代/修订说明（本仓惯例：ADR-058 v2.11 / ADR-060 v1.9 的反向指针）。
5. **ADR-060 / ADR-062 / spec 全文无「同批 / 同一 change」类约束**（已 grep）⇒ 同步面只有 3 处，无新增自相矛盾。

## Q6 — 「内部信号名」措辞不可判定（**spec delta 与 ADR 同病**）

### 问题陈述

- `specs/rtl-hierarchical-output/spec.md:58`：「父侧 MUST NOT 引用子 module 的**内部信号名**」
- `ADR-066` §2.2（`decision-requests.md` 引用处 `ADR-066:100-101`）同义表述

而 **落点网名 = 端点的 ctx 全局名 = 子 module 内部使用的同一串**（F2 + `design.md:81`）
⇒ ⇒ **逐字执行会把正确实现判成违规**。可判定的口径是「**仅在**子 module 内声明」（= 父作用域可解析）。

### 候选与代价

| 选项 | 内容 | 代价 |
|---|---|---|
| **A（planner 倾向）** | 把「内部信号名」改为「**仅在子 module 内声明**的名字（判据 = 父 module 作用域可解析）」⇒ spec delta + ADR-066 同步（ADR 文字属 architect） | 措辞修订 ⇒ 只走 **oracle 单审**（按审查配对：改措辞只需 oracle）；风险 = 若有人把「内部信号名」读成别的东西，需在 change 的 design 里留一句 |
| **B** | 保留措辞，靠 V3/A2/A3 的判据覆盖 | ❌ 不推荐：规范文本与验收判据**正相反**，verifier 会按文本判 ⇒ 假失败 |
