# design · 补齐 AXI-Lite 11 根输出进跨后端向量（步 2）

> **Change**：`rv32i-obs-vector-axil-2026-11` · **母 improvement**：同名
> **纪律**：期望值 MUST **手推**（禁抄仿真输出）· 每条新判据配一条变异 · 逐拍 diff **无掩码**

---

## 1. 载体与拓扑

```
test_rv32i_soc_dual_parity.cpp
├─ kObsNames[39]            ← 28 + 11 根 axil_*（顺序 == 核顶层 __io）
├─ obs_snapshot()           ← 39 次 read_port_output（顺序必须与 kObsNames 一致）
├─ AxilSlave{8 根 in}       ← 默认「立即应答」· 全常量
│    └─ drive_axil()        ← 在 load_firmware() 内统一调用（**每个用例都被驱动**）
└─ TEST_CASE Rv32iSoc - AxilMmioCrossBackend
     ├─ ① MMIO 程序（5 字）⇒ 逐拍 diff（39 根）+ AXI 语义 golden（B–F）
     └─ ② plain 程序（7 字）⇒ 逐拍 diff + 「请求线全程 0」（G）
```

**为什么从设备接线必须是常量**：逐拍 diff 的**前提**是「两个后端的输入逐拍完全相同」。
若从设备反应式地跟随 DUT 输出（像 `test_rv32i_core_mmio` 的 `pending_since`），
一旦两端分歧，**输入也跟着分歧** ⇒ 差异被放大成噪声 ⇒ 定位困难。
常量接线把分歧**完整地**体现在 DUT 输出上（那正是要比的东西）。

**为什么默认「立即应答」而不是「全 0」**：全 0（永不应答）时，任何走到 MMIO 的固件
都会**永久停住**（store 的 `data_ready` 永不回来）⇒ ⇒ 未来某用例一碰 MMIO 就**挂死**
（不是红，是挂）。「立即应答」对无 MMIO 固件零影响。

## 2. 手推期望（**禁抄仿真输出**）

固件（与 `test_rv32i_core_mmio.cpp` 同款，其常量已逐条手推 + 库表交叉校验）：

| 字 | 指令 | 手推 |
|---|---|---|
| 0 | `lui x4, 0x80102` | x4 = 0x8010_2000（== `riscv::kGpio.base`） |
| 1 | `lw x6, 4(x4)` | MMIO 读 @ **0x8010_2004** ⇒ 从设备回 `rdata` = **0x5A** |
| 2 | `addi x7, x0, 1` | x7 = 1（非 MMIO 后继） |
| 3 | `sw x6, 0(x4)` | MMIO 写 @ **0x8010_2000** · 数据 = **0x5A** · `wstrb` = **0xF**（`sw` = 4 车道全开） |
| 4 | `jal x0, 0` | 自环（rd = 0 ⇒ 无写回） |

编码交叉校验（编译期常量 vs 库编码器）：`0x80102237 / 0x00422303 / 0x00100393 / 0x00622023 / 0x0000006F`。

从设备 = 立即应答 ⇒ 每条事务 **1 拍**：AW+W 同拍握手 ⇒ 次拍 `bvalid` ⇒ 完成脉冲；
AR 握手 ⇒ 次拍 `rvalid` ⇒ 完成脉冲。⇒ ⇒ `awvalid` / `arvalid` **各恰好 1 拍**。

**写回 3 条**（手推，按程序序）：x4 = 0x8010_2000 · x6 = 0x5A · x7 = 1。
（`jal x0, 0` 的 `rd = 0` ⇒ x0 保护 ⇒ 不写回。）

## 3. 判据设计（每条都有变异）

| 代号 | 判据 | 变异（判别力自证） |
|---|---|---|
| **A** | 逐拍 diff（39 根 · 无掩码） | 去掉向量里任一根 ⇒ AC1（护栏 C1）红 |
| **B** | `awvalid` / `arvalid` 各**恰好 1 拍** | 从设备改成「永不应答」⇒ VALID 持续到超时 ⇒ 拍数 > 1 ⇒ 红 |
| **C** | 首个 `awvalid` 拍：`awaddr` / `wdata` / `wstrb` == 0x8010_2000 / 0x5A / 0xF | 把 `wstrb` 判据改成 0x3 ⇒ 红（`sw` 车道） |
| **D** | 首个 `arvalid` 拍：`araddr` == 0x8010_2004 | 改成 0x8010_2000 ⇒ 红（读地址偏 4 字节） |
| **E** | store 事件 **1 次**（addr / data） | 若 MMIO 写被当成普通 store（分流方向错）⇒ 地址是 TCM 地址 ⇒ 红 |
| **F** | 写回 **3 条**（x4 / x6 / x7 + 数据） | 删 `addi x7` ⇒ 2 条 ⇒ 红 |
| **G** | 非 MMIO 程序 ⇒ 请求线**全程 0** | 把 `in_mmio` 的判定改宽（例如把地址 0 也算 MMIO）⇒ 请求线拉高 ⇒ 红 |

## 4. 边界与错误路径

| 路径 | 处置 |
|---|---|
| verilator 缺席 | `tool_available()` 检查 ⇒ `WARN` + return（**不用** `SKIP`：全 SKIP ⇒ Catch2 exit 4 ⇒ CTest 红） |
| `VerilatorBackend::initialize()` 返回 false | 同上 `WARN` + return（ADR-035 R3：>64 位端口被拒） |
| `port_access_` 空 | 同上 |
| 固件以后某个用例**意外**碰 MMIO | 默认从设备「立即应答」⇒ 不会挂死；但会引入 golden 未覆盖的 `axil_*` 变化 ⇒ 由 G 的「plain 程序请求线恒 0」在本用例内兜底 |

## 5. 与步 1 护栏的关系（**登记表归零**）

步 1 的 analyzer 原把「登记表解析到 0 行」当 **fail-closed** ⇒ ⇒ 本项补齐后会**误判红**。
⇒ ⇒ 本项把它改成「空登记表 = 合法（缺口归零）」，并**新增自检 P0** 钉住这个语义：
`空登记表 + 向量覆盖全部端口 ⇒ 绿`。
⇒ ⇒ 真正的判据仍是 **C4（V ∪ R == P）** —— 端口漏了照样红，与「表里有没有行」无关。
