# Capability: rv32i-data-forwarding

## MODIFIED Requirements

### Requirement: 数据前推 MUST 为消费者提供**最新值**

- **MODIFIED**: 本 Requirement 的**契约面**因 **A0**（D-TCM `aread` → `sread` ⇒ ⇒ EX→WB 级数 2 → 3）
  而**扩展** —— 既有内容**一条都不删**（全部 WHEN/THEN/AND 逐字保留）⇒ ⇒ 本 delta 只**改写 4 处**并**追加 1 条** Scenario：
  ① 「距离 ⇔ 生产者所在级**一一对应**」句（MUST 改写：基线仍一一对应，**A0 之后不再**）
  ② 「距离矩阵」表（距离 2/3 的来源前移至 **M2 档** · 距离 4 落到 **WB 档** · ≥ 4 改为 ≥ 5）
  ③ 「距离 2 的 load → use」的 NOTE（数据源 MEM/WB 级 ⇒ ⇒ **M2 级**）
  ④ 「距离 3 的 load → use」的 NOTE（WB→ID ⇒ ⇒ **M2→ID**）+「距离 ≥ 4」Scenario 拆段
  ⑤ **追加**「**A0 下的两级旁路**」Scenario（M2 档优先 + WB 档保留）
  ⇒ ⇒ 架构依据 = `docs/adr/ADR-069-mem-data-alignment.md`（**Accepted** · §7.1 / §7.1.1 / §7.1.2 / §7.1.3）
  与 `docs/adr/ADR-047-rv32i-data-forwarding.md`（§5.5.2.1 dated note）
  ⇒ ⇒ ⚠️ **本 Requirement 是距离矩阵的唯一权威** ⇒ ⇒ 本 delta 落地后**以本文件文本为准**
  ⇒ ⇒ ⚠️ **禁**只改实现不改 spec（ADR-047 §5.5.3 ②）。


- **WHEN** 一条指令的源操作数依赖**更早**指令写入的寄存器
- **THEN** 消费者 MUST 拿到该寄存器的**最新值**
- **AND** MUST NOT 要求固件手工插 NOP 来避免读到旧值
- **AND** 消费者 MUST NOT 为了拿到新值而**额外停顿**
  （load-use 停顿是**唯一**例外 —— 见 `rv32i-commit-path` capability 的
  「load-use 冒险 MUST 被检测到，且停顿 MUST 是**保持型**」）
- **AND** 各类**距离**的取值来源 MUST 符合下方「距离矩阵」Scenario

#### Scenario: 距离矩阵（**本 capability 的唯一权威**）

- **WHEN** 一个消费者依赖某个生产者写入的寄存器
- **THEN** 消费者 MUST 拿到该寄存器的**最新值**
- **AND** **「距离」的定义** MUST 是：
  **距离 = 生产者与消费者之间的指令间隔数 + 1**
  （相邻（中间无指令）= 距离 1；中间隔 **1** 条 = 距离 2；隔 **2** 条 = 距离 3）

- **AND** 它与「生产者所在级」的对应关系 MUST 是（⚠️ **2026-11-13 修订** · 依据 =
  `docs/adr/ADR-069-mem-data-alignment.md` §7.1.3 + `docs/adr/ADR-047-rv32i-data-forwarding.md` §5.5.2.1）：
  - **基线（`aread` · EX→WB = 2 级）**：距离 1 ⇒ 生产者在 **EX** 级；距离 2 ⇒ **MEM** 级；距离 3 ⇒ **WB** 级
    ⇒ ⇒ **一一对应**
  - **A0 之后（`sread` + M2 · EX→WB = 3 级）**：⚠️ **不再一一对应** ⇒ ⇒ 距离 2 与距离 3 **同落 M2 级**
    ⇒ ⇒ 二者靠「**消费者所在级**」区分（距离 2 的消费者在 EX 级 ⇒ 走**档位 2**；
    距离 3 的消费者在 ID 级 ⇒ 走**读点旁路**）⇒ ⇒ **见下方矩阵**
- **AND** 各类距离的**取值来源** MUST 是（⚠️ **2026-11-13 修订** · 下表 = **A0 之后**的矩阵；
  **基线**矩阵见本 Scenario 的 ⚠️ 注记）：

  | 距离 | 生产者所在级 | **取值来源** | 结论 |
  |---|---|---|---|
  | 1 | EX | 档位 `1`（EX/MEM 级流水线寄存器） | ✅ 前推覆盖（⚠️ **load→use 是例外** —— 走 **load-use 停顿**，档位 `1` **不覆盖 load**） |
  | 2 | **M2** | 档位 `2`（**M2 级**的**合并写回值**） | ✅ 前推覆盖 |
  | 3 | **M2** | **寄存器堆读点的 M2→ID 组合旁路**（**新增**） | ✅ 旁路覆盖 |
  | 4 | **WB** | **寄存器堆读点的 WB→ID 组合旁路**（**保留**） | ✅ 旁路覆盖 |
  | ≥ 5 | 已退休 | 寄存器堆路径（写回早已落地） | ✅ |

  - **NOTE**: ⚠️ **基线矩阵（`aread`）** = 距离 1 → EX/档位 1 · 距离 2 → MEM/档位 2 ·
    距离 3 → **WB/WB→ID 旁路** · ≥ 4 → 已退休/寄存器堆路径
    ⇒ ⇒ **A0 把同沿竞态从「距离 3」推到了「距离 4」**（**没有消灭**它）
    ⇒ ⇒ ⇒ **距离 3 的取值来源从 WB 档前移到 M2 档**
    ⇒ ⇒ ⇒ **距离 4 的取值来源从「寄存器堆路径」改为 WB 档**
  - **NOTE**: ⚠️ **A0 = `docs/adr/ADR-069-mem-data-alignment.md` 的 **Accepted** 决策**
    ⇒ ⇒ 依据 = 其 §7.1（拍级表）· §7.1.2（两级优先旁路）· §7.1.3（本矩阵右移）
    ⇒ ⇒ **实现方 MUST 先读 ADR-069 §7.1.2**（其中钉死「M2 档优先 + WB 档保留」
    ⇒ ⇒ 且 **`wb_stage` 的写回 mux MUST NOT 前移** ⇒ ⇒ 前移会让**真正提交的那条指令永不写回**）

#### Scenario: 相邻 ALU → ALU（中间无间隔）

- **WHEN** 固件是 `addi x5, x0, 7` → `add x6, x5, x0`（**中间无 NOP**）
- **THEN** `x6` MUST 是 `7`
- **AND** MUST NOT 是该寄存器在写入**之前**的旧值

#### Scenario: 距离 2 的 load → use

- **WHEN** 固件是「一条 load」→「一条无关指令」→「一条读该 load 目标寄存器的指令」
- **THEN** 该消费者 MUST 读到 load 写入的**新值**
- **AND** MUST NOT 读到该寄存器在 load 之前的旧值
- **NOTE**: 该距离由「MEM 级前推档位」覆盖 ⇒ 其**数据源** MUST 是 **M2 级**的
  **合并写回值**（该值已含 load 数据）⚠️ **2026-11-13 修订**（基线是 MEM/WB 级 ⇒ ⇒ A0 后前移到 M2 级
  ⇒ ⇒ 依据 = ADR-069 §7.1.3）

#### Scenario: 距离 3 的 load → use

- **WHEN** 固件是「一条 load」→「**两条**无关指令」→「一条读该 load 目标寄存器的指令」
- **THEN** 该消费者 MUST 读到 load 写入的**新值**
- **AND** MUST NOT 读到该寄存器在 load 之前的旧值
- **NOTE**: 该距离**不经前推档位**（消费者在 ID 级 ⇒ 已离开 EX 级的档位命中窗口）
  ⇒ 它依赖「寄存器堆读点对**同沿**取值的旁路」
  ⇒ 该读点 MUST NOT 与写回沿**竞态**
  ⚠️ **2026-11-13 修订**：⚠️ **A0 之后**该距离的取值来源是 **M2→ID 组合旁路**（**不是** WB→ID）
  ⇒ ⇒ 因为 A0 把写回推迟 1 拍 ⇒ ⇒ 距离 3 的生产者在消费者的 ID 读拍**尚未写回**
  ⇒ ⇒ ⇒ **WB 档在该距离上够不着** ⇒ ⇒ **MUST 新增 M2 档**
  ⇒ ⇒ ⇒ 依据 = ADR-069 §7.1.1 的拍级表

#### Scenario: 距离 ≥ 4 的依赖

- **WHEN** 生产者与消费者之间隔着 **≥ 3** 条无关指令
- **THEN** 该消费者 MUST 读到生产者的**新值**
  （写回早已落地 ⇒ 走寄存器堆路径）
- **NOTE**: ⚠️ **2026-11-13 修订**：**A0 之后**本 Scenario MUST 拆成两段解读 ——
  **距离 4**（隔着 **3** 条无关指令）⇒ ⇒ 生产者在 **WB** 级 ⇒ ⇒ 写回沿与消费者的 ID/EX 锁存沿
  **同沿** ⇒ ⇒ **仍需 WB→ID 组合旁路**（**不是**寄存器堆路径）
  ⇒ ⇒ **距离 ≥ 5**（隔着 **≥ 4** 条无关指令）⇒ ⇒ 写回**早已落地** ⇒ ⇒ 走**寄存器堆路径**
  ⇒ ⇒ ⇒ 依据 = ADR-069 §7.1.1 的拍级表（写回沿 = posedge N+4 · 距离 4 消费者的锁存沿 = posedge N+4）

#### Scenario: **A0 下的两级旁路**（M2 档优先 + WB 档保留）

- **WHEN** 寄存器堆读点需要为消费者取到**新值**，且候选生产者可能落在 **M2 级**或 **WB 级**
- **THEN** 读点 MUST 具备**两级**旁路：**M2 档**（判据 = `m2_valid` ∧ 生产者类型 ∧ `m2_rd_addr != 0`
  ∧ `m2_rd_addr` 与消费者 `rs1`/`rs2` 相等）与 **WB 档**（判据 = `wb_write_en`
  ∧ `wb_stage.io().rd_addr_out` 与消费者 `rs1`/`rs2` 相等）
- **AND** 两档同时命中**同一个** `rd` 时 MUST 取 **M2 档**（该指令更年轻 ⇒ youngest-wins）
- **AND** 两档的**数据叶子** MUST 是**流水线寄存器**（M2 寄存器 + `sread` 输出寄存器 / MEM/WB′ 寄存器）
  ⇒ ⇒ MUST NOT 形成**组合环**
- **AND** **WB 档 MUST 保留** ⇒ ⇒ 删除它 MUST 使「距离 4」与「**4 拍**停顿后的 load-use 消费者」**读旧值**
  ⇒ ⇒ ⇒ 依据 = ADR-069 §7.1.1 + §7.1.2 · ADR-047 §5.5.2.1

#### Scenario: 分支条件用紧邻新值

- **WHEN** 固件是 `addi x1, x0, 1` → `beq x1, x0, label`（**中间无 NOP**）
- **THEN** 分支 MUST 按 `x1` 的**新值**（`1`）判定 ⇒ MUST **不**被 taken
- **AND** MUST NOT 按写入之前的旧值判定

#### Scenario: store 的**写数据**（rs2）MUST 同样被前推

- **WHEN** 固件是 `addi x5, x0, 0xab` → `sw x5, 0x0(x6)`（**中间无 NOP**）
- **THEN** 写入内存的**数据** MUST 是 `0xab`
- **AND** MUST NOT 是该寄存器在写入之前的旧值
- **NOTE**: store 的写数据走 `rs2` 通路 ⇒ 前推 MUST 同时覆盖 `rs1` 与 `rs2` **两路**

#### Scenario: `x0` MUST NOT 被误命中

- **WHEN** 生产者写 `x0`（`rd == 0`）或消费者读 `x0`
- **THEN** 该匹配 MUST 被**门掉**（`x0` 恒为 0，MUST NOT 被前推成别的值）
- **AND** 消费者读 `x0` 时 MUST 得到 `0`

#### Scenario: jump 的写回值 MUST 能到达消费者（**经寄存器堆路径**）

- **WHEN** 固件用 `JAL` 跳到子程序，且子程序之后的指令读 `ra`
- **THEN** 该指令 MUST 拿到**返回地址**（`JAL` 的 `pc + 4`）
- **AND** MUST NOT 拿到 ALU 的垃圾结果
- **NOTE**: ⚠️ 该值**不经前推档位**到达消费者 —— 跳转在 EX 级就重定向 PC，
  目标指令最早在**若干拍之后**才到 ID 级，此时生产者已离开可命中的级
  ⇒ 该值经**寄存器堆写回路径**到达消费者
  ⇒ ⇒ **该场景 MUST NOT 被当作前推的判别性证据**

#### Scenario: 距离矩阵 MUST NOT 在别处自述

- **WHEN** 其它 capability 或文档需要说明「距离 N 的依赖拿到什么值」
- **THEN** 它 MUST **引用**本 capability 的矩阵
- **AND** MUST NOT 自述一份矩阵（两份必然漂移）

### Requirement: 前推的档位、数据源与**时间对齐** MUST 正确

- **MODIFIED**: 本 Requirement 的**契约面**因 **A0** 而**扩展** —— 既有内容**一条都不删** ⇒ ⇒
  本 delta 只**改写 3 处**：① 档位 `2` 的数据源（MEM/WB 级 ⇒ ⇒ **M2 级**）
  ② 档位 `0` 的读点旁路（**WB→ID 单档** ⇒ ⇒ **M2→ID + WB→ID 两级**，M2 优先）
  ③ 「寄存器堆读点 MUST 有 WB→ID 组合旁路」Scenario（追加 NOTE：WB 档 **MUST 保留** + **MUST 新增 M2 档**）
  ⇒ ⇒ 架构依据同上（ADR-069 §7.1.2 · ADR-047 §5.5.2.1）
  ⇒ ⇒ ⚠️ **禁**只改实现不改 spec（ADR-047 §5.5.3 ②）。


- **WHEN** 前推通路被接入流水线装配
- **THEN** 档位选择 MUST **延迟一拍**再生效
- **AND** 档位编号 MUST 表示**延迟之后**的语义
  （`0`→寄存器堆、`1`→EX/MEM 级、`2`→MEM/WB 级）
- **AND** 档位 `1` 的数据源 MUST 取自 **EX/MEM 级流水线寄存器**
- **AND** 档位 `2` 的数据源 MUST 取自 **M2 级**的**合并写回值**
  ⚠️ **2026-11-13 修订**（基线是 MEM/WB 级 ⇒ ⇒ A0 后前移到 M2 级 ⇒ ⇒ 依据 = ADR-069 §7.1.3）
- **AND** 数据源的**叶子** MUST 是**流水线寄存器**
- **AND** 数据源 MUST NOT 取自 EX/MEM 级的**组合输出**
- **AND** 档位 `0`（寄存器堆读）的取值 MUST 具备 **两级**组合旁路：
  **M2→ID**（供**距离 3** 的依赖取到新值 · ⚠️ **2026-11-13 新增**）
  **与** **WB→ID**（供**距离 4** 的依赖取到新值 · **基线既有** · **MUST 保留**）
  ⇒ ⇒ 两档同时命中同一 `rd` 时 MUST 取 **M2 档**
  ⇒ ⇒ ⇒ 依据 = ADR-069 §7.1.2 · ADR-047 §5.5.2.1


#### Scenario: 档位 select MUST 延迟一拍

- **WHEN** 冒险检测在某一拍算出「档位 `1`」
- **THEN** 该档位 MUST 在**下一拍**才生效
- **AND** MUST NOT 在**当拍**生效
  （当拍生效 ⇒ MUST 把「生产者自己的结果」喂给当前正在执行的指令
  ⇒ **静默错值**，不是「不前推」）

#### Scenario: 数据源的**叶子** MUST 是流水线寄存器（不成环的前提）

- **WHEN** 前通路的任一数据源取自 EX/MEM 级的**组合输出端口**
- **THEN** 装配 MUST 形成**组合环** ⇒ 拓扑排序 MUST 报环
- **AND** 数据源的**叶子**是**流水线寄存器**时 MUST NOT 成环
- **NOTE**: 「取自寄存器」可以是**传递性**成立 —— 例如「合并写回值」是对多个
  MEM/WB 寄存器的组合 select ⇒ 叶子是寄存器即可

#### Scenario: 档位 `1` 的源 MUST 含跳转的**返回地址**

- **WHEN** EX/MEM 级持有的是一条 `JAL` / `JALR`
- **THEN** 档位 `1` 的数据 MUST 是该跳转的**返回地址**
- **AND** MUST NOT 是该跳转的 ALU 结果
- **NOTE**: 这是**防御性**要求 —— 固件级**不可达**（跳转的距离-1 消费者必在
  错误路径上）⇒ 该条 MUST 由**组件级单测**验收，MUST NOT 靠固件

#### Scenario: 寄存器堆读点 MUST 有 **WB→ID 组合旁路**

- **WHEN** 寄存器堆的写回与「ID→EX 锁存」发生在**同一条**时钟沿
- **THEN** 读点 MUST 用**组合旁路**给出**写回中的**那个值
  ⇒ 否则 ID/EX 锁存到的是**写回前**的旧值
- **AND** 该旁路 MUST NOT 形成**组合环**
  （其数据的**叶子** MUST 是 **MEM/WB 级流水线寄存器**）
- **NOTE**: ⚠️ **2026-11-13 修订**：本 Scenario 的 **WB 档 MUST 保留**（A0 把它从「距离 3」
  推到了「距离 4」⇒ ⇒ 距离 4 与 4 拍停顿后的 load-use 消费者仍落在本档）
  ⇒ ⇒ 且 **MUST 新增 M2 档**（供距离 3）⇒ ⇒ **两级 + M2 优先**
  ⇒ ⇒ ⇒ 详见本 Requirement 的「**A0 下的两级旁路**」Scenario 与 ADR-069 §7.1.2
