# 设计：怎样把「已过时」的当前态陈述订正掉（而不冻结错规范）

## 1. 问题形态

**不是**「写得不好」，是**规范文本内部互相否定**：

```
Requirement A「组合子 MUST NOT 无条件忽略消费端的 ready」
  └─ Scenario「转发类 MUST NOT 被读作『已合规』」
       └─ "demux / fork 仍是两端都断" + "仍属违规"      ← 2026-11-02 前属实

Requirement B「分流 / 分叉类组合子的 ready 语义 MUST 是『消费端 ⇒ 上游』」
  └─ 5 个 Scenario 规定 demux / fork 的确切行为           ← 现行契约
```

⇒ ⇒ 两条 Requirement 对同一对组合子给出**相反**的规范指令。

⚠️ 这不是文字洁癖：本仓已多次因「文档落后于实现」被咬（`AGENTS.md` 登记的
「名字 over-promise」三次、`fwft_fifo` / `stream_arbiter_sequence` / ADR-052/053
的 Scenario 订正）⇒ ⇒ **纸面契约与实现漂移 = 本仓的头号复发病症**。

## 6. 失败模式与对策

## 8. 归档后的**可判定**核对形式（验收用 ⇒ 每条都有确定判定）

```bash
M=openspec/specs/chlib-stream-ready-ownership/spec.md
R=openspec/specs/rv32i-isa-semantics/spec.md

# ① **未决语气残留**必须消失（**Requirements 段** ⇒ ⇒ 0 命中）
#    ⚠️ 面**收窄**到「未决语气」子集 ⇒ ⇒ 「两端都断」「未收口者」作为
#    **dated / 历史语境**被引用是**合法的**（delta 里就有 5 处）⇒ ⇒ 不可全量判 0
#    ⚠️ **必须限定 Requirements 段** ⇒ ⇒ `## Purpose` 里的对应陈述
#    （旧块「未收口者仍属『硬编码常量 ready ⇒ ⇒ 仍属违规』」）由 **C3b 手改**
#    处理 ⇒ ⇒ 合并后、手改前该处**仍会命中** ⇒ ⇒ 全文件判 0 = **必红**
awk '/^## Requirements/,0' $M \
  | grep -c "直至它们落地\|⚠️ \*\*仍\*\*未收口者\|❌ \*\*仍未收口\*\*"
# ①′ 手改 Purpose **之后**，全文件也应为 0
grep -c "直至它们落地\|❌ \*\*仍未收口\*\*" $M

# ② 违规条款**至少存在 1 处**（**存在性**判据，不是唯一性）
#    ⚠️ 实测（模拟合并 + 模拟手改 Purpose）：命中 = **2**
#    （K-4 正文 1 + **Purpose 新文本自带 1** ⇒ §4.3 明写「对所有转发类仍属违规」）
#    ⇒ ⇒ 写成 ==1 会**必红** ⇒ ⇒ 用 >= 1 ⇒ ⇒ 且由 ②′ 单独定位 K-4
grep -c "仍属违规" $M          # ⇒ MUST >= 1

# ②′ K-4 那段**逐字存在**（单独断言 ⇒ 义务没被漏抄）
grep -F "转发类**（mux / demux / arbiter）" $M

# ③ 已死组件**不得**出现在 **Requirements 段**（反向判据）
#    ⚠️ **Purpose 段允许**点名它（design §4.4 故意写「已物理删除」作 dated 说明）
awk '/^## Requirements/,0' $M | grep -c "stream_arbiter_sequence"   # ⇒ MUST == 0

# ④ 旧计数已消失
grep -n "3 个实例化点" $R        # ⇒ MUST 0 命中

# ④′ DataTCM 实例化点 = 4（**模式 MUST 完整** ⇒ ⇒ 可复现）
#    ⚠️ 裸 `grep "DataTCM<"` 命中 **12** 处（含注释）⇒ ⇒ 不可复现
#    ⚠️ 模式以 `riscv::DataTCM<` 收尾 ⇒ 命中 **7** 处（含 3 处注释）⇒ ⇒ 不可复现
#    ⇒ ⇒ MUST 按「构造形态 + 类型别名形态」两式匹配 ⇒ ⇒ 命中恰为 **4**
grep -rnE "ch_module<DataTCM|ch_device<DataTCM|^using [A-Za-z_]+ = riscv::DataTCM<" \
     include/ src/ examples/ tests/ | wc -l    # ⇒ MUST == 4

# ⑤ Requirement B 的**侧歧义**已消失
grep -n "out_ready = true" $M    # ⇒ MUST 0 命中

# ⑥ Requirement B 的「现状 = 死路」已标注为收口前
#    ⚠️ 该串是**旧**文本的**精确字面量**（合并后应为 0）⇒ ⇒ 勿当业务串
grep -n '转发类现状 = 「上游恒不 ready = 死路」' $M   # ⇒ MUST 0 命中
```
