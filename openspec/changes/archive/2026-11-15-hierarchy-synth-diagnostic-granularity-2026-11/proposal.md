# Proposal: 合成类诊断的**粒度** MUST 是「边」（三档的广度 / 计数 / 观测载体）

## Why

ADR-060 §2.4.1 的三档语义**按「边」定义**：

| 取值 | ADR 原文（诊断义务） |
|---|---|
| `SynthesizeWarn` | `CHWARN` 点名**每一条**被合成的边 + 合成端口名 |
| `SynthesizeFatal` | 错误结果里 MUST 列出**全部**被合成的边 + 合成端口名 |
| `Reject` | 只报**第一条需合成的跨 module 边**（本档不合成 ⇒ 无从列出合成端口名） |

而发射器 `src/hierarchy_verilog.cpp` 的实现单位是**合成物**（`synth_events`：每个端口 / 每根网一条），
⇒ ⇒ 三处兑现不了 ADR：

1. **`Reject` 报错了对象**：报的是 `module 'x': synthesized output port '__x_0'` ——
   ① 报**端口**不报**边**（用户拿不到「哪条边」）② 本档**不合成**却报出了合成端口名
   ⇒ 与 ADR 的「无从列出合成端口名」**相反**。
2. **首行计数恒不等于列出的条目数**：首行用 `synth_events.size()`（合成物数），
   而列出的条目也是同一批合成物 ⇒ 一旦按边列举，1 条边 = k 端口 + 1 网 ⇒ **必然错报**
   （这是**用户可见**的数字）。
3. **`Warn` 的边数不可观测**：逐条 `CHWARN` 只进日志（`result.warnings` 是既有字段但从未写入）
   ⇒ ⇒ 任何「合成了几条边」的判据只能抓 stderr（脆、易假绿）。

## What Changes

- **边级记录**取代合成物级清单：`synth_edge_records`（1 条记录 = 1 条**已合成**的边 + 它合成出的产物清单）。
  合成物级的 `synth_events` 与它的两个 push 点一并删除（Zero-Debt）。
- **三档从同一份记录渲染**（广度 / 措辞不会漂移）：
  - `SynthesizeWarn`：每边一条诊断 ⇒ 进 `result.warnings` **且** `CHWARN`（点名边 + 产物名）；
  - `SynthesizeFatal`：失败结果逐条列**全部边 + 产物名**，首行计数 == 列出的条目数（= 边数）；
  - `Reject`：失败结果只列**第一条边**、**不含**产物名；首行给 `1 of N`（列出的条目数 + 总数）。
- `Reject` 的告警措辞改**条件式**（`would be synthesized`）—— 本档不合成，声称「已合成」是假陈述。
- 判据：新增「成功路径三档元组」用例（产物是否存在 / 边级诊断条数 / 产物注释是否存在），
  并把产物注释的 `implicit port` 与 `net` **分别计数**（1 边 ⇒ k 端口 + 1 网
  ⇒ 「两类之和 == 边数」是**假**判据）。

## Out of Scope

- `UndrivenPolicy` 的悬空诊断（已按**全部**列出 · 不依赖合成动作 · 不在本 change 面内）。
- **产物文本**（合成注释 / 端口表 / 网声明）—— **零改动** ⇒ 逐字节一致与 R1–R8 判据不受影响。
- `PortPolicy` 枚举本身、「合成是纯内存 phase 且先于任何 I/O」的次序（ADR-060 §2.4.1 / ADR-058 §2.3）。
- 失败路径（**不可合成**形态）的诊断广度 —— 既有用例 `TwoOpTop` 覆盖，**保留不动**。

## 验收标准（可勾选）

- [x] **V1**（`Reject`）：`error` **不含**合成端口名 / 产物名（`__x_` / `__if_` / `implicit port` / `port '` / `net '`）
      **且**恰含 **1** 条边级记录（`from <node> (<module>) -> to <node> (<module>)`）
      **且**首行 `1 of N` 的「1」== `[n]` 行数
- [x] **V2**（`Fatal`）：`error` **仍含**端口名（`__x_0`）+ `[n]` 行数 == **边数** == 首行计数
      （负向：把产物名一并删掉 ⇒ 必红）
- [x] **V3**（`Warn`）：`result.warnings` 中含 `synthesized` 的行数 == **边数**
      ⇒ ⇒ **不抓 stderr** 也能断言（观测载体 = 既有公开字段）
- [x] **V4**：三档元组 = `Warn (true, 2, 有)` · `Fatal (false, 2, —)` · `Reject (false, 1, —)`；
      三个 `std::filesystem::remove` **均成功**（= 前一轮确实落过盘 ⇒ 「先删残留」是判据的一部分）
- [x] **V5**：产物注释 `implicit port` 计数 == 1 **且** `net` 计数 == 1（**分别**判）
- [x] **V6**：变异自证 M1–M5 逐条转红 + 还原后**重建**复绿（见 design.md §6）
- [x] `ctest -LE perf` **254/254** · 全部 `scripts/verify_*.sh` PASS

## 用户可见变更

| 面 | 变更 | 迁移动作 |
|---|---|---|
| `Reject` 诊断 | 报**边**（不再是端口名）；首行 `1 of N` | 解析过 `error` 文本的下游需更新；只看 `ok==false` 者无感 |
| `Fatal` 诊断 | 条目数 = **边数**（此前 = 合成物数，偏大）；`result.warnings` 也逐条落一份 | 同上 |
| `Warn` 诊断 | `result.warnings` 新增**每条边**一行（此前只进日志） | 无（字段内容增加，签名不变） |
| 层次化产物 | **不变**（逐字节） | 无 |
