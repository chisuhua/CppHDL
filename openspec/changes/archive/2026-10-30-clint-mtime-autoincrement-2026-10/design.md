# Design: CLINT 的 `mtime` 自由运行计数器

> 实施 **ADR-049**（`docs/adr/ADR-049-clint-mtime-semantics.md`）。
> ⚠️ 本文件承载**逐拍推导** / **变异清单** / **探针证据** ⇒ ADR 正文只留决策。

## 1. 内部表示的选择（ADR-049 D6：实施者自选）

ADR-049 D6 给了两个**语义等价**的形态：

| 形态 | 结构 | 优点 | 代价 |
|---|---|---|---|
| **A** | 两个 32 位 `ch_reg` + 显式进位 | 读写路径最短 | ⚠️ 进位逻辑**存在** ⇒ 多一类 bug（ADR-049 §1.4 陷阱 1） |
| **B** | 单一 64 位 `ch_reg` + `bits<>` 切片 | 进位**自动正确** | ⚠️「保高半换低半」需 `bits_update<32>`（ADR-049 §1.4 陷阱 2） |

⇒ ⇒ **本 change 选形态 B**（ADR-049 D6 的推荐）：进位逻辑**不存在** ⇒ 少一类
bug；且 64 位加法由框架的 `ch_uint<64>` 算术承担 ⇒ 回绕语义**天然**正确。

⚠️ 形态 B 的**第三个**陷阱（**实施期实测新发现**，ADR-049 未载）：
**`bits_update<32>` 在 64 位 target 上返回的是 64 位值**
（`operators_width.h:192` 的 `make_uint_result<ch_width_v<Target>>`）
⇒ ⇒ 若用 `ch_uint<32>` 接收 ⇒ **静默截断** ⇒ 「写高半」**完全失效**
⇒ ⇒ 必须用 **64 位**变量接收。

### 1.1 探针证据（实施期，`/tmp/opencode/clintprobe/`）

| 探针 | 内容 | 结果 |
|---|---|---|
| `p1` | 64 位 `ch_reg` + `mtime + 1` + `bits_update<32>(mtime, wdata, 0)` | ✅ 递增 `0x1→0x4`；写 lo `0x12345678` ⇒ `0x12345678`（高半保持 0） |
| `p2`（首版） | 同上 + 写 hi | 🔴 **写 hi 完全失效**（`mtime` 仍 `0x0`）⇒ **根因 = 我把 `bits_update` 的返回值用 `ch_uint<32>` 接收 ⇒ 静默截断**（⇒ **现场复现了 ADR-052 D1 要治的病**） |
| `p2`（修正后） | 用 `ch_uint<64>` 接收 | ✅ 5 项手推金标**全对**（见 §2.3） |
| `p3` | `bits_update` 三种形态 | ⚠️ 用 `operator uint64_t()` 读**非常量节点** ⇒ 报「Attempting to convert non-constant node」⇒ **常量折叠不可用** ⇒ 必须走仿真器 |
| `p4` | `bits_update` 三种形态（仿真器求值） | ✅ `bits_update<32>(t64,s,0)` = `0x11223344AABBCCDD`；`bits_update<32>(t64,s,32)` = `0xAABBCCDD55667788`；32 位 target 亦对 ⇒ ⇒ **`bits_update` 本身正确**（⇒ p2 的失效**不是**框架缺陷） |

## 2. 逐拍推导（**手推**，禁抄仿真输出）

### 2.1 记号

- `M_k` = 第 k 个时钟沿**之后** `mtime` 的值（`M_0` = 复位值 = 0）；
- `D_k` = 第 k 个时钟沿**之后**分频计数器 `d` 的值（`D_0` = 0）；
- 「拍 k」= 第 k 个时钟沿**期间**（此时寄存器仍持有 `M_{k-1}` / `D_{k-1}`）。

### 2.2 核心关系式（形态 B）

```
inc_en(k)   = (D_{k-1} == TIMER_DIVIDER - 1)          // 硬件原语：select / ==
mtime_next  = select(write_lo,  bits_update<32>(mtime, wdata, 0),
               select(write_hi,  bits_update<32>(mtime, wdata, 32),
               select(inc_en(k), mtime + 1,
                                          mtime)))
d_next      = select(inc_en(k), 0, d + 1)
```

⇒ ⇒ **写优先**（`write_lo` / `write_hi` 在 `select` 的**外层**）⇒ 写的那一拍
**不递增**（ADR-049 D3）⇒ ⇒ **写拍的分频计数器照常推进**（`d_next` 与写**无关**）
⇒ ⇒ 写拍若恰是递增拍 ⇒ 该次递增被丢弃，但**相位不变**（ADR-049 D2）。

### 2.3 手推金标（形态 B，`TIMER_DIVIDER = 1`）

| 拍 | 操作 | `M_k` | 期望 | 备注 |
|---|---|---|---|---|
| 1 | 写 lo = `0xFFFFFFFF` | `0xFFFFFFFF` | `0xFFFFFFFF` | 写优先 ⇒ **不递增** |
| 2 | 无写 | `0x1_00000000` | `0x1_00000000` | ⚠️ **跨 32 位边界** ⇒ 抓「进位用 C++ 三元 ⇒ 恒 0」 |
| 3 | 写 hi = 7 | `0x7_00000000` | `0x7_00000000` | 低半**保持** 0 |
| 4 | 写 lo = `0x11111111` | `0x7_11111111` | `0x7_11111111` | 高半**保持** 7 |
| 5 | 无写 | `0x7_11111112` | `0x7_11111112` | 写后从写值继续 |

⚠️ 拍 2 是**唯一**能跨 32 位边界的路径 ⇒ ⇒ 它是**判别性**用例
（形态 A 的进位 bug 会让它停在 `0xFFFFFFFF`）。

### 2.4 分频相位（`TIMER_DIVIDER = N > 1`）

`d` 复位为 0 ⇒ 递增发生在 `d == N-1` 的那一拍 ⇒ ⇒

| 拍 k | `D_{k-1}` | `inc_en(k)` | `M_k`（无写） |
|---|---|---|---|
| 1 | 0 | `0 == N-1`? | N=4 ⇒ 否 ⇒ `M_1 = 0` |
| 2 | 1 | 否 | `M_2 = 0` |
| 3 | 2 | 否 | `M_3 = 0` |
| **4** | **3** | **是** | **`M_4 = 1`** ← **复位后第 N 拍第一次递增** |
| 5 | 0 | 否 | `M_5 = 1` |
| 6 | 1 | 否 | `M_6 = 1` |
| 7 | 2 | 否 | `M_7 = 1` |
| **8** | **3** | **是** | **`M_8 = 2`** |

⇒ ⇒ **第 N 拍**（= 拍 4）第一次递增 ⇒ 之后每 N 拍一次 ✔（ADR-049 D2）。

⚠️ **写拍落在递增边界**的判别（区分「写复位分频器」与「写暂停分频器」）：

| 拍 | 操作 | `D` 变化 | `M` |
|---|---|---|---|
| 1 | 无写 | `D_1 = 1` | `M_1 = 0`（N=4） |
| 2 | 无写 | `D_2 = 2` | `M_2 = 0` |
| 3 | 无写 | `D_3 = 3` | `M_3 = 0` |
| **4** | **写 lo = 50** | `D_4 = 0`（**照常推进**） | **`M_4 = 50`**（写优先 ⇒ 递增被丢弃） |
| 5 | 无写 | `D_5 = 1` | `M_5 = 51` |
| 6 | 无写 | `D_6 = 2` | `M_6 = 52` |
| 7 | 无写 | `D_7 = 3` | `M_7 = 53` |
| **8** | 无写 | `D_8 = 0` | **`M_8 = 54`** ← 递增恢复，**相位未被打乱** |

⇒ ⇒ 「写复位分频器」的实现会让拍 8 的递增提前/推后 ⇒ ⇒ **可判别** ✔。

## 3. 读路径的时序（⚠️ 实施期实测的关键事实）

CLINT **没有**直读 `mtime` 的端口 ⇒ ⇒ 只能经 `read_data`（32 位）+ 地址偏移读。

⚠️ `io().read_data = select(io().read_en, read_val, 0)` 是**组合**输出 ⇒ ⇒
`sim.get_value(read_data)` 读到的是**上一次 tick 结束时**的组合结果 ⇒ ⇒
**组合读反映的是该拍「开始时」的寄存器值**（即 `M_{k-1}`，不是 `M_k`）。

⇒ ⇒ **读 `mtime` 的代价是「多一次 tick」** ⇒ ⇒ 递增测试若用读来断言，必须把
这个偏移算进去 ⇒ ⇒ **更稳的做法**：用「**写-读同拍**」（`write_en=1` 且
`read_en=1` 且 `addr` 指到目标半）⇒ ⇒ 写的那一拍**不递增** ⇒ ⇒ 值完全确定。

⚠️ 但写-读同拍读到的是**该拍开始时**的 `mtime`（组合读的固有滞后）⇒ ⇒
要读**写后的**值，仍需**再 tick 一拍**（那一拍无写 ⇒ 会递增 1）。

⇒ ⇒ **本 change 的测试策略**：
- **递增类**断言用「不写 + 读」的偏移模型（§3 的公式），期望值**手推**；
- **写优先类**断言用「写-读-再读」两步，明确期望值；
- ⇒ ⇒ **`test_interrupt_flow` 的既有断言 MUST 改成「每次采样前重写 `mtime`」**
  （ADR-049 §4）⇒ ⇒ 消除「靠余量才通过」的时序脆弱性。

## 4. 变异清单（每条**先确认编译成功** ⇒ 否则跑的是旧二进制 ⇒ 假绿）

| # | 注入 | 期望转红 | 抓的是 |
|---|---|---|---|
| **M1** | 分频边界判定换成 **C++ 三元**（`d == N-1 ? 1_d : 0_d`） | **V2**（跨边界）转红 | ADR-049 §1.4 陷阱 1 |
| **M2** | `bits_update<32>` 换成手写 `hi \| lo`（**漏移位**） | **V6**（写半保持）转红 | ADR-049 §1.4 陷阱 2 |
| **M3** | 去掉「写的那一拍不递增」（写值 **+1**） | **V6** / **V7** 转红 | D3 |
| **M4** | 忽略 `TIMER_DIVIDER`（每拍递增） | **V3**（分频相位）转红 | D2 |
| **M5** | 写拍**复位**分频器（`d_next` 受写影响） | **V4** / **V5** 转红 | D2 的相位纯函数性 |
| **M6** | 删掉整个递增源（回到「静态比较器」） | **V1**（递增）转红 | D1（证明该用例**真的**在测递增） |
| **M7**（额外） | `bits_update` 的返回值用 **32 位**接收（静默截断） | **V6**（写高半）转红 | ⚠️ **实施期新发现的第三个陷阱** |

## 6. 非目标（与 ADR-049 §4 一致）

- **不**把 CLINT 接入 SoC；
- **不**提供 64 位原子读 / 撕裂检测（D5 ⇒ 已知边界）；
- **不**变更 `mtimecmp` 的语义；
- **不**变更 `Clint` 的命名空间（`ch::chlib`）⇒ ADR-033 另议；
- **不**新增运行期配置端口。
