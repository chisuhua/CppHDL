# hierarchy-friendliness-diagnosis Specification

## Purpose
定义「用户能否**在设计早期**知道自己设计的**层次友好度**」这条**用户面契约**：★
诊断入口存在且**只读** ⇒ ★ 报告给出**可判定**的 5 项事实 ⇒ ★ 不可分析时
**MUST NOT** 把未测项呈现为 0 ⇒ ★ 诊断与发射器**同源**（单一判定实现）。

⚠️ **边界**：本 capability **不**管产物结构（★ 归 `rtl-hierarchical-output`）⇒ ★
**不**管「前置校验首错即抛」那个缺口（★ 独立 backlog）。

## Requirements

### Requirement: 诊断入口 MUST 存在且只读

框架 MUST 提供一个**只读**的层次友好度诊断入口 ⇒ ★ 用户 MUST 能在**不发射**的
前提下得到诊断报告 ⇒ ★ 诊断 MUST NOT 修改图 / ctx / 产物 ⇒ ★ 调用 MUST NOT
改变既有行为（★ 零回归）。

⇒ ⇒ 该入口 MUST 与既有分析入口**同源**（★ 同一 ctx · 同一分析产物）⇒ ⇒ 否则
诊断与发射可能给出**互相矛盾**的结论。

#### Scenario: const 上下文可读诊断结果

- **WHEN** 用户在一个 **const** 上下文里读取诊断报告
- **THEN** 读取 MUST 编译通过 ⇒ ⇒ 不必为「在 const 接口里读诊断」而放弃 const 正确性

#### Scenario: 诊断不改变任何既有行为

- **WHEN** 诊断被调用
- **THEN** ctx 的节点集合与**全部**节点的驱动关系 MUST **逐项不变** ⇒ ⇒ 生成的
      产物 MUST **逐字节不变** ⇒ ⇒ 「只读」**MUST NOT** 靠承诺 ⇒ ⇒ MUST 可核验

### Requirement: 报告 MUST 给出可判定的 5 项事实

诊断报告 MUST 给出 5 项**可机械判定**的事实 ⇒ ★ 隐式**边**数 ⇒ ★ 需合成的
**端口**数 ⇒ ★ 跨层悬空输入数 ⇒ ★ 未被子层消费的输出数 ⇒ ★ 各层规模（★ 端口数 /
实例数 / 体内节点数**分开给**）⇒ ★ 跨模块内存访问数。

⇒ ⇒ 「边」与「端口」MUST 是**两个不同的量**（★ 同类隐式边的代价可能是 1 个端口
也可能是 N 跳端口链）⇒ ⇒ 报告 MUST NOT 用单一「边数」代表代价。

⇒ ⇒ 某项**无法测得**时 MUST 表达为「未测得」⇒ ⇒ **MUST NOT** 呈现为 **0**
（★ 0 与「未测」不可区分 ⇒ ⇒ 会被读成「我没问题」）。

#### Scenario: 无法分析时未测项与真实 0 可区分

- **WHEN** 一个设计**不可分析**（★ 例如跨模块内存访问被拒）
- **THEN** 诊断 MUST 返回报告（★ **MUST NOT** 抛异常）⇒ ⇒ 且未测项 MUST 表达为
      「未测得」⇒ ⇒ 与「真实为 0」在报告上**可区分** ⇒ ⇒ 报告 MUST NOT 全是 0

#### Scenario: 边的单位与端口数分别正确

- **WHEN** 一个节点驱动**两个**父侧端点
- **THEN** 隐式**边**数 MUST 记 2 ⇒ ⇒ 需合成的**端口**数 MUST 记 1 ⇒ ⇒ 二者
      **MUST NOT** 混为一谈

### Requirement: 诊断 MUST 与发射器同源且 MUST 提供确定性快照

诊断 MUST 与层次化发射**同源** ⇒ ★ 同一 ctx 下，诊断给出的**隐式边合成**端口数
MUST 与发射产物里标记为「合成」且**属隐式边合成**的端口数**相等** ⇒ ⇒ 否则二者可能
**各自算错而互相印证**。

⇒ ⇒ ⚠️ **向上 pass-through 的端口 MUST NOT 计入**（★ 它的数量 = 链长 ⇒ 不可由边数
推导）⇒ ⇒ 判据 MUST 按端口名前缀**分别计数**。

⇒ ⇒ 报告 MUST 提供**确定性快照**（★ 同一设计连续两次诊断 MUST **逐字节相同**）
⇒ ⇒ 否则「快照只增不改」这类兼容承诺**无法机械核验**。

#### Scenario: 诊断的端口数与发射产物一致

- **WHEN** 同一 ctx 先诊断、再发射
- **THEN** 诊断报告的隐式合成端口数 MUST 等于发射产物里「合成端口」中**属隐式边
      合成**的条数 ⇒ ⇒ 两者**MUST NOT** 是两份独立实现

#### Scenario: 快照确定性

- **WHEN** 对同一设计连续调用两次诊断
- **THEN** 两份快照 MUST **逐字节相同** ⇒ ⇒ 明细的顺序 MUST NOT 依赖哈希遍历序
