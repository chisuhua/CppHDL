# rv32i-data-forwarding Specification

## Purpose
本 capability 管辖 **RV32I 流水线的数据前推**（data forwarding）——
即「消费者 MUST 拿到源寄存器的**最新值**」这层契约的**唯一权威**：
档位语义、数据源、时间对齐、**距离矩阵**、装配无环，以及「证据 MUST **判别**」。

它**不**管辖 ISA 语义本身（跳转 / 字节道 / 算术的正确性）——
那是 `rv32i-isa-semantics` 的职责；它也**不**管辖退休数 / 有效链 / 停顿契约 ——
那是 `rv32i-commit-path` 的职责。

**本 capability 的由来**（2026-10-27）：`rv32i-isa-semantics` 与
`rv32i-commit-path` 里长期挂着「**前推未裁决**」的指针（指向 ADR-046 §D5），
而根 `AGENTS.md §KNOWN LIMITATIONS` 的相关条目已叠了 4 层修订 ⇒
「前推」这件事一直以「实现缺陷」的形式散落在多处，既没有单一权威，
也没有可判定的验收。前推的接入与形态已由 ADR-047 裁决 ⇒ 这些 MUST 收拢到一处。

⚠️ **「距离矩阵」的出处**：本 capability 是距离矩阵的**唯一权威**
⇒ 其它 capability / 文档 **MUST 引用**它，**MUST NOT** 自述一份
⇒ 否则必然漂移。

## Requirements

### Requirement: 数据前推 MUST 为消费者提供**最新值**

- **WHEN** 一条指令的源操作数依赖**更早**指令写入的寄存器
- **THEN** 消费者 MUST 拿到该寄存器的**最新值**
- **AND** MUST NOT 要求固件手工插 NOP 来避免读到旧值
- **AND** 消费者 MUST NOT 为了拿到新值而**额外停顿**
  （load-use 停顿是**唯一**例外 —— 见 `rv32i-commit-path` capability 的
  「load-use 冒险 MUST 被检测到，且停顿 MUST 是**保持型**」）
- **AND** 各类**距离**的取值来源 MUST 符合下方「距离矩阵」Scenario

#### Scenario: 距离矩阵（**本 capability 的唯一权威**）

- **WHEN** 一个消费者依赖某个生产者写入的寄存器
- **THEN** 消费者 MUST 拿到该寄存器的**最新值**
- **AND** **「距离」的定义** MUST 是：
  **距离 = 生产者与消费者之间的指令间隔数 + 1**
  （相邻（中间无指令）= 距离 1；中间隔 **1** 条 = 距离 2；隔 **2** 条 = 距离 3）
- **AND** 它与「生产者所在级」**一一对应**：距离 1 ⇒ 生产者在 **EX** 级；
  距离 2 ⇒ **MEM** 级；距离 3 ⇒ **WB** 级
- **AND** 各类距离的**取值来源** MUST 是：

  | 距离 | 生产者所在级 | **取值来源** | 结论 |
  |---|---|---|---|
  | 1 | EX | 档位 `1`（EX/MEM 级流水线寄存器） | ✅ 前推覆盖（⚠️ **load→use 是例外** —— 走 **load-use 停顿**，档位 `1` **不覆盖 load**） |
  | 2 | MEM | 档位 `2`（MEM/WB 级的**合并**写回值） | ✅ 前推覆盖 |
  | 3 | WB | **寄存器堆读点的 WB→ID 组合旁路** | ✅ 旁路覆盖 |
  | ≥ 4 | 已退休 | 寄存器堆路径（写回早已落地） | ✅ |

#### Scenario: 相邻 ALU → ALU（中间无间隔）

- **WHEN** 固件是 `addi x5, x0, 7` → `add x6, x5, x0`（**中间无 NOP**）
- **THEN** `x6` MUST 是 `7`
- **AND** MUST NOT 是该寄存器在写入**之前**的旧值

#### Scenario: 距离 2 的 load → use

- **WHEN** 固件是「一条 load」→「一条无关指令」→「一条读该 load 目标寄存器的指令」
- **THEN** 该消费者 MUST 读到 load 写入的**新值**
- **AND** MUST NOT 读到该寄存器在 load 之前的旧值
- **NOTE**: 该距离由「MEM 级前推档位」覆盖 ⇒ 其**数据源** MUST 是 MEM/WB 级
  的**合并写回值**（该值已含 load 数据）

#### Scenario: 距离 3 的 load → use

- **WHEN** 固件是「一条 load」→「**两条**无关指令」→「一条读该 load 目标寄存器的指令」
- **THEN** 该消费者 MUST 读到 load 写入的**新值**
- **AND** MUST NOT 读到该寄存器在 load 之前的旧值
- **NOTE**: 该距离**不经前推档位**（生产者此时已在 **WB** 级 ⇒ 已离开可命中的级）
  ⇒ 它依赖「寄存器堆读点对**同沿写回**的旁路」
  ⇒ 该读点 MUST NOT 与写回沿**竞态**

#### Scenario: 距离 ≥ 4 的依赖

- **WHEN** 生产者与消费者之间隔着 **≥ 3** 条无关指令
- **THEN** 该消费者 MUST 读到生产者的**新值**
  （写回早已落地 ⇒ 走寄存器堆路径）

#### Scenario: 分支条件用紧邻新值

- **WHEN** 固件是 `addi x1, x0, 1` → `beq x1, x0, label`（**中间无 NOP**）
- **THEN** 分支 MUST 按 `x1` 的**新值**（`1`）判定 ⇒ MUST **不**被 taken
- **AND** MUST NOT 按写入之前的旧值判定

#### Scenario: store 的**写数据**（rs2）MUST 同样被前推

- **WHEN** 固件是 `addi x5, x0, 0xab` → `sw x5, 0x0(x6)`（**中间无 NOP**）
- **THEN** 写入内存的**数据** MUST 是 `0xab`
- **AND** MUST NOT 是该寄存器在写入之前的旧值
- **NOTE**: store 的写数据走 `rs2` 通路 ⇒ 前推 MUST 同时覆盖 `rs1` 与 `rs2` **两路**

#### Scenario: `x0` MUST NOT 被误命中

- **WHEN** 生产者写 `x0`（`rd == 0`）或消费者读 `x0`
- **THEN** 该匹配 MUST 被**门掉**（`x0` 恒为 0，MUST NOT 被前推成别的值）
- **AND** 消费者读 `x0` 时 MUST 得到 `0`

#### Scenario: jump 的写回值 MUST 能到达消费者（**经寄存器堆路径**）

- **WHEN** 固件用 `JAL` 跳到子程序，且子程序之后的指令读 `ra`
- **THEN** 该指令 MUST 拿到**返回地址**（`JAL` 的 `pc + 4`）
- **AND** MUST NOT 拿到 ALU 的垃圾结果
- **NOTE**: ⚠️ 该值**不经前推档位**到达消费者 —— 跳转在 EX 级就重定向 PC，
  目标指令最早在**若干拍之后**才到 ID 级，此时生产者已离开可命中的级
  ⇒ 该值经**寄存器堆写回路径**到达消费者
  ⇒ ⇒ **该场景 MUST NOT 被当作前推的判别性证据**

#### Scenario: 距离矩阵 MUST NOT 在别处自述

- **WHEN** 其它 capability 或文档需要说明「距离 N 的依赖拿到什么值」
- **THEN** 它 MUST **引用**本 capability 的矩阵
- **AND** MUST NOT 自述一份矩阵（两份必然漂移）

### Requirement: 前推的档位、数据源与**时间对齐** MUST 正确

- **WHEN** 前推通路被接入流水线装配
- **THEN** 档位选择 MUST **延迟一拍**再生效
- **AND** 档位编号 MUST 表示**延迟之后**的语义
  （`0`→寄存器堆、`1`→EX/MEM 级、`2`→MEM/WB 级）
- **AND** 档位 `1` 的数据源 MUST 取自 **EX/MEM 级流水线寄存器**
- **AND** 档位 `2` 的数据源 MUST 取自 **MEM/WB 级**的**合并写回值**
- **AND** 数据源的**叶子** MUST 是**流水线寄存器**
- **AND** 数据源 MUST NOT 取自 EX/MEM 级的**组合输出**
- **AND** 档位 `0`（寄存器堆读）的取值 MUST 具备 **WB→ID 组合旁路**
  （供距离 3 的依赖取到新值）

#### Scenario: 档位 select MUST 延迟一拍

- **WHEN** 冒险检测在某一拍算出「档位 `1`」
- **THEN** 该档位 MUST 在**下一拍**才生效
- **AND** MUST NOT 在**当拍**生效
  （当拍生效 ⇒ MUST 把「生产者自己的结果」喂给当前正在执行的指令
  ⇒ **静默错值**，不是「不前推」）

#### Scenario: 数据源的**叶子** MUST 是流水线寄存器（不成环的前提）

- **WHEN** 前通路的任一数据源取自 EX/MEM 级的**组合输出端口**
- **THEN** 装配 MUST 形成**组合环** ⇒ 拓扑排序 MUST 报环
- **AND** 数据源的**叶子**是**流水线寄存器**时 MUST NOT 成环
- **NOTE**: 「取自寄存器」可以是**传递性**成立 —— 例如「合并写回值」是对多个
  MEM/WB 寄存器的组合 select ⇒ 叶子是寄存器即可

#### Scenario: 档位 `1` 的源 MUST 含跳转的**返回地址**

- **WHEN** EX/MEM 级持有的是一条 `JAL` / `JALR`
- **THEN** 档位 `1` 的数据 MUST 是该跳转的**返回地址**
- **AND** MUST NOT 是该跳转的 ALU 结果
- **NOTE**: 这是**防御性**要求 —— 固件级**不可达**（跳转的距离-1 消费者必在
  错误路径上）⇒ 该条 MUST 由**组件级单测**验收，MUST NOT 靠固件

#### Scenario: 寄存器堆读点 MUST 有 **WB→ID 组合旁路**

- **WHEN** 寄存器堆的写回与「ID→EX 锁存」发生在**同一条**时钟沿
- **THEN** 读点 MUST 用**组合旁路**给出**写回中的**那个值
  ⇒ 否则 ID/EX 锁存到的是**写回前**的旧值
- **AND** 该旁路 MUST NOT 形成**组合环**
  （其数据的**叶子** MUST 是 **MEM/WB 级流水线寄存器**）

### Requirement: 前推的关键选择 MUST **可单测**（组件边界）

- **WHEN** 前推通路里有「按指令类型选择数据源」的逻辑
- **THEN** 该逻辑 MUST 由 mux 组件的**输入端口**表达
- **AND** MUST NOT 是流水线装配里**内联**的表达式
- **AND** **理由**：内联表达式的输入是流水线的**成员寄存器**
  ⇒ 测试台**无法驱动** ⇒ MUST NOT 依赖「实施者自己重建一份等价逻辑」的测试
  （那测的是**副本** ⇒ 对**真实接线零信号** ⇒ **假绿**）

#### Scenario: 档位 `1` 的源选择 MUST 在 mux 组件**内部**

- **WHEN** 档位 `1` 需要在「ALU 结果」与「跳转返回地址」之间选择
- **THEN** 该选择 MUST 由 mux 组件的**输入端口**表达
  （例如 `is_jump` + `jump_result`）
- **AND** MUST NOT 是流水线装配里**内联**的表达式

### Requirement: 前推 MUST NOT 形成**组合环**，且 MUST 有**负向对照**

- **WHEN** 前推通路被接入真实流水线装配
- **THEN** 拓扑排序 MUST NOT 报组合环
- **AND** 该约束 MUST 有**可执行的验证**（装配后构建 + 运行 ⇒ 无环错误）
- **AND** **负向对照** MUST 存在：数据源取自 EX/MEM 级**组合输出**的形态 MUST
  **仍然**触发环检测
  （否则「不成环」可能只是**环检测本身失效** ⇒ 该结论没有意义）
- **AND** 该负向对照 MUST 是**常驻**的（一次性的人工检查 ⇒ 护栏失效无人守）

#### Scenario: 装配后 MUST 无环

- **WHEN** 前推通路被接入真实流水线装配并构建
- **THEN** 拓扑排序 MUST NOT 报组合环
- **AND** 该验证 MUST 是**常驻**的（不是一次性的人工检查）

### Requirement: 前推 MUST 有**判别性**证据

- **WHEN** 用例被用来证明前推接线正确
- **THEN** MUST 存在「生产者与消费者之间**无间隔**」的用例
- **AND** 每个此类用例 MUST 附带**反向期望**
  （「未接前推时此处读到旧值 `X_old`」）⇒ 否则该用例**可能已退化**（零信号）
- **AND** 所有重算的期望值（内存值 / 停顿拍数 / 退休数 / 控制停顿数）MUST
  **手工推导**并在**代码注释**里留痕
  （MUST NOT 从仿真输出直接抄值 —— 那是**循环论证**）
- **AND** MUST NOT 只依赖「生产者与消费者之间留了间隔」的固件
  （那种固件在**未接前推**时同样通过 ⇒ 对前推是**零信号**）
- **AND** 那些**固件级不可达**的失效模式 MUST 由**组件级**测试验收
  （例如「档位 `1` 漏接返回地址」与「前推判定漏排除 load」）

#### Scenario: 每个判别性用例 MUST 带反向期望

- **WHEN** 一个用例断言消费者读到新值 `X_new`
- **THEN** 该用例 MUST 同时写明「未接前推时会读到 `X_old`」且 `X_old != X_new`
- **AND** 若 `X_old == X_new` ⇒ 该用例 MUST 被视为**无效**（零信号）并重写

#### Scenario: 金标 MUST 手工推导并留痕

- **WHEN** 一个期望值（内存值 / 停顿拍数 / 退休数 / 控制停顿数）被写死
- **THEN** 推导过程 MUST 写在**代码注释**里
- **AND** MUST NOT 是「跑一遍仿真把输出抄进期望值」

#### Scenario: 变异验证 MUST 先确认编译成功

- **WHEN** 一个变异被用来证明某个判据有判别力
- **THEN** MUST 先确认**变异后仍编译成功**
- **AND** 编译失败的变异 MUST NOT 被计入「已抓到」
  （它跑的是**旧二进制** ⇒ **假绿**）

#### Scenario: 固件级不可达的失效模式 MUST 走**组件级**验收

- **WHEN** 一个失效模式在固件级**不可达**
  （例如「档位 `1` 漏接跳转返回地址」—— 跳转的距离-1 消费者必在错误路径上；
  或「前推判定漏 `& !ex_is_load`」—— 误选只打进气泡 ⇒ 结果被丢弃）
- **THEN** 该失效模式 MUST 由**组件级真值表 / 单测**验收
- **AND** MUST NOT 用固件验收（固件对它**零信号** ⇒ 变异会**假绿**）
