# core-node-driver-visibility Specification

## Purpose
定义框架层**节点驱动状态**的**只读诊断**契约：`ch::core::diagnose_drive` MUST
回答「某个字段 / 代理 / 端口**是否被驱动**」，并 MUST 区分**五种**状态
（`no_node` · `literal` · `undriven` · `driven_by_literal` · `driven`）。

**为什么需要**（B7）：框架读一个**未被驱动**的字段 / 代理 / 端口时返回 **0**
且**不报错** ⇒ ⇒ **静默**（本仓第 3 个实例：前两个是 `ch_in` 的 `operator=`
与未驱动代理节点）。⇒ ⇒ 实测机制：`ch_uint::operator<<=` 在目标**没有节点**时
**另建**一个 assign 节点并**只绑到本地副本** ⇒ ⇒ 调用方看不到任何效果；
而 `logic_buffer()` 默认构造 = `node_impl_(nullptr)` ⇒ ⇒ 「没有节点」是**可达**
状态（= 缺 `as_master()`）。

⇒ ⇒ **诊断与拒绝是两件事**：本 capability 只**告知**（只读，MUST NOT 改变任何
读取语义 ⇒ ⇒ 零回归）；「响亮拒绝」由各组合子自己做，且 MUST 使用**同一个**
诊断接口 ⇒ ⇒ 判据**只有一处** ⇒ ⇒ 两份实现不会漂移。

⚠️ **边界**：诊断**不**回答「这个设计会不会跑起来」—— 框架**不跟踪**「某节点
是否已连到任何顶层输入」⇒ ⇒ 「有源但未连到顶层」与「完全无源」**无法**区分。
## Requirements

### Requirement: 节点的驱动状态 MUST 可被**只读**诊断

框架 MUST 提供一个**只读**的诊断接口，回答「某个节点 / 字段 / 端口**是否被驱动**」
⇒ ⇒ 且 MUST **区分**「无节点」「自身是字面量」「有节点但无驱动源」「被字面量驱动」
「被真信号驱动」这**五种**状态。

⚠️ 诊断 MUST NOT 改变任何**读取**语义（框架读未驱动字段仍返回 0）⇒ ⇒
**只读**接口与「响亮拒绝」是**两件事**：前者**告知**，后者**拒绝**。

#### Scenario: 五种驱动状态 MUST 被区分

- **WHEN** 诊断一个节点（字段 / 代理 / 端口）
- **THEN** MUST 返回下列**恰好**五种状态之一：
  `no_node`（节点不存在）· `literal`（自身是字面量 ⇒ 驱动它无效）·
  `undriven`（有节点但无驱动源）· `driven_by_literal`（被字面量驱动 ⇒
  = 组合子的**默认值** ⇒ **允许**被覆盖）· `driven`（被真信号驱动 ⇒
  再驱动 = last-wins ⇒ **静默接管**）
- **AND** `driven_by_literal` MUST 与 `driven` **分开**（前者可覆盖，后者不可）
- **AND** 每种状态 MUST 有**可执行**判据（⇒ ⇒ 少一格就可能让「诊断说未驱动、
  实际已驱动」这类**误判**溜过去）

#### Scenario: 诊断 MUST NOT 改变读取语义

- **WHEN** 使用诊断接口
- **THEN** 框架读一个未驱动字段的行为 MUST **逐位不变**（仍返回 0）
- **AND** ⇒ ⇒ 引入诊断 MUST NOT 造成任何既有测试回归

#### Scenario: 组合子的「响亮拒绝」MUST 走**同一**判定

- **WHEN** 组合子要判定「能不能驱动上游的 `ready`」
- **THEN** 它 MUST 使用**同一个**诊断接口 ⇒ ⇒ 判据**只有一处**
- **AND** MUST NOT 在组合子里**重新实现**该判定（⇒ ⇒ 两份实现必然漂移）
- **AND** 「无节点」「字面量」「已被真信号驱动」三种情形 MUST **响亮拒绝**
  （MUST 用**抛异常**的机制；只打日志的机制不抛 ⇒ = 假安全网）

#### Scenario: 「未驱动」MUST NOT 被读成「已驱动」

- **WHEN** 变异诊断实现，使「未驱动」看起来像「已驱动」
- **THEN** 诊断判据 MUST **转红**（⇒ ⇒ 判别力可证）
- **AND** ⇒ ⇒ 该判据 MUST 能区分「未驱动」与「**已被真信号驱动**」
  （⇒ ⇒ 两者在**响亮拒绝**上表现相同 ⇒ ⇒ 只有诊断接口能区分 ⇒ ⇒
  ⇒ ⇒ **诊断判据不是冗余的**）

#### Scenario: 已知边界 MUST 被如实声明

- **WHEN** 一个节点**有源**但该源**未连到任何顶层输入**
- **THEN** 它 MUST 被诊断为 `driven`（框架当前**不跟踪**「是否连到顶层」）
- **AND** ⇒ ⇒ 「有源但未连到顶层」与「完全无源」**无法**区分
  （⇒ ⇒ 诊断**不**回答「这个设计会不会跑起来」）
